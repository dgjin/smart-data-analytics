模块按横切关注点拆分为独立文件，彼此通过明确接口耦合：
- `db.ts` 是 MySQL 持久化入口，集中维护连接池、所有业务表 DDL 与幂等迁移（ALTER TABLE 捕获 ER_DUP_FIELDNAME），并在启动时执行种子数据（默认管理员、内置技能、看板 widget、SQL 样例等）。
- `stateStore.ts` 定义 `StateStore` 抽象接口，提供 `MemoryStateStore`（默认）与 `RedisStateStore` 两种实现，由工厂函数根据 `REDIS_URL` 惰性选择；键命名约定以 `qp:`/`rqp:`/`qc:`/`uql:`/`uqs:`/`rl:` 前缀区分用途，并提供分布式锁、固定窗口计数器等原子原语。
- `rateLimiter.ts`（IP 级）与 `userQueryLimit.ts`（用户级配额 + 并发槽）复用 `StateStore`，在 Redis 模式下走全局共享计数，内存模式退化为进程内 Map。
- `taskQueue.ts` 基于 `async_tasks` 表实现无外部 MQ 的长任务队列，支持 `FOR UPDATE SKIP LOCKED` 多 worker 领取、心跳保活、孤儿任务回收与最大重试次数保护。
- `auditLog.ts` 将问数全链路事件写入 `query_audit_log`，写入失败仅告警不阻塞主流程（fail-open）。
- `secretsCrypto.ts` 使用 AES-256-GCM 对数据源密码进行落库加密，密钥从 `DS_SECRET_KEY` 或 `JWT_SECRET` 经 scrypt 派生，支持明文存量就地迁移。
- `logger.ts`、`requestLogger.ts`、`errorCodes.ts`、`monitoring.ts` 分别提供结构化日志、请求追踪、统一错误码与 Prometheus 埋点。
依赖方向单向向外：业务路由 → infra → db/stateStore/logger，infra 内部不反向依赖业务模块。
