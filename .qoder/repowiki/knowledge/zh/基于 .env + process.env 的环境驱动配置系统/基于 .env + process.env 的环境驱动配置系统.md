## 1. 采用的方案

本项目采用 **纯环境变量驱动** 的配置体系，核心依赖 `dotenv` 在进程启动时加载 `.env.local` / `.env` 文件，所有运行时配置（数据库、LLM 引擎、Redis、认证、限流、监控等）均通过 `process.env` 读取。没有使用 `config/` 目录、YAML/TOML 配置文件或专用配置库（如 `@hapi/joi` 的 schema 校验），而是以“惰性函数 + 默认值”的方式在模块内部按需解析环境变量。

## 2. 关键文件与入口

- **配置加载入口**：`server.ts` 在 Express 应用初始化前调用 `dotenv.config()`，按 `__dirname` → `__dirname/..` → `process.cwd()` 三个候选路径依次加载 `.env.local` 和 `.env`；注释明确“多次加载不覆盖已有值（先加载者优先），进程环境变量始终优先于文件”。
- **环境示例**：`.env.example`（仓库提供）、`.env.local`、`.env.production`（本地/生产环境隔离）。
- **构建期注入**：`vite.config.ts` 通过 `define` 将 `package.json` 中的 `version` 以 `import.meta.env.VITE_APP_VERSION` 形式注入前端，作为构建期常量。
- **部署侧配置**：`deploy/prometheus.yml`、`deploy/alertmanager.yml`、`docker-compose.multi-instance.yml`、`Dockerfile`、`start.sh` 用于容器化与多实例部署时的外部化配置。

## 3. 架构与设计约定

### 3.1 惰性读取与环境变量命名规范
每个模块对 `process.env` 的访问都封装为局部函数（而非模块级常量），以避免 ESM import 提升导致在 `dotenv.config()` 之前读取到空值。典型模式：
- `mysqlBase()` / `dbName()` / `appPoolMax()`（`server/infra/db.ts`）：MySQL 连接参数、默认管理员账号、连接池容量公式。
- `llmModel()` / `qwenUrl()` / `qwenModel()` / `geminiModel()`（`server/llm/llmClient.ts`）：各 LLM 后端的模型名、端点、超时、重试次数、熔断阈值。
- `jwtSecret()` / `jwtExpiresIn()`（`server/auth/auth.ts`）：JWT 密钥与过期时间，未配置时在 dev 下生成随机密钥并告警。
- `getStateStore()`（`server/infra/stateStore.ts`）：根据 `REDIS_URL` 是否存在选择 `MemoryStateStore` 或 `RedisStateStore`，实现单机/多实例无缝切换。

### 3.2 分层配置优先级
项目内形成明确的优先级约定（从高到低）：
1. 进程环境变量（`process.env.*`，由容器/编排层注入）
2. `.env.local`（开发时覆盖）
3. `.env`（共享基础配置）
4. 代码内默认值（如 MySQL 默认 `127.0.0.1:3306/root/admin`、LLM 默认 `deepseek-r1:32b`）

### 3.3 安全敏感配置的 fail-fast 策略
- 生产环境（`NODE_ENV=production` 或运行 `dist/server.cjs`）若缺失 `JWT_SECRET`，`server.ts` 直接 `process.exit(1)` 拒绝启动，防止 JWT 降级到 dev 随机密钥。
- 管理员默认密码首次登录强制改密（`must_change_password` 标记），并在每次启动时检测并告警。
- 数据源凭据（`data_sources.config_json.password`）在启动时扫描明文并就地加密（`encryptSecret`，AES-256-GCM，`enc:v1:` 前缀幂等跳过）。

### 3.4 可插拔后端（Feature Toggle via Env）
- **状态存储**：`REDIS_URL` 存在 → Redis 多实例共享；否则回退内存实现，零依赖。
- **LLM 引擎**：`AI_ENGINE` 显式指定 → `ollama/gemini/qwen`；否则按密钥存在性自动选择（`GEMINI_API_KEY` / `QWEN_API_KEY`）→ 兜底 `ollama`。支持阶段级路由（`LLM_SQL_ENGINE`+`LLM_SQL_MODEL`、`LLM_ANALYSIS_ENGINE`+`LLM_ANALYSIS_MODEL`）和请求级覆盖（`setLlmOverride`）。
- **OIDC 登录**：仅当 `OIDC_ISSUER`、`OIDC_CLIENT_ID`、`OIDC_CLIENT_SECRET` 全部配置时启用，否则走内置 JWT。
- **HMR**：`DISABLE_HMR=true` 关闭 Vite HMR 与文件监听。

### 3.5 运维/监控配置
- Prometheus 指标暴露 `/metrics`，可选 `METRICS_TOKEN` 保护。
- 健康检查 `/api/health` 公开可用。
- 漂移检测周期 `DRIFT_SCAN_INTERVAL_MS`（默认 24h）。
- 限流/配额/缓存键统一经 `StateStore` 抽象，键命名约定：`qp:`（问数计划）、`rqp:`（报表计划）、`qc:`（问数缓存）、`uql:`（用户配额）、`rl:`（IP 限流）。

## 4. 约定与约束

| 约定 | 说明 | 依据 |
|---|---|---|
| 所有 `process.env` 必须通过惰性函数读取 | 避免 ESM import 提升早于 dotenv 加载 | `db.ts`、`auth.ts`、`llmClient.ts` 中多处注释与实现 |
| 生产环境禁止无密钥启动 | 缺失 `JWT_SECRET` 直接退出 | `server.ts` 启动校验 |
| 数据源密码落库必须加密 | 启动时扫描明文并就地迁移 | `db.ts` 启动迁移逻辑 |
| 默认管理员账号首登强制改密 | 新库种子写入 `must_change_password=1` | `db.ts` seed 逻辑 |
| 多实例共享状态必须通过 `REDIS_URL` 开启 | 未配置则回退内存实现 | `stateStore.ts` 工厂函数 |
| LLM 调用具备熔断/重试/并发限制 | 可通过 `LLM_BREAKER_FAILS`、`LLM_RETRY_MAX`、`LLM_MAX_CONCURRENT` 调整 | `llmClient.ts` 韧性层 |
| 前端版本唯一事实源来自 `package.json` | 构建期注入 `VITE_APP_VERSION` | `vite.config.ts` |

## 5. 主要环境变量清单（按子系统）

- **服务器**：`PORT`、`HOST`、`NODE_ENV`
- **MySQL**：`MYSQL_HOST`、`MYSQL_PORT`、`MYSQL_USER`、`MYSQL_PASSWORD`、`MYSQL_DATABASE`、`APP_POOL_MAX`、`EXPECTED_CONCURRENT_USERS`
- **Redis**：`REDIS_URL`
- **认证**：`JWT_SECRET`、`JWT_EXPIRES_IN`、`SCRYPT_PEPPER`、`OIDC_*`（`ISSUER`、`CLIENT_ID`、`CLIENT_SECRET`、`REDIRECT_URI`、`DEFAULT_ROLE`）
- **LLM**：`AI_ENGINE`、`LLM_MODEL`、`LLM_SQL_ENGINE`、`LLM_SQL_MODEL`、`LLM_ANALYSIS_ENGINE`、`LLM_ANALYSIS_MODEL`、`LLM_RETRY_MAX`、`LLM_MAX_CONCURRENT`、`LLM_BREAKER_FAILS`、`LLM_BREAKER_COOLDOWN_MS`、`LLM_ADAPTIVE_TIMEOUT`、`QWEN_API_KEY`、`QWEN_URL`、`QWEN_MODEL`、`QWEN_TIMEOUT_MS`、`GEMINI_API_KEY`
- **监控/运维**：`METRICS_TOKEN`、`DRIFT_SCAN_INTERVAL_MS`、`DISABLE_HMR`、`EVAL_BASE_URL`、`EVAL_USER`、`EVAL_PASS`
