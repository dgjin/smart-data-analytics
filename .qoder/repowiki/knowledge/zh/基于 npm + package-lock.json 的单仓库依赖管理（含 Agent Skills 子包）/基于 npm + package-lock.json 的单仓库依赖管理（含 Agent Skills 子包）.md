## 1. 使用的系统与工具

- **包管理器**：npm（通过 `package-lock.json` 锁定版本，CI 使用 `npm ci` 安装）。
- **Node.js 版本**：CI 固定为 Node 22（`.github/workflows/ci.yml` 中 `setup-node@v4` 的 `node-version: 22`），根 `package.json` 未声明 `engines`，但 `.agents/skills/archify` 子包声明了 `"engines": { "node": ">=18" }`。
- **构建与打包**：前端用 Vite（`vite.config.ts`、`vite.config.browser.js`），服务端用 esbuild 将 `server.ts` 打包为 `dist/server.cjs`（`package.json` scripts 中的 `build` 命令）。
- **测试/类型检查**：Vitest（`vitest run`）、TypeScript（`tsc --noEmit`，分主配置、`tsconfig.server.json`、`tsconfig.strict.json`）、ESLint。
- **CI**：GitHub Actions（`.github/workflows/ci.yml`），在 push/PR to main 时执行 `npm ci` → lint → type check → vitest 全量单测；另有一个 eval-gate 作业校验评测集结构。
- **Husky**：通过 `scripts.prepare = husky` 和 `.husky/pre-push` 做本地钩子。

## 2. 关键文件

| 文件 | 作用 |
|---|---|
| `package.json` | 根工作区依赖声明（dependencies / devDependencies）、脚本入口 |
| `package-lock.json` | npm 锁文件，保证可重复安装 |
| `skills-lock.json` | 锁定 `.agents/skills` 下的 Agent Skill（archify）来源、路径与 `computedHash` |
| `.agents/skills/archify/package.json` | 独立 skill 包的依赖与 `overrides`（强制 `fast-uri` 到 `3.1.5`） |
| `.agents/skills/archify/package-lock.json` | archify skill 自身的 npm 锁文件 |
| `.github/workflows/ci.yml` | CI 中统一使用 `npm ci`，缓存 `npm` 目录 |
| `.husky/pre-push` | 本地 pre-push 钩子（由 prepare 阶段安装） |

## 3. 架构与约定

### 3.1 单一 npm 工作区
项目是**单仓库、单 `package.json`** 的 Node.js 应用，没有使用 npm workspaces。所有运行时依赖集中在根 `package.json` 的 `dependencies` 中（Express、mysql2、pg、ioredis、jsonwebtoken、react、recharts、zustand、prom-client 等），开发依赖集中在 `devDependencies`（Vite、esbuild、typescript、vitest、playwright、eslint、tailwindcss 等）。

### 3.2 依赖锁定与可重现安装
- 通过 `package-lock.json` 锁定精确版本，CI 一律使用 `npm ci`（非 `npm install`），确保每次构建都从锁文件安装，避免漂移。
- `.agents/skills/archify` 作为被 git 子目录引入的第三方 skill，自带独立的 `package.json` 与 `package-lock.json`，其自身依赖通过该子包的锁文件管理，不受根 `package.json` 影响。

### 3.3 依赖版本策略
- 生产依赖普遍使用 `^` 语义化版本范围（如 `express ^4.21.2`、`react ^19.0.1`、`mysql2 ^3.23.2`），允许小版本升级。
- 部分对兼容性敏感的工具使用较窄范围或精确版本，例如 TypeScript 使用 `~5.8.2`（patch 级锁定）。
- 通过 `overrides` 进行依赖冲突修复：archify skill 的 `package.json` 显式覆盖 `fast-uri` 至 `3.1.5`，用于解决下游依赖的版本冲突。

### 3.4 外部 Skill 依赖管理
Agent Skill（archify）通过 `skills-lock.json` 声明来源（`source: tt-a1i/archify`、`sourceType: github`、`skillPath: archify/SKILL.md`）并记录 `computedHash`，使 skill 的引入可追踪、可验证，而非直接以源码形式随意拷贝。

### 3.5 构建产物与依赖外置
- 服务端构建命令 `esbuild server.ts --bundle --platform=node --format=cjs --packages=external` 将运行时依赖标记为 external，最终部署产物 `dist/server.cjs` 依赖运行环境已安装的 node_modules，不内联第三方库。
- 前端通过 Vite 构建静态资源，依赖在构建期解析。

## 4. 约定与约束

- **安装方式**：CI 与推荐安装方式均为 `npm ci`，禁止跳过锁文件安装。
- **Node 版本**：CI 固定 Node 22；archify skill 要求 Node ≥18，实际运行需满足更严格的 CI 版本。
- **Skill 引入**：新增 agent skill 应通过 `skills-lock.json` 声明来源与 hash，而不是直接复制源码到 `.agents/skills`。
- **依赖变更流程**：修改 `package.json` 后应提交对应的 `package-lock.json`，否则 CI 的 `npm ci` 会失败。
- **依赖冲突处理**：通过 `overrides` 字段在特定子包（如 archify）中强制指定依赖版本，避免传递性依赖冲突。
- **私有 registry**：仓库中未发现 `.npmrc`、`registry=` 或 `--registry` 参数，默认使用官方 npm registry；如需私有源需在 CI 环境变量或 `.npmrc` 中配置。
- **安全扫描/审计**：仓库中未见 `npm audit` 或 Dependabot/ Renovate 等自动化更新配置，依赖更新主要依赖人工维护 `package.json` 与 `package-lock.json`。
