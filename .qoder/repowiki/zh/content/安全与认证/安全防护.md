## 项目结构
安全相关能力按职责分层组织：

- 状态存储抽象：Memory/Redis 统一接口，支撑限流、缓存、锁等

- 认证与授权

  - 提示词注入特征拦截、控制字符清理、长度限制
  - 历史消息净化，防止模型输出回流污染上下文
  - 敏感列识别与剔除，避免进入 LLM 上下文
  - SQL 安全执行层：仅 SELECT、单语句、表名白名单、AST 复核、敏感列拒绝、强制 LIMIT、执行超时、结果行数截断、行级权限注入、EXPLAIN 预估扫描量拦截
- **依赖安全管理**
  - **第三方包版本锁定：通过 package.json overrides 强制关键依赖版本**
  - **CVE 漏洞修复：qs@^6.16.0 修复 express/body-parser 链 DoS 漏洞**
  - **测试框架安全：vitest 4.1.11 修复 @vitest/mocker 安全问题**
  - **供应链安全验证：定期扫描依赖漏洞，及时更新补丁**
- **文件验证防护**
  - **PNG 二进制签名验证：isPngDataUri 函数实现双重校验（前缀+魔数）**
  - **恶意图片检测：阻断 ICNS/JXL/HEIF 等格式的无限循环 DoS 攻击**
  - **报告导出安全：normalizeExportData 与 buildReportPptx 双重防护**
- 限流与配额
  - IP 级滑动窗口限流（内存或 Redis 固定窗口）
  - 用户级每小时配额 + 同用户并发互斥（分布式锁/内存槽）
- 机密与密钥
  - 数据源凭据 AES-256-GCM 加密存储，迁移期兼容明文
  - 密码哈希使用 scrypt，参数可调，支持 pepper
- 审计与监控
  - 全链路审计落库（成功/降级/错误/拒绝），失败不阻塞主流程
  - Prometheus 指标埋点（低基数 label，fail-open）
  - 统一日志出口，级别可控

## 详细组件分析

### 认证与授权（JWT、角色、密码、ACL、OIDC）
- JWT 签发与校验：服务端在鉴权中间件中解析 token 并回查用户状态，附加 req.user；支持强制首次改密策略
- 角色守卫：基于角色的路由级访问控制
- 密码强度与哈希：统一入口校验，scrypt 加盐，支持 pepper；兼容旧格式
- OIDC：可选的统一身份登录流程（授权码模式）
- 数据源 ACL：部门/个人维度授权，管理员豁免；提供审批并入个人授权的原子更新

### PNG 文件二进制签名验证与 DoS 攻击防护
**新增** 报告导出功能中的 PNG 文件验证机制，防止恶意图片处理导致的拒绝服务攻击：

- **双重验证机制**：isPngDataUri 函数实现 data URI 前缀验证 + 8 字节 PNG 魔数二进制签名验证
- **恶意格式检测**：专门拦截 ICNS、JXL、HEIF 等可能触发 image-size 库无限循环的格式
- **多层防护**：normalizeExportData 归一化时验证 + buildReportPptx 二次验证，确保即使绕过第一层也能被拦截
- **优雅降级**：伪造载荷自动回退为纯文字页面，保证 PPTX 产物有效性

```mermaid
flowchart TD
Input["PNG Data URI 输入"] --> PrefixCheck["前缀验证 (data:image/png;base64,)"]
PrefixCheck --> |通过| MagicCheck["8字节魔数验证"]
PrefixCheck --> |失败| Reject["拒绝输入"]
MagicCheck --> |真实PNG| Allow["放行处理"]
MagicCheck --> |ICNS/JXL/HEIF| Reject
MagicCheck --> |其他格式| Reject
Allow --> Normalize["normalizeExportData 验证"]
Reject --> TextFallback["文字兜底"]
Normalize --> BuildPptx["buildReportPptx 二次验证"]
BuildPptx --> ValidPPTX["生成有效 PPTX"]

```

### SQL 安全执行层（防注入、白名单、AST、行级权限、EXPLAIN、超时、截断）
- 仅允许 SELECT，单语句，禁止危险关键字与 INTO 写操作
- 表名白名单校验（结合 scope 与敏感列过滤后的 Schema）
- AST 二道防线：语法树级复核语句类型与表引用
- 行级权限注入：对受控表自动包裹 WHERE 谓词，递归处理子查询/CTE/UNION
- EXPLAIN 防线：预估扫描行数超阈值则拦截，保护后端数据库
- 强制 LIMIT 与结果行数截断；MySQL 注入 MAX_EXECUTION_TIME hint
- 场景化连接池与超时：交互/分析链/导出独立配额与超时档位

### 限流与配额（IP 级、用户级、并发互斥）

## 性能与安全权衡
- SQL 执行层采用"正则+AST"双重校验，兼顾误杀率与安全性；CTE 场景下优先 AST 解析，失败 fail-closed
- EXPLAIN 防线以预估扫描量为依据，保护后端数据库免受大范围扫描；EXPLAIN 失败 fail-open 放行但不影响安全底线
- **依赖安全检查在构建阶段执行，不影响运行时性能；PNG 验证仅解码前 16 个 base64 字符，开销极小**
- **文件验证采用短路策略：前缀验证失败立即拒绝，魔数验证仅在必要情况下执行**
- 连接池按场景分级（交互/分析链/导出），避免后台任务挤占交互资源；超时按场景差异化配置
- 限流与配额在 Redis 模式下具备全局共享与 TTL 自动过期能力，提升多实例可用性与一致性
- 审计与监控采用旁路设计，失败不阻塞主流程，保证高可用

## 结论
本系统构建了从输入到执行的纵深防御体系：认证授权、输入净化、SQL 白名单与 AST 校验、行级权限、EXPLAIN 防线、结果截断与超时控制，配合 IP 级限流、用户级配额与并发互斥，形成多层次防护。**新增的依赖安全加固机制通过强制版本锁定修复已知 CVE 漏洞，PNG 文件二进制签名验证有效阻断恶意图片处理导致的 DoS 攻击**。机密管理通过 AES-256-GCM 与 scrypt 哈希强化数据安全。审计与监控提供可观测性，便于问题定位与持续改进。整体设计在高可用前提下最大化安全边界，适合企业级部署。
