# 多实例部署指南（P2-13）

本文档说明如何将智能问数分析系统以多副本（≥2 实例）方式部署，实现水平扩展与滚动发布。
应用为**无状态设计**：会话、缓存、限流、并发槽等全部共享状态均已外置，副本数可随时增减。

## 1. 目标架构

```
                ┌────────────┐
   客户端 ────▶ │  LB/Nginx  │（轮询分发，无粘性要求）
                └─────┬──────┘
              ┌───────┼───────┐
          ┌───▼───┐  ┌▼────┐  ┌▼────┐
          │ app-1 │  │app-2│  │app-N│   Node 22，无状态副本
          └───┬───┘  └┬────┘  └┬────┘
              └───────┼───────┘
        ┌─────────────┼─────────────────┐
   ┌────▼────┐   ┌────▼────┐      ┌─────▼─────┐
   │  MySQL  │   │  Redis  │      │  LLM 引擎  │
   │(业务/审计│   │(共享状态│      │Ollama/Qwen │
   │ /指标库) │   │  缓存等)│      │            │
   └─────────┘   └─────────┘      └───────────┘
```

## 2. 共享状态盘点（无状态化依据）

| 状态项 | 存储位置 | 多实例行为 |
|---|---|---|
| 登录会话 | JWT（无状态签发/校验） | 任意实例可校验；`JWT_SECRET` 必须全实例一致 |
| 问数结果缓存 L1（精确） | Redis `qc:*`（未配 REDIS_URL 时进程内存） | 全实例共享命中 |
| 问数结果缓存 L2（语义） | Redis `qcidx:*`（embedding 索引） | 全实例共享命中 |
| IP 限流计数 | Redis `rl:*` 固定窗口 INCR | 全实例共享限额 |
| 用户配额/并发槽 | Redis `uql:*` INCR + 分布式锁 | 跨实例互斥，崩溃自动释放 |
| 计划模式一次性计划 | Redis `qp:*`（GETDEL 消费） | 任意实例可消费 |
| Schema 上下文缓存 | Redis（schemaContext 模块） | 全实例共享 |
| OIDC 登录 state（P2-13） | Redis `oidc:st:*`（GETDEL 一次性） | 发起与回调可落不同实例 |
| 用户/数据源/指标/审计/知识库 | MySQL | 单点权威存储 |
| LLM 熔断器/并发信号量 | 进程内存（**有意保留**） | 实例级自我保护，无需共享 |
| 数据源连接池 | 进程内存（**有意保留**） | 连接不可跨进程共享，各实例独立 |
| OIDC discovery 文档 | 进程内存 1h（性能缓存） | 各实例各自回源一次，无正确性问题 |

> 结论：配置 `REDIS_URL` 后，全部**正确性相关**的共享状态经 Redis/MySQL 全局一致；
> 仅性能缓存与实例级保护组件保留进程内存，不影响多实例正确性。

## 3. 环境变量要求

| 变量 | 要求 | 说明 |
|---|---|---|
| `REDIS_URL` | **多实例必须** | 如 `redis://redis:6379`；未配置时各实例状态独立（仅单实例可接受） |
| `JWT_SECRET` | **全实例一致** | 否则跨实例会话校验失败（未设置将拒绝启动） |
| `MYSQL_*` | 全实例一致 | 指向同一 MySQL |
| `SCRYPT_PEPPER` | 全实例一致 | 密码哈希加固（如启用） |
| `PORT`/`HOST` | 可实例级 | 容器内固定 3000 即可 |
| `OLLAMA_URL` / `LLM_*` | 建议一致 | 指向同一 LLM 服务或其负载均衡 |

## 4. SSE 流式问数与负载均衡

- 全系统仅一处 SSE：`POST /api/query/natural-language`（`stream=true`）。
  该实现为**单连接内闭环**（请求即流，阶段事件与最终结果在同一 HTTP 连接内推送完毕），
  天然满足粘性要求——**LB 无需 ip_hash/会话保持**。
- LB 侧唯一要求：**长连接不被截断**：
  - Nginx：`proxy_buffering off; proxy_read_timeout 600s;`（见 `deploy/nginx.multi-instance.conf`）
  - 应用已设置响应头 `X-Accel-Buffering: no` 与 `Cache-Control: no-cache`
- 云 LB（ALB/SLB）：将 `/api/*` 的 idle timeout 调至 ≥ 600s。

## 5. 部署步骤

### Docker Compose（示例编排见 `docker-compose.multi-instance.yml`）

```bash
export JWT_SECRET=<强随机串> MYSQL_USER=<...> MYSQL_PASSWORD=<...> ADMIN_PASSWORD=<...>
docker compose -f docker-compose.multi-instance.yml up -d --build
# 访问 http://localhost:8080（Nginx 轮询 app1/app2）
```

### 裸机/虚机多副本

```bash
# 每个副本（可同机不同端口或不同机器）：
REDIS_URL=redis://<redis-host>:6379 JWT_SECRET=<一致密钥> MYSQL_HOST=<...> \
  npm run build && node dist/server.cjs
```

## 6. 多实例正确性验证（本地双实例实测步骤）

```bash
redis-server --port 6379 --daemonize yes          # 1) 起共享 Redis
REDIS_URL=redis://127.0.0.1:6379 PORT=3000 npm run dev &   # 2) 实例 A
REDIS_URL=redis://127.0.0.1:6379 PORT=3001 npm run dev &   # 3) 实例 B
# 4) 限流跨实例共享：同一 IP 向 A 打 20 次、再向 B 打 11 次 /api/auth/login → 第 31 次返回 429
# 5) 缓存跨实例命中：向 A 发起问数，同问题再向 B 发起 → B 命中缓存（fromCache: true）
# 6) OIDC state 跨实例：A 实例 createState → B 实例 consumeState 成功且一次性
```

## 7. 滚动发布与扩缩容

- **扩容**：直接新增副本注册进 LB——无状态、无数据迁移。
- **滚动发布**：LB 摘除副本 → 等待在途请求完成（问数最长 600s 或配置 drain 超时）→ 替换新版本 → 健康检查 `/api/health` 通过后回挂。
- **缩容**：同上摘除即可；Redis 并发槽 TTL（15 分钟）保证崩溃实例的槽位自动释放。
- **Redis 不可用**：缓存/限流/配额按设计降级（缓存 fail-open 视为未命中；限流 fail-closed 拒绝；
  OIDC 登录拒绝发起），业务核心链路（问数直连）不中断，但**应尽快恢复 Redis**。

## 8. 注意事项

- 审计/导出审批等 MySQL 写入无跨实例冲突（自增主键 + 行级原子操作）。
- 语义缓存阈值（`SEMANTIC_CACHE_THRESHOLD`，默认 0.95）须全实例一致，否则同问题在不同实例命中行为不同。
- 评测/压测脚本（`server/eval/*`）建议固定打单一实例，避免缓存跨实例命中影响测量。
