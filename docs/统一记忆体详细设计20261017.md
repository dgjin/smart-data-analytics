# 智能问数统一记忆体详细设计

> 版本：v1.0（2026-10-17）
> 状态：结论与决策点已批准，设计待评审后实施
> 关联：评估结论（2026-10-17）· 一期范围 P0/P1
> 决策基线：概念统一为"本地记忆体"，实现本地化（MySQL + 现有 embedding），不引入外部记忆服务依赖；记忆审核后生效；跨项目共享放二期。

---

## 1. 背景与目标

### 1.1 现状结论（评估摘要）

问数链路已有 7 路并行"类记忆"注入（[liveQuery.ts](../server/query/liveQuery.ts)），但缺四件事：

1. **统一记忆抽象**：7 路各自实现检索、固定槽位、预算分散（knowledge 2700 / fewshot 3600 / external 1200 / history 1500 token）。
2. **纠错记忆**：`query_feedback` 仅有 `verdict`，实测 30 UP / **0 DOWN**，点踩后无"错在哪、正确做法是什么"的采集；`adversarial_samples` 仅 2 条 PENDING。
3. **记忆生命周期**：无置信度、衰减、合并去重、遗忘；点赞 1 次与 20 次等价。
4. **引用留痕与评测**：无法回答"哪条记忆影响了哪次问数、效果如何"。

### 1.2 一期目标（可度量）

| 目标 | 度量 |
|---|---|
| 纠错可采集、可沉淀、可生效 | 点踩纠正提交率、纠错记忆审核通过数 |
| 记忆统一召回与留痕 | trace 新增 memory 阶段，记录通道/条目/分数/token |
| 质量不降、纠错复发下降 | eval 集准确率 ≥ 基线；纠正回归集复发率下降 ≥ 30%（灰度 2 周） |
| 延迟可控 | 记忆召回 P95 ≤ 300ms；问数整体 P95 增量 ≤ 5% |
| 零回归、可秒级回滚 | 现有 2187 测试全过；`MEMORY_ROUTER_ENABLED=off` 行为与现状完全一致 |

### 1.3 非目标（一期不做）

- 不搬迁语义指标、铁律、知识库、样例库到新存储（继续以现有表为权威来源）。
- 不接入 agentmemory 等外部记忆进程（二期以 `MemoryProvider` 可插拔后端预留）。
- 不做无审核的自动记忆生效（自动记忆一律进候选池）。
- 不改变 SQL 执行层、安全白名单、DLP 与行级权限逻辑。

## 2. 总体架构

```
                    ┌───────────────────────────── 问数阶段一/二 ─────────────────────────────┐
                    │ liveQuery.ts                                                          │
                    │   recallMemory({query, scope, budget})  ←── 新增统一入口（可开关）       │
                    └───────────────┬───────────────────────────────────────────────────────┘
                                    │
                     ┌──────────────▼──────────────┐
                     │      Memory Router          │  并行召回 → 去重 → 加权融合 → 预算/槽位
                     │  server/memory/router.ts    │  超时降级（单通道 400ms / 整体 800ms）
                     └──────────────┬──────────────┘
        ┌──────────┬──────────┬──────────┬──────────┬──────────┬──────────┬──────────┐
        ▼          ▼          ▼          ▼          ▼          ▼          ▼          ▼
    IronCh.  MetricCh.  KnowledgeCh.  ExternalCh.  ExampleCh.  NegativeCh.  ConversationCh.  CorrectionCh.(新增)
    iron_rules  metric_*  knowledge_*  external_kb  sql_examples  query_feedback  conversation_*  memory_items
        │          │          │          │          │          │          │          │
        └──────────┴──────────┴──────────┴──────────┴──────────┴──────────┴──────────┘
                                    │
                     ┌──────────────▼──────────────┐
                     │   MemoryProvider (MySQL)    │  统一读写 + 置信度/衰减/合并/归档
                     │   memory_items / usage      │  + Adapter 只读现有表（零迁移）
                     └─────────────────────────────┘
                                    │
                     ┌──────────────▼──────────────┐
                     │ 治理与观测：Admin API + 面板 │  候选审核 / 条目管理 / 统计 / 引用留痕
                     └─────────────────────────────┘
```

**设计原则**

- **权威资产不动**：指标/铁律/知识库/样例库/对话历史继续由现有表承载，Router 通过 Adapter 只读复用，避免双写不一致。
- **新增只增表**：仅新增 `memory_items`、`memory_candidates`、`memory_usage` 三张表，不改存量表结构。
- **失败不阻断**：任一通道超时/异常仅跳过该通道，Router 整体异常回退旧七路实现（保留一个版本）。
- **影子先行**：`shadow` 模式只记录召回结果不注入，用于离线对比后再开启注入。

## 3. 数据模型

### 3.1 新增表 DDL

```sql
-- 记忆主表：一期仅承载 CORRECTION（纠错）与可选的 PREFERENCE（用户偏好）；
-- 其余类别由 Adapter 读取现有表，不在此表重复存储。
CREATE TABLE IF NOT EXISTS memory_items (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  kind VARCHAR(20) NOT NULL DEFAULT 'CORRECTION' COMMENT 'CORRECTION/PREFERENCE',
  data_source_id VARCHAR(64) NOT NULL DEFAULT '' COMMENT '命名空间：数据源',
  user_id INT NULL COMMENT 'NULL=数据源级共享；非空=个人记忆',
  question VARCHAR(500) NOT NULL DEFAULT '' COMMENT '触发记忆的问题',
  content TEXT NOT NULL COMMENT '纠正内容（结构化中文，注入用）',
  error_type VARCHAR(20) NOT NULL DEFAULT 'OTHER' COMMENT 'TABLE_CHOICE/COLUMN/CALIBER/UNDERSTANDING/OTHER',
  expected_sql VARCHAR(2000) NOT NULL DEFAULT '' COMMENT '管理员确认的正确 SQL（可空）',
  embedding_json MEDIUMTEXT NULL COMMENT 'content 向量（复用 nomic-embed-text/qwen）',
  source VARCHAR(20) NOT NULL DEFAULT 'USER' COMMENT 'USER/ADMIN/DERIVED',
  confidence DECIMAL(3,2) NOT NULL DEFAULT 0.40 COMMENT '置信度 0-1',
  hits INT NOT NULL DEFAULT 0 COMMENT '被注入次数',
  last_used_at TIMESTAMP NULL DEFAULT NULL,
  status ENUM('ACTIVE','ARCHIVED','DISABLED') NOT NULL DEFAULT 'ACTIVE',
  created_by VARCHAR(50) NOT NULL DEFAULT '',
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX idx_mem_scope (data_source_id, kind, status),
  INDEX idx_mem_user (user_id, status),
  INDEX idx_mem_recent (last_used_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='统一记忆条目（纠错为主）';

-- 候选池：点踩纠正、自动识别、AI 提炼均先入候选，审核后转 ACTIVE 记忆
CREATE TABLE IF NOT EXISTS memory_candidates (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  kind VARCHAR(20) NOT NULL DEFAULT 'CORRECTION',
  data_source_id VARCHAR(64) NOT NULL DEFAULT '',
  user_id INT NULL,
  question VARCHAR(500) NOT NULL DEFAULT '',
  wrong_sql VARCHAR(2000) NOT NULL DEFAULT '',
  error_type VARCHAR(20) NOT NULL DEFAULT 'OTHER',
  payload JSON NOT NULL COMMENT '原始采集：错误类型/期望口径文本/期望SQL/来源trace',
  status ENUM('PENDING','APPROVED','REJECTED','MERGED') NOT NULL DEFAULT 'PENDING',
  reviewed_by VARCHAR(50) NOT NULL DEFAULT '',
  reviewed_at TIMESTAMP NULL DEFAULT NULL,
  memory_id BIGINT NULL COMMENT '审核通过后生成的 memory_items.id',
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_cand_ds (data_source_id, status, id),
  INDEX idx_cand_user (user_id, status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='记忆候选（待审核）';

-- 引用留痕：哪次问数、注入了哪条记忆、分数与 token；支撑效果归因与复发统计
CREATE TABLE IF NOT EXISTS memory_usage (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  trace_id VARCHAR(40) NOT NULL DEFAULT '',
  user_id INT NOT NULL,
  data_source_id VARCHAR(64) NOT NULL DEFAULT '',
  memory_ref VARCHAR(80) NOT NULL COMMENT 'mem:<id> 或 ext:<table>:<id>',
  channel VARCHAR(24) NOT NULL DEFAULT '',
  rank_no INT NOT NULL DEFAULT 0,
  score DECIMAL(6,4) NOT NULL DEFAULT 0,
  tokens INT NOT NULL DEFAULT 0,
  injected TINYINT(1) NOT NULL DEFAULT 1 COMMENT 'shadow 模式下为 0',
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_usage_trace (trace_id),
  INDEX idx_usage_mem (memory_ref, created_at),
  INDEX idx_usage_ds (data_source_id, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='记忆引用留痕';
```

### 3.2 现有表映射（Adapter 只读）

| 通道 | 来源表 | 关键字段 | 派生置信度（不写回） |
|---|---|---|---|
| IRON | `iron_rules` | title/content，ACTIVE | 1.00（强制） |
| METRIC | `metric_definitions` | name/synonyms/formula，ACTIVE | 1.00（命中即注入） |
| KNOWLEDGE | `knowledge_base` | chunk_text/embedding_json | 0.9 × 时效衰减 |
| EXTERNAL | `external_kb_sources` | 运行时外部检索结果（不落记忆表） | 0.85 × 时效衰减 |
| EXAMPLE | `sql_examples` | question/sql_text/source | MANUAL 0.95 / FEEDBACK_UP 0.70 / IMPORT 0.60 × 衰减 |
| NEGATIVE | `query_feedback` | verdict=DOWN 的 question/executed_sql | 0.50 × 衰减（仅问题与错表名） |
| CONVERSATION | `conversation_history` | SUCCESS 的问答对 | 0.60 × 衰减（仅个人） |
| CORRECTION | `memory_items` | 见 3.1 | 存储值 × 衰减 |

### 3.3 容量与保留

- `memory_items`：按数据源 ≤ 5,000 条预期；`memory_usage` 保留 90 天（每日抽样清理，参考 `query_trace` 做法）。
- 候选池：`REJECTED` 保留 30 天后清理；`MERGED` 仅保留指针。
- 级联删除：用户删除对话历史 → 同步删除其个人 `memory_items(user_id)`；数据源删除 → 删除该 `data_source_id` 的记忆与候选。

### 4.2 核心接口

```ts
export type MemoryKind = 'IRON' | 'METRIC' | 'KNOWLEDGE' | 'EXTERNAL' | 'EXAMPLE' | 'NEGATIVE' | 'CONVERSATION' | 'CORRECTION';

export interface MemoryScope {
  dataSourceId: string;
  userId: number;         // 个人记忆召回域
  role: 'ADMIN' | 'ANALYST' | 'VIEWER';
}

export interface MemoryItem {
  id: number;
  kind: MemoryKind;
  dataSourceId: string;
  userId: number | null;
  question: string;
  content: string;
  errorType: string;
  expectedSql: string;
  confidence: number;
  hits: number;
  lastUsedAt: string | null;
  status: 'ACTIVE' | 'ARCHIVED' | 'DISABLED';
}

export interface RecalledMemory {
  ref: string;            // mem:12 / ext:sql_examples:34
  kind: MemoryKind;
  content: string;        // 已格式化的注入片段
  sql?: string;           // 仅内部评估使用，默认不注入
  score: number;          // 融合后分数
  confidence: number;
  tokens: number;
  forced?: boolean;       // 铁律/指标命中：不受预算裁剪
}

export interface MemoryChannel {
  id: MemoryKind;
  /** 通道内检索；返回候选（未格式化），按通道自身相关度排序 */
  recall(ctx: RecallContext): Promise<ChannelHit[]>;
  /** 通道最小保留槽位（条数）与可选开关 */
  minSlots: number;
  enabled(): boolean;
}

export interface MemoryProvider {
  recallItems(scope: MemoryScope, query: string, opts: { embed?: number[]; limit: number }): Promise<MemoryItem[]>;
  rememberCandidate(input: RememberInput): Promise<number>;
  approveCandidate(id: number, reviewer: string, patch?: Partial<MemoryItem>): Promise<number>;
  rejectCandidate(id: number, reviewer: string): Promise<void>;
  touchUsage(rows: UsageRow[]): Promise<void>;   // 批量，fire-and-forget
  updateConfidence(id: number, delta: number): Promise<void>;
  archiveStale(days: number, minConfidence: number): Promise<number>;
}
```

## 5. 召回编排（Memory Router）

### 5.1 流程

```
recallMemory(ctx):
  1. 灰度判定：userId 哈希 ∉ rollout → 返回 null（调用方走旧七路）
  2. 并行召回：所有 enabled 通道 → Promise.allSettled + 单通道 400ms 超时
  3. 归一化：每通道取 topN（默认 8），附带通道内相关度 rel∈[0,1]
  4. 去重：SQL 指纹（normalizeSql → sha1）+ 文本指纹（去空白前 80 字）
     - 同指纹保留 score 最高者，其余累加 hits 计入命中
  5. 融合：final = rel × confidence × decay × sourceWeight
     - sourceWeight: CORRECTION=1.1, IRON/METRIC=1.0, KNOWLEDGE=1.0, EXAMPLE=0.9, EXTERNAL=0.85, NEGATIVE=0.8, CONVERSATION=0.7
     - decay = exp(-ln2 × ageDays / halfLife)
  6. 预算：强制通道（IRON 全量 / METRIC 命中）先占位；其余按 final 降序，
     受 MEMORY_ITEM_LIMIT 与总预算约束：各通道原有 token 上限保留（knowledge 2700 / external 1200 /
     example 3600 为通道内上限），融合后注入总量硬上限 6000 token（不含铁律与指标强制段）；
     超出按分数截断，KNOWLEDGE 保底 1 块、CORRECTION 保底 1 条、EXTERNAL 有成功源时保底 1 块）
  7. 输出：按 强制 → 纠错 → 知识 → 外部知识 → 样例 → 反例 → 对话 顺序拼装 memory block，带来源标注
  8. 留痕：memory_usage 批量写入（injected=0 in shadow）；trace step_type='memory'
  9. 异常：Router 抛错 → 调用方回退旧七路（记录告警日志）
```

### 5.2 注入格式（追加到阶段一 system prompt，现有段落之后）

```
【记忆体召回】（统一管理的历史经验，生成 SQL 时必须遵循；按来源标注，禁止照抄完整 SQL）
[铁律·强制] ……（保持现有 buildIronRulesPrompt 输出不变）
[指标口径] ……（保持现有 buildMetricPrompt 输出不变）
[历史纠错·高优先] 问题：各机构本年投放金额排名 → 纠正：投放金额须用 MAX(BBRQ) 子查询去重后汇总（错误类型：口径）
[业务知识] ……（现有知识片段）
[外部知识] ……（现有外部知识库片段，独立预算）
[正确样例] ……（现有 few-shot 说明，保持消息对形式）
[反面教材] ……（现有反例说明，追加"优先参考历史纠错"）
[个人沉淀] ……（现有个人 few-shot）
```

约束：`expected_sql` 默认不注入（防照抄），仅在管理员勾选"允许作为正确样例"时进入 EXAMPLE 通道；纠错只给"正确口径文字"。

### 5.3 集成改造点（liveQuery.ts）

- 新增入口：`const memory = await recallMemory({ query, scope, budget }).catch(() => null);`
- 若 `memory` 非空：用 `memory.prompt` 替代现有 `knowledge + externalSnippet + negativePairs` 的字符串拼装；`fewShotPairs`/`convPairs` 保持消息对形式（由 Router 统一返回 `fewShotMessages`）。
- 若 `memory === null`（关闭/灰度外/异常）：**原七路逻辑原样执行**（保留一个版本，下个版本删除）。
- trace：新增 `stepType: 'memory'`（`query_trace.step_type` 为 VARCHAR(20)，无需改表），summary 示例：
  `通道 7/8 命中；注入 knowledge=2 external=1 example=3 correction=1，共 1873 token；耗时 214ms；去重合并 2 条`

## 6. 纠错记忆闭环（核心增量）

### 6.1 采集（用户侧，低摩擦）

点踩后弹出轻量 Popover（跳过则仅记 DOWN，行为与现状一致）：

- 错误类型（单选，必填）：选错表 / 字段错误 / 口径或聚合错误 / 理解偏差 / 其他
- 补充说明（可选，≤200 字）：如"投放金额应按最新批次去重"
- 期望 SQL（可选，折叠区，管理员/分析师可见）

接口扩展（向后兼容，原字段不变）：

```
POST /api/query/feedback
{ dataSourceId, question, sql, verdict, provenance,
  correction?: { errorType: 'TABLE_CHOICE'|'COLUMN'|'CALIBER'|'UNDERSTANDING'|'OTHER',
                 note?: string, expectedSql?: string } }
→ 200 { success: true, candidateId?: number }
```

服务端行为：写入 `query_feedback`（原逻辑不变）→ 若 `correction` 存在，写 `memory_candidates`（PENDING，payload 含 traceId）→ 同问题同类型去重（bigram≥0.85 合并 payload 计数）。

### 6.2 自动识别（一期可选，默认关）

规则：下一轮问题以"不对/不是/应该/要按/改成"开头，且与上轮问题 bigram 相似度 ≥ 4 → 生成候选（`source=DERIVED`，confidence 0.3）；仅提示管理员，不自动生效。开关 `MEMORY_AUTO_CANDIDATE=off`。

### 6.3 审核与生效（管理员侧）

系统管理 → 新增「记忆管理」页签：候选列表（数据源筛选/错误类型筛选/相似合并组）→ 查看原问题、错误 SQL、用户说明 → 编辑纠正文本 / 填写 expected_sql → 通过（生成 `memory_items`，confidence：用户提交 0.4、管理员确认 0.9、填写 expected_sql 1.0）/ 驳回。

### 6.4 检索与复发统计

- 纠错通道：按 `data_source_id + status='ACTIVE'` 取最近 200 条（按 last_used_at/confidence），embedding 余弦取 top2（embedding 不可用降级 bigram），阈值 0.45。
- 复发统计：以 `memory_usage.memory_ref` 关联纠正条目，统计"注入后 7 天内同数据源同类错误（同 error_type 且问题相似）再次出现"的比例，作为灰度期核心指标。

## 7. 记忆治理

| 规则 | 说明 |
|---|---|
| 置信度更新 | UP +0.05（≤1）；DOWN −0.20（≥0）；被注入且该次问数成功 +0.01（≤1）；管理员可直改 |
| 衰减 | decay = exp(-ln2 × ageDays / halfLife)；halfLife：CORRECTION 180d、EXAMPLE 120d、KNOWLEDGE 365d、CONVERSATION 60d |
| 合并去重 | 同归一化 SQL + 问题相似 ≥0.9 → 保留高置信，hits 累加，来源合并；候选标 MERGED |
| 归档 | 90 天未命中且 confidence < 0.3 → ARCHIVED（不物理删除，可恢复） |
| 遗忘 | 用户删除对话历史 → 级联删除个人记忆；数据源删除 → 级联删除该域记忆与候选 |
| 审计 | 管理员所有改动用现有审计机制记录（action=memory.*，含前后值摘要） |

## 8. 权限与安全

- **命名空间强制**：`scope.dataSourceId` 必填；个人记忆仅 `user_id` 本人召回；管理员可跨用户管理但召回仍受数据源 ACL 约束。
- **ACL 前置**：Router 召回前校验 `checkDataSourceAccess(user, dataSourceId)`，失败直接返回空（不区分"无记忆"与"无权限"错误文案）。
- **DLP**：写入记忆前对 `expected_sql`/`content` 做敏感列扫描（复用 DLP 规则），命中敏感列则拒存并提示；已有 schema 层剔除不受影响。
- **注入安全**：记忆文本入库前去除 SQL 代码块以外的可执行指令；注入时只作为"参考经验"段落，不改变系统安全约束（只读、白名单、行级谓词仍由执行层强制）。
- **审计留痕**：`memory_usage` + 现有审计；管理操作记录操作人、时间、条目、前后差异摘要。

## 9. 观测与评测

### 9.1 运行指标（Prometheus，复用现有 metrics）

- `memory_recall_duration_ms{channel}`、`memory_recall_total{result=hit|empty|timeout|error}`
- `memory_injected_tokens`、`memory_channel_hits{channel}`
- `memory_correction_recurrence_rate`（7 日复发率，每日离线计算后以 gauge 暴露，按数据源）

### 9.2 评测

- **离线**：复用 `runEval`（准确率门禁 `--min-accuracy`）对比开关开/关；新增 `server/eval/memoryCases.json`（从历史纠正与点踩构造 30–50 条，含期望纠正口径关键词）。
- **检索评测**：扩展 `retrievalRunner`，新增 memory 通道召回@3 指标（与现有知识库检索评测同构）。
- **影子对比**：`shadow` 模式记录"若注入会选哪些记忆 + 预估 token"，与 `on` 模式对比注入稳定性，人工抽检 50 条。
- **灰度**：`on` 模式先 20% 用户，观察 2 周复发率、准确率、P95 延迟；达标后全量。

### 9.3 验收标准

| 类别 | 标准 |
|---|---|
| 功能 | 点踩纠正可提交并生成候选；审核通过后该数据源后续相似问题可召回（trace 可见） |
| 质量 | eval 集准确率不低于基线（门禁阈值）；纠正回归集复发率下降 ≥30%（2 周灰度） |
| 性能 | 召回 P95 ≤300ms（embedding 缓存命中 ≤120ms）；问数 P95 增量 ≤5% |
| 稳定 | `MEMORY_ROUTER_ENABLED=off` 与现状零差异；全量测试通过，新增单测 ≥40 例 |
| 安全 | 越权召回单测 0 失败；敏感列不入记忆；删除级联生效 |

## 13. 风险与回滚

| 风险 | 对策 |
|---|---|
| 记忆污染 | 审核生效 + 置信度分级 + 禁用/回滚 + 引用留痕 |
| 延迟劣化 | 并行 + 400/800ms 超时 + embedding 缓存（现有）+ P95 门禁 |
| Token 膨胀 | 强制通道外全局预算 + 保底槽位 + 截断留痕 |
| 权限泄露 | scope 强制 + ACL 前置 + 越权单测 |
| 集成回归 | 开关默认 off + 旧七路保留 + shadow 先行 |
| 存储增长 | usage 90 天清理、候选 30 天清理、归档不删除 |

**回滚**：`MEMORY_ROUTER_ENABLED=off` 即时恢复旧链路；DDL 只增不改，回滚无需迁移；新表可保留不影响现有功能。
