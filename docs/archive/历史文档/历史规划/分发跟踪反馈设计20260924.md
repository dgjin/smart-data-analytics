# 分发跟踪反馈设计（匿名部署心跳）

> 日期：2026-09-24　状态：**待批准**　目标版本：v0.9.73

## 一、背景与目标

本项目经 GitHub / Gitee 开源分发（含 `start.sh` 本机、生产构建、Docker 三类部署方式）。作者无法感知是否有人 clone 部署并实际运行。

**目标**：
1. **部署知晓**：任一部署首次启动时，作者收到一封「新部署上线」邮件通知；
2. **规模洞察**：可查询活跃实例数、版本分布、最近活跃时间；
3. **增长观察**：结合被动统计（GitHub Traffic / Star）观察分发增长。

**边界（不追求）**：不识别具体使用者身份、不采集任何业务数据、不阻断或影响部署者任何功能。

**已确认决策（作者拍板）**：接收端 = Cloudflare Worker 中转（Workers + KV）；默认行为 = 默认开启·持续心跳（启动 + 每 24h）；通知渠道 = 邮件。

## 二、总体设计：三条跟踪线

| 线 | 手段 | 能力 | 侵入性 |
|---|------|------|--------|
| **L1 主动心跳（核心）** | 应用启动后上报匿名事件 → Worker 落库 → 邮件通知 | 精确知晓「有人部署并运行」，含版本/OS/部署形态 | 匿名最小化、可一键关闭 |
| **L2 被动观察（零代码）** | GitHub Watch 邮件订阅 + Insights→Traffic（clone 统计）；Gitee 星标/动态 | 知晓「有人下载」 | 无 |
| **L3 引导反馈** | README 部署反馈引导段 + 首次启动日志透明声明 | 提升主动反馈率、合规透明 | 无 |

```
部署者机器                                   作者（dgjin）
┌──────────────────────┐    POST /hb     ┌──────────────────┐
│ 智能问数应用          │ ───────────────▶│ Cloudflare Worker │

```

## 三、应用侧设计（L1 核心）

### 3.1 模块与挂载

- 新增 `server/telemetry/heartbeat.ts`（零依赖：Node 内置 `fetch` + `crypto.randomUUID`）；
- 在 `server.ts` 启动序列末尾（各协程注册之后）调用 `startTelemetryHeartbeat()`，**不 await、不阻断启动**；
- 协程风格与 `startPatrolScheduler` 一致：定时器 `unref()`，不阻塞进程退出。

### 3.2 实例 ID 与本地状态

新建单行表 `app_telemetry`（`server/infra/schema.ts`，幂等 DDL）：

```sql
CREATE TABLE IF NOT EXISTS app_telemetry (
  instance_id   CHAR(36)     NOT NULL PRIMARY KEY,
  first_seen    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  last_report   DATETIME     NULL,
  report_count  INT          NOT NULL DEFAULT 0,
  last_version  VARCHAR(32)  NULL
)
```

- **以元数据库为粒度**：多实例（Nginx 双机）共享同一个库 → 一个部署只算一个实例，天然去重；
- 表空 → 生成 UUID v4 并 INSERT（本次事件为 `install`）；有记录 → UPDATE（`alive`）。

### 3.3 上报时机与内容

- 启动后 **15 秒**首次上报（避开初始化高峰），**每 24 小时**一次；每次重启立刻补发一次；
- 事件：`install`（该库首次上报）/ `alive`；
- 请求体（**字段白名单，全部匿名**）：

| 字段 | 说明 |
|------|------|
| `id` | 部署实例 UUID（随机生成，不含任何机器指纹） |
| `event` | `install` / `alive` |
| `version` | 应用版本（运行时读 `package.json`，失败降级 `unknown`；Docker 镜像已含该文件） |
| `os` / `arch` | `process.platform` / `process.arch` |
| `node` | Node 主版本（如 `v22`，截断 minors 减少指纹） |
| `docker` | 是否容器环境（`/.dockerenv` 存在性） |
| `count` | 本实例累计上报次数 |
| `firstSeen` / `ts` | 首次/本次上报时间（ISO） |

- **不采集清单**：IP（Worker 不落库）、主机名、用户名、路径、账号、表名、SQL、任何业务数据。

### 3.4 开关与容错

| 环境变量 | 行为 |
|----------|------|
| `TELEMETRY_DISABLED=1` | 完全关闭，启动日志 INFO 声明，不发任何请求 |
| `TELEMETRY_URL=<url>` | 覆盖内置端点（自建/测试用；置空同样等同关闭） |
| 默认（不配置） | 启用，指向内置 Worker 端点 |

- 请求超时 5s（`AbortSignal.timeout`）；失败**静默**（仅 debug 日志，不重试堆积、不影响任何功能）；
- 启动日志明示：`[Telemetry] 匿名部署统计已启用（仅上报版本/OS 等匿名信息，TELEMETRY_DISABLED=1 可关闭）`。

## 四、接收端设计（Cloudflare Worker）

### 4.1 端与职责

新增 `deploy/telemetry-worker/`（独立于主构建，不进主 `tsconfig` 门禁）：

| 端点 | 职责 |
|------|------|
| `POST /hb` | 校验 → KV 落库 → 首次发邮件；返回 204 |
| `GET /stats?token=` | 汇总查询：总实例数、版本分布、近 7 日活跃、实例列表（key metadata 免逐条读） |

KV 结构：`inst:<uuid>`（value=最近事件体，metadata=version/os/firstSeen/lastSeen）+ `meta:count`（总部署数）+ `meta:day:<date>`（当日新增计数，限量用）。

### 4.2 邮件通知（双路径，自动适配）

| 路径 | 条件 | 说明 |
|------|------|------|
| A. Cloudflare Email Service | 作者**有域名**且已 `wrangler email sending enable` | 原生 `send_email` binding，零第三方 |
| B. Resend API | 作者**无域名** | 免费 100 封/天；测试发件域名只能发给账号本人邮箱——恰好满足「只通知自己」（需注册提供 API key） |

- **仅 `install` 事件发邮件**（`alive` 只更新 KV），天然限流；附加每日邮件上限（20 封，超出仅落库）防刷；
- 邮件内容：`🎉 新部署：v0.9.73 (linux/x64)　实例 3f2a…c1，容器部署，09-24 15:30`。

### 4.3 防滥用

字段白名单 + 类型/长度/UUID 格式校验（body ≤ 1KB）；同 id 60 秒内重复上报忽略；每日新增实例上限 100（超出返回 429，仅接受已知 id 更新）；`/stats` 需 `STATS_TOKEN`（secret）。

### 4.4 部署方式

`wrangler.jsonc` + KV binding；部署步骤（含用户配合项）：`npx wrangler login`（浏览器授权一次）→ `wrangler kv namespace create` → 写入 secret（`STATS_TOKEN` / `NOTIFY_EMAIL` / 邮件凭据）→ `wrangler deploy`。产出 `deploy/telemetry-worker/README.md` 逐步指引。

## 五、隐私与合规

- **透明**：源码开源可审计；启动日志明示；README 增加「隐私与匿名统计」小节（采集字段、用途、关闭方法）；
- **最小化**：仅 9 个匿名字段，无任何可识别信息；IP 不落库（Workers 仅在请求瞬态可见，代码不做记录）；
- **可控**：`TELEMETRY_DISABLED=1` 一键关闭；`TELEMETRY_URL` 可改指自建端点；
- **无副作用**：上报失败静默，不影响部署者任何功能。

## 九、验收标准

1. 本机启动应用 → Worker 收到 `install`，**邮箱实收通知邮件**（证据留档）；
2. 同库再次启动 → `alive` 事件、KV 更新、**不重复发邮件**；
3. `TELEMETRY_DISABLED=1` 启动 → 本地日志声明关闭、Worker 零记录（实测）；
4. `GET /stats?token=` 返回正确聚合（总实例数/版本分布）；
5. 门禁全绿；文档同步完成；提交推送双远程。

## 十、风险与缓解

| 风险 | 缓解 |
|------|------|
| `workers.dev` 域名在国内可达性不稳定 → 部分部署者上报静默失败 | 可选绑定自定义域名（显著提升）；失败不影响部署者；`TELEMETRY_URL` 可自指自建端点 |
| Worker URL 公开在源码中，可能被恶意刷 | 严格校验 + 60s 去重 + 每日新增上限 + 邮件仅首次且日限 20 |
| 通知邮件进垃圾箱 | 走正规发信通道（域名 SPF/DKIM 或 Resend）；建议加入白名单 |
| KV 免费额度（1000 写/天） | 当前量级（≤500 活跃实例）远低于额度；超额仅丢失统计不影响功能 |
| 部署者隐私顾虑 | 匿名最小化 + 文档明示 + 一键关闭 + 开源可审计 |

## 十一、执行前置输入（需作者提供）

1. **Cloudflare 账号**（执行时 `npx wrangler login` 浏览器授权一次）；
2. **通知邮箱地址**（收件人）；
3. **邮件通道二选一**：无域名 → 注册 Resend（2 分钟）提供 API key；有域名 → 执行 `wrangler email sending enable`（零第三方）；
4. （可选）自定义域名用于绑定 Worker，提升国内上报稳定性。
