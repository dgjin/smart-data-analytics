## 一、判定"完整"的三个硬条件

AI 工程闭环（数据飞轮）不是"有模块、有代码"就算完整，必须同时满足以下三个条件：

1. **六环节链路真实接通、无断链**
   感知（`queryGuard` 注入检测 L1-L4）→ 生成（双阶段 + 四契约：澄清/拒答/自省/生成）→ 执行验证（SQL 三道防线 + 自纠错 + EXPLAIN 防线）→ 反馈采集（点赞/点踩/失败样本）→ 学习回注（人工审核 → Few-Shot 注入）→ 评估灰度（A/B + 评测门禁）。

2. **学习产物真实回流生效**
   反馈不能落空——失败样本经审核采纳后，必须真实进入样例库、并在后续相似问数中被检索命中。

3. **量化可证 + 灰度可控**
   每一次策略变更都能通过 A/B 数据或评测集证明有效后再全量上线（渐进式发布）。

> **关键教训（判定试金石）**：v0.9.44/45 曾实现"审核→注入"模块，但 **9 处断链未打通**（审核提交、示例入库、策略分支未接通），直到 v0.9.46 修复后才算真闭环——**"有模块"不等于"链路通"**。验收时必须以端到端数据链路生效为准，而非模块与单测存在。

## 二、项目现状核对（v0.9.47 时点）

| 环节 | 现状 | 判定 |
|------|------|:---:|
| 感知 → 执行验证 | `queryGuard` 注入检测 L1-L4、语义缓存、自纠错、EXPLAIN 防线、行级权限 AST 注入 | ✅ 完整 |
| 反馈采集 | 反馈飞轮（点赞沉淀/点踩反例/个人记忆）+ 失败样本自动采集（`adversarial_samples`）+ 审计十态 | ✅ 完整 |
| 学习回注 | Fallback 三层自救 + 人工审核队列 + Few-Shot 注入 + 主动学习排序（v0.9.46 打通 9 处断链） | ✅ 完整（**提示词/样例层**） |
| 评估灰度 | A/B 实验框架 + A/B Dashboard + CI 评测门禁 + 在线四率看板 | ✅ 完整（**策略层**） |

**结论**：评估报告所述的"闭环完整"，成立范围是**提示词层 + 策略层**。当前系统学习发生时只改 Prompt 与样例库，**模型权重本身不变**（in-context learning，非模型级学习）。

## 三、距"彻底完整"还差的三块（对应 Q4 规划）

| 缺口 | 现状 | 完整化所需条件 |
|------|------|---------------|
| **模型参数级学习（RLHF）** | 学习止步于 in-context，通用模型在金融统计域存在系统性偏差 | ≥5000 条高质量审核样本对（训练燃料）+ GPU 算力 + SFT/PPO 框架（DeepSpeed/Axolotl）+ A/B 扩展 Group C + 渐进发布（5%→100%） |
| **Few-Shot 自动生成** | 人工审核注入为主，自动生成覆盖率 **0%** | 双塔编码器 + SQL AST 编码器 + 自适应 Top-K 选择（目标覆盖率 ≥80%） |
| **Schema Linking 知识图谱** | 混合检索，无图谱、无实体消歧 | Neo4j/NebulaGraph + NER + 消歧澄清联动（目标准确率 ≥90%） |

## 四、操作路径（按依赖顺序）

### 第 0 步——前置条件（现在就能做，零成本）

- **持续运营审核队列**：入口为「系统管理 → AI 审核 → Fallback 困难样本审核」，管理员采纳/驳回积压困难样本，积累 `adversarial_samples` 数据。**样本量是 RLHF 的硬前提**，没有千级样本，Q4 训练无从谈起。
- **先修评测器口径**（评估报告 P2-8）：宽表集因 `maxRows=100` 截断导致结果集形态差异，`multi_dim` 33.3% / `time` 37.5% 分数虚低——**度量不准 = 评估环节是假闭环**，会误导后续所有优化方向。
- **评测集扩容**：当前 158 条（主集 104 + 宽表集 54）→ 目标 1000 条（Q4 验收标准）。

### 第 1 步——策略层巩固

- 等 A/B 数据积累到统计显著后做策略去留决策（Group A 规则式 vs Group B 人工审核 + 示例增强），用数据决定策略取舍。

### 第 2 步——Q4 三线落地（16 周）

- **RLHF 16 周四阶段**：数据准备（≥5K 样本对）→ Pipeline 设计与训练 → 模型服务化（GGUF 导出 + 渐进发布）→ 评估体系（≥1000 测试集 + 评审委员会），每阶段设里程碑验收。
- **Few-Shot 自动生成 8 周**：排序算法 → Prompt Builder → 知识图谱辅助与 UI 集成。
- **知识图谱 8 周**：图模式设计与导入 → 实体识别与链接 → 可视化与优化。

### 验收纪律（贯穿始终）

每项以**端到端链路测试**验收——"提问失败 → 审核采纳 → 入库 → 下次相似问题命中示例并一次成功"，而非"模块存在 + 单测通过"。v0.9.44/45 的 9 处断链就是"有模块但链路没通"的反面教材。

---

## 五、总结

> "提示词层闭环"已在 v0.9.46 完整交付并被 A/B 量化验证；要达成"彻底完整"，前置条件是**"用审核队列把样本攒到千级 + 修准评测口径"**，然后按 Q4 规划分三线推进模型层学习——每一步以**数据链路真实生效**为唯一验收标准。
