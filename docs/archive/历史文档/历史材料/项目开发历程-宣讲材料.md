# 智能问数分析系统 · 项目开发历程（宣讲材料）

> 本文档基于项目记忆与《系统功能说明书》变更记录（v0.1 → v0.4.7）梳理，用于内部宣讲。
> 一句话概括：**从一个 AI Studio 前端模板起步，7 天 27 个版本迭代，打造出一套面向不良资产经营分析的企业级 NL2SQL 智能问数系统——492 个自动化测试守护，双模型分工，真库真数，全程留痕。**

---

## 一、项目是什么

**定位**：让业务人员用一句自然语言直接查数、出图、得结论的智能数据分析系统。

**核心场景**：不良资产经营分析——基于 127 万行业务宽表 + 1139 万行财务宽表（月末快照、20 个报告期），支持「各机构本年投放金额排名」「长龄业务 TOP8」「同比增减变化」等真实业务问数。

**技术底座**：

| 层 | 选型 |
|----|------|
| 前端 | React + Vite + Tailwind v4 + Recharts |
| 后端 | Node.js + Express（Vite dev 中间件一体化） |
| AI 引擎 | 本地 Ollama 主引擎（qwen3.8:27b 生成 SQL + deepseek-r1:8b 数据解读双模型分工），可选通义千问百炼云端引擎 |
| 数据库 | MySQL（元数据库 smart_analytics + 业务库 analytics_test），兼容 PostgreSQL / Greenplum |
| 向量检索 | Ollama nomic-embed-text，JSON 落 MySQL + 应用层余弦相似度（轻量方案，无独立向量库） |

**三种角色**：ADMIN（全权）/ ANALYST（问数+沉淀）/ VIEWER（只读）。

## 二、开发历程：五个阶段

### 阶段 0 · 起点：模板与数据地基（8 月 12 日前后）

- 项目从 **Google AI Studio 本地运行模板**起步（Gemini API + Vite + Express 一体化骨架），具备 PDF 导出、Recharts 图表等基础能力。
- **数据地基先行**：创建 `analytics-test` 数据库用户与 `smart_analytics` 元数据库；将 Greenplum/PostgreSQL 语法的宽表 DDL 转译为 MySQL 后导入——业务宽表 94 列 / 财务宽表 204 列，`LOAD DATA` 灌入 **127 万行 + 1139 万行**真实口径数据。
- 这一步确立了后续一切迭代的验证基准：**真库真数，任何改动都能用真实业务问题回归验证。**

### 阶段 1 · v0.1：正名与引擎奠基（8 月 13 日）

- **系统正名**：由模板名改为「智能问数分析系统」，版本号归零重启为 NL2SQL Pro v0.1。
- **AI 引擎三连**：接入通义千问百炼（OpenAI 兼容协议 + AI_ENGINE 三引擎切换）→ 上线**用户自选模型**（模型目录接口 + 问数输入框下拉、请求级引擎切换、缓存键隔离）→ 主引擎正式切换。
- 踩坑沉淀：百炼 Coding Plan Key 禁止用于自建后端，改走标准按量 Key + 通用端点——**API Key 与端点严格配套**成为团队规范。

### 阶段 2 · v0.2 ~ v0.3：能力框架成型（8 月 13 日 ~ 14 日）

这是框架性建设最密集的两天：

- **v0.2 分析过程增强五项**：推导过程记录与可视化（query_trace 全链路留痕 + 时间线回放）、问数**计划模式**（先出计划、用户批准再执行）、中间表清洗链（ait_* 注册表 + TTL 清理）、报表计划模式、报告 PPT 下载。
- **v0.3 P0-P2 企业级优化**（借鉴 DB-GPT 工程化落地）：
  - NL2SQL 评测集 + 评测运行器（16 用例基准）；
  - StateStore 抽象 + Redis 外置；语义指标层（权威口径固化）；
  - 行级权限（scope.rowFilters AST 强制注入）；报表图表点击下钻；
  - **知识库 RAG**（切块 + embedding + 向量/词法混合检索注入 prompt）、**SQL 自纠错**（多候选择优投票）、**few-shot 双维度评分**（问题相似度 × 表重叠度）、**技能库插件系统**；
  - 图表能力扩展至 scatter / treemap / heatmap 共 9 种；浅色主题切换上线。
- 同期落地：**宽表元数据 Excel 批量导入知识库**（8 个 sheet 约 670 行 → 8 篇文档 326 块），让模型「懂」宽表口径；**系统帮助功能**上线——《系统功能说明书》作为单一事实源，帮助入口实时读取，确立「功能变更必同步说明书」的维护约定。
- v0.3.1~v0.3.10 连续打磨：展示字段全面中文化、知识库面向 NL2SQL 优化（口径/指南文档 + 8 个语义指标）、**数据库索引优化**（长龄机构查询 4×、最新快照聚合 20×+ 提速）、技能库重构为不良资产 8 大专业场景、看板默认内容换成真实数据 5 图、**问数性能优化**（同题 105s→68s：复杂度预门控、上下文并行化、embedding 短 TTL 缓存、快速模型路由、Ollama keep_alive）。

### 阶段 3 · v0.4.0 ~ v0.4.1：体验与生态扩展（8 月 15 日 ~ 16 日）

- **v0.4.0 对话历史与自主学习**：对话服务端落库（跨设备共享）、历史面板（搜索/重问/删除）+ Markdown 导出；自主学习双通道——本人成功问答自动沉淀为个人 few-shot，负反馈进反面教材库。
- **v0.3.9/v0.3.10** 对话按数据源隔离（盖源戳防串源）、血缘视图悬停叠层修复。
- **v0.4.1 外部知识库接入**：POST 检索协议 + Bearer 认证、API Key AES-256-GCM 加密落库、四容器响应容错解析——知识库从「内置」走向「可接入企业既有知识平台」。
- 同期支持 **Greenplum 全链路**（pg 协议双引擎连接池、方言感知 SQL 校验与 prompt、PG schema 提取），数据源矩阵扩展为 MySQL / PostgreSQL / Greenplum。

### 阶段 4 · v0.4.2 ~ v0.4.7：口径治理与交互打磨（8 月 17 日 ~ 18 日）

进入「真实业务口径深水区」，每个版本都在解决真问题：

- **v0.4.2 图表同/环比维度错配修复**：新增时间序列轴判定（格式解析 + 单调性校验），只有真时间轴才启用同环比——消灭「把前一机构当历史基线」的伪数据。
- **v0.4.3 快照表跨期重复累计修复**：「本年投放 2318 亿误算 39204 亿（虚大 17 倍）」事故——根因是语义指标 filters 缺报告期锁定，且「权威口径禁止变更」指令压制了知识库正确规则；配置层修复 8 个指标 + 4 个知识块，**不改一行代码**。
- **v0.4.4 SQL 白名单误拒修复 + 双模型分工**：同比类子查询 SQL 被正则防线误判（逗号分表误吞聚合函数名）；修正后确立 **qwen3.8:27b 生成 SQL + deepseek-r1:8b 解读**的双模型路由，生成提速一倍。
- **v0.4.5 金额单位自选**：亿元/百万元/万元/元随提问生效，白名单校验 + 单位进缓存键防口径互串；小数默认两位 + 全展示层千分位统一。
- **v0.4.6 解读失败规则化降级**：LLM 解读异常不再输出「使用兜底文案」空壳，`buildFallbackAnalysis` 基于真实列统计生成有信息量的降级解读，trace 标注「规则降级」可追溯。
- **v0.4.7 拒答契约**：无关问题/超出能力不再用演示数据托底，阶段一契约扩展第四种输出如实反馈，审计与对话历史以 REFUSED 留痕（含存量表 ENUM 迁移）。

## 四、沉淀的关键经验（宣讲亮点）

1. **真库真数是质量底线**：从第一天就用真实宽表数据验证，任何「看似正确」的口径错误（17 倍虚增、维度错配同环比）都逃不过与手工 SQL 的比对。
2. **配置层优先于代码层**：报告期锁定、口径固化等问题通过语义指标与知识库配置修复，不动核心代码、不引入回归风险。
3. **全链路留痕**：query_trace 推导回放、审计日志八态（含 CLARIFY/REFUSED）、对话历史落库——每个结论都可追溯、可复盘。
4. **优雅降级是一等公民**：LLM 失败 → 规则化解读；embedding 缺失 → bigram 词法检索；执行失败 → 显式标记演示数据——**降级不撒谎**（v0.4.7 拒答契约是这一原则的终点）。
5. **文档即产品**：《系统功能说明书》单一事实源 + 系统内帮助入口实时读取，每次变更同步更新，文档永不失真。
6. **安全纵深防御**：SELECT-only 白名单 + AST 双校验、行级权限强制注入、敏感列剔除、API Key 加密落库、注入检测——问数直达生产库也能放心。
