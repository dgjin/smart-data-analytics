## 四、Import 重写与踩坑记录

重写总量约 **200 处**，覆盖四种引用形态：

| 形态 | 示例 | 说明 |
|------|------|------|
| 静态 import | `from './db'` → `from './infra/db'` | 覆盖根层、routes/eval/llm/knowledge/auth/infra、server.ts 入口、scripts/ |
| vi.mock 路径 | `vi.mock('./db')` → `vi.mock('../infra/db')` | 与静态 import 同步改，mock 路径与被测模块 import 路径必须一致 |
| 动态 import() | `await import('../sqlExecutor')` → `'../query/sqlExecutor'` | eval/loadTest 等按需加载处 |
| 路径字符串 | check-stateless.ts 中 `{ file: 'server/db.ts' }` 登记项 | 状态残留检查脚本的文件定位 |

**踩坑与修复**（供后续批次/项目参考）：

1. **vi.mock 漏改**：第一批 sed 只替换 `from '...'` 形态，`vi.mock('...')` 未覆盖 → 42 个测试失败（mock 未生效打到真实模块）。教训：残留检查必须同时扫两种形态
2. **zsh for 循环不分词**：`for m in $VAR` 在 zsh 中不做词分割，整串匹配失败且 sed 静默无效果。教训：批量替换改用逐词列举
3. **动态 import() 漏网**：第二批 `oidc.test.ts`、`loadTest.ts` 的 `await import('./stateStore')` 残留，tsc 阶段捕获。教训：残留全扫增加第三种形态
4. **测试文件漏移**：`userQueryLimit.test.ts` 首批未随源文件走。教训：git mv 时源与测试成对核对
5. **静态/vi.mock 双轨**：`liveReportExec.test.ts` 中 vi.mock 已改但顶部静态 import 漏改，tsc 捕获

**文档同步**：`docs/DEPLOYMENT.md`（server/db.ts 路径引用）、`scripts/check-stateless.ts`（约 15 处文件登记路径）。

## 五、依赖方向约束

