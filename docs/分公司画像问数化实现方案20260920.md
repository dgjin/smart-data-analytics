## 一、背景与目标

### 1.1 业务目标

分公司财务画像目前依赖**人工从各部门搜集数据、手工制表**（模版原文明确记载）。目标是通过问数能力实现：

1. **快速提取** — 输入分公司名称，自动完成 9 张表的取数
2. **自动分析** — 同比、结构占比、全辖排名、规模收益匹配度等自动计算与解读
3. **完整报告** — 一键生成结构化画像报告（在线看板 / PPT / PDF / Excel）

### 1.2 模版结构（9 张表 → 4 大部分）

| 模版部分 | 对应 xlsx 工作表 | 核心内容 |
|---|---|---|
| 一、各类任务完成情况 | `经营目标总体完成情况ok` | 主业收入/投放/回现/存量去化/红档去化/风险化解，含同类排名、全辖排名、贡献占比、预算完成率、同比 |
| 二、时间序列分析 | `长周期分析-成本、损益ok`、`长周期分析-处置类4-4成本覆盖率进度表`、`长周期分析-处置类5-5各会计年度收益率情况表` | 自 21 年以来的规模/收入/收益率/成本/拨备/覆盖率 |
| 三、横截面分析 | `当年分析--业务总体情况`、`当年分析--业务总体收益ok`、`当年分析--各业务板块`、`风险情况` | 年初 vs 月末、本年变动、按账龄/风险/业务分类的结构 |
| 四、新老特分析 | `新老特ok` | 按老业务/新业务/特殊业务拆分的规模、收益、收益率 |

模版声明数据源：**全量资产清单、处置类指标体系**。

### 2.4 三个硬缺口

#### ① 口径对不上账（最关键，已实测）

模版「当年分析-业务总体情况」的成本口径：

| 分类 | 模版值（亿元） | 占比 |
|---|---|---|
| 处置类 | 81.99 | 0.4762 |
| 固收类 | 84.48 | 0.4906 |
| 权益类 | 3.01 | 0.0175 |
| 抵债资产 | 0.25 | 0.0014 |
| 其他 | 2.45 | 0.0142 |
| **合计** | **172.18** | 1 |

**实测过程**（按「锁快照期 + 锁核算版 + 按 `cate4_id` 汇总」全库全快照搜索）：

```sql
SELECT segment1_desc, data_dt, data_version,
  ROUND(SUM(CASE WHEN cate4_id='1.1处置类' THEN cbye END)/1e8,2) AS 处置,
  ROUND(SUM(CASE WHEN cate4_id='1.2固收'   THEN cbye END)/1e8,2) AS 固收,
  ROUND(SUM(CASE WHEN cate4_id='1.3权益类' THEN cbye END)/1e8,2) AS 权益,
  ROUND(SUM(CASE WHEN cate4_id='1.4抵债资产' THEN cbye END)/1e8,2) AS 抵债
FROM fct_jc_financial_stat
GROUP BY segment1_desc, data_dt, data_version
HAVING 处置 BETWEEN 80 AND 84 AND 固收 BETWEEN 83 AND 86;
-- 结果：空（无任何机构在任何快照/版本上匹配）
```

最接近的是**黑龙江省分公司**（合计 171.8 亿），但其分类分解为
`处置 102.24 / 固收 31.79 / 权益 19.94 / 抵债 16.45 / 其他 7.83`，与模版**完全不吻合**。

**另一处矛盾**：模版同一张 sheet 内并存两个合计口径——
「各类业务成本余额（本年变动及新老情况）」合计 **292.91 亿**，
「各类业务成本、拨备、账面价值情况」合计 **172.18 亿**。
两者范围显然不同（前者含老四类等），说明模版口径本身需要业务方澄清。

> **判定**：模版数据**不等于**现有宽表口径。须先确认模版真实取数范围（是否仅主营 / 母公司本部 / 特定项目集）。

#### ② 历史深度不足

| 项 | 现状 | 模版要求 | 缺口 |

| 财务宽表快照 | 2025-01-31 ~ 2026-08-31（21 个月） | 自 2020/2021 年以来 | 约 4 年 |
| 业务宽表快照 | 2025-01-31 ~ 2026-08-31（20 个月） | 同上 | 约 4 年 |

→ **长周期分析（模版第二、四部分）在补齐历史前无法完成。**

#### ③ 风险维度缺失

| 维度 | 模版要求 | 宽表覆盖 |
|---|---|---|
| 五级分类（正常/关注/次级/可疑/损失） | 固收专项、风险情况 | ❌ 未覆盖 |
| 中投三分类 | 处置类、固收 | ❌ 未覆盖 |

## 三、总体思路：三层递进，不靠模型「现编」

```
第 1 层  口径资产化
         把 9 张表的取数逻辑固化为「指标库 + SQL 样例库 + 铁律红线」
         模型只负责翻译，不负责编口径
              ↓
第 2 层  问数取数
         把 9 张表拆成章节级问数模板，逐节取数并校验
         每节产出：结构化结果 + 生成 SQL + 审计留痕
              ↓
第 3 层  报告组装
         报表模板 + 报告模式 → 一键拼装完整画像报告（在线 / PPT / PDF / Excel）
```

### 为什么不做「一句话生成整篇画像」

画像含 9 张表、上百个指标、多层嵌套口径（快照期 × 核算版 × 业务分类 × 风险维度）。一次性生成必然在**快照期 / 核算版 / 去重**三处出错。

本项目的 `39204 亿口径偏差事故`（金额虚增近 17 倍）根因正是：快照型宽表跨期累加 + 未锁定核算版 + 未按业务编号去重。

**必须分节取数、节节可验。**

## 五、关键技术设计

### 5.1 铁律红线（防错核心）

画像取数的标准骨架，**四项约束缺一不可**：

```sql
WITH snap AS (SELECT MAX(data_dt) AS dt FROM fct_jc_financial_stat)
SELECT t.segment1_desc AS 机构,
       t.cate4_id       AS 分类,
       ROUND(SUM(t.cbye)/1e8, 2) AS 成本余额_亿元
FROM fct_jc_financial_stat t, snap
WHERE t.data_dt = snap.dt          -- ① 锁快照期：防跨期累加（缺 → 金额虚增十余倍）
  AND t.data_version = 2           -- ② 锁核算版：防多核算版重复
  AND t.segment1_desc = ?          -- ③ 机构入参
GROUP BY t.segment1_desc, t.cate4_id;
-- ④ 分成版去重：按 XMBH + YWBH 取一行（模版注明「同一业务对应多行数据」）
```

| # | 红线 | 不遵守的后果 |
|---|---|---|
| ① | 必须锁 `data_dt = MAX(data_dt)` | 跨期快照累加 → 金额虚增（39204 亿事故根因） |
| ② | 必须锁 `data_version` | 多核算版数据重复计入 |
| ③ | 机构口径必须显式指定 | 混入全辖数据 |
| ④ | 分成版按 `XMBH + YWBH` 去重 | 同一业务重复计数 |
| ⑤ | 分类必须走 `cate4_id`（经营分析报告分类） | 用 `cate1~3` 会导致分类结构与模版不符 |

### 5.2 分章节取数策略

- **每节独立问数**，产出结构化结果并落库，便于逐节复核与重跑
- **节间勾稽**：如「合计 = 各分类之和」「年末 = 年初 + 投放 − 减少 + 其他变动」
- **数值容差**：`max(0.005, 相对 1e-9)`，吸收 `ROUND(x,2)` 造成的假阴性（沿用现有评测口径）

### 5.3 报告组装

复用现有能力，无需新建链路：
- 「可视化决策报表」→ section 编排
- 「报告模式」→ 计划模式（批准后生成）
- 导出 → PPT（pptxgenjs）/ PDF / Excel（exceljs）/ Word（docx）
