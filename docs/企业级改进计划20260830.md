# 智能问数分析系统 · 企业级改进计划

> 制定日期：2026-08-30
> 基线版本：NL2SQL Pro v0.8.8（git HEAD `ee3e46a`）
> 输入来源：《企业级评估报告 20260830》（红灯问题 R1-R7 + 优化建议 P0-P3）+ 扩展性专项建议（9 项）
> 使用方式：按阶段顺序执行，**每项完成须满足验收标准并通过全量回归（tsc 三档 + vitest + docs:check）后才进入下一项**；完成后在状态列打勾并记录提交哈希

---

## 一、目标与原则

**总目标**：三个月内将系统从"准生产级"推进到"企业级可交付"——门禁常绿、流程不可绕过、水平扩容就绪、准确率在线可度量。

**执行原则**：
1. **先止血后建设**：门禁绿灯（Phase 0）不完成，不启动任何新功能开发；
2. **不引入新中间件**：优先复用 MySQL / 已有 ioredis / GitHub Actions，保持"单机零依赖、配置即扩展"风格；
3. **每步可验证**：每项都有明确验收标准，改动后跑全量回归再前进；
4. **文档同步红线**：每项完成同步《系统功能说明书》变更记录，**记录数据必须与实测一致**（吸取 R6 教训）。

## Phase 2 · 扩展性核心（2-4 周）

> 来源：扩展性专项建议 #1-#5。按投入产出比排序：队列化 > LLM 多后端 > 状态巡检 > 连接池分级 > SSE 续传。

| # | 任务 | 实施要点 | 验收标准 | 状态 |
|---|------|----------|----------|:---:|
| 2-1 | 长任务队列化 | 深度分析链/报告生成/PDF 导出改异步：MySQL 任务表（`status` + worker 心跳，不引入 MQ），提交即返回 taskId，前端轮询或 SSE 订阅进度；worker 与交互问数隔离 | 分钟级任务运行中交互问数 P95 不劣化；实例重启后任务可恢复/标失败不丢失 | ☐ |
| 2-2 | LLM 多后端路由 | `llmClient` 支持同引擎多后端（`OLLAMA_URLS=host1,host2`），最少并发路由 + 健康检查剔除坏节点；embedding 调用批量化（知识库导入/列裁剪场景一次请求多段文本） | 双后端压测吞吐接近线性；单后端宕机自动摘除、问数不中断；知识库导入 embedding 往返次数下降 ≥50% | ☐ |
| 2-3 | 进程内状态巡检 | ① `scripts/check-stateless.ts`：扫描 `new Map` 对照白名单，纳入 CI；② schemaLinking 表/列 embedding 缓存 key 加 schema 版本号（防数据源编辑后旧向量残留）；多实例部署文档明确标注哪些缓存是"本地加速层" | CI 能拦截白名单外的新增进程内状态；编辑数据源 schema 后 embedding 缓存自动失效 | ☐ |
| 2-4 | 连接池分级 | 交互问数/清洗链/导出独立连接池配额（如 10/5/2）；按场景设 `MAX_EXECUTION_TIME`（交互 15s / 分析链 120s） | 大导出占满自身配额时交互问数不排队（并发实测） | ☐ |
| 2-5 | SSE 会话韧性 | 支持 `Last-Event-ID` 断线续传：重连按 traceId 回放已完成阶段；部署指南补充网关配置（粘性会话 / `proxy_buffering off`） | 流式过程中断网重连，已完成阶段即时回放、不重新执行 SQL | ☐ |

## Phase 4 · 战略演进（按需排期）

> 来源：评估报告 P3 + 扩展性建议 #6-#9。启动前逐项立项评审。

| # | 任务 | 价值 | 触发条件 |
|---|------|------|----------|
| 4-1 | 数据源方言适配器 | 抽 `DialectAdapter` 接口（extractSchema/quoteIdent/validateSql/testConnection），MySQL/Greenplum 各一实现；新库（Oracle/ClickHouse/达梦）适配成本从全链路改造降为加一个文件 | 出现第三种数据库接入需求（国产化场景可预期，建议提前做） |
| 4-2 | MCP Server 工具化 | 问数引擎封装为 MCP Server 暴露 query/clarify/schema 工具，供公司统一 AI 平台或其他 Agent 调用——从"应用"升级为"能力底座"，扩展性投入产出比最高 | 公司 AI 平台对接启动时 |
| 4-3 | 配置热更新 | 限流阈值/模型路由/缓存 TTL 从环境变量迁到 DB 配置表 + 30s 轮询（或 Redis pub/sub），多实例同时生效免滚动重启 | 多实例部署上线后 |
| 4-4 | 读写分离预留 | `sqlExecutor` 加 `readReplica` 配置位（有则只读查询路由过去），改动极小 | 业务库出现读压力信号时 |
| 4-5 | 多实例 Redis 化落地 | 生产部署启用 `REDIS_URL`（StateStore/queryCache 已支持），压测验证多实例缓存共享与限流一致性 | 单实例容量达到压测报告阈值 70% 时 |
| 4-6 | 架构演进预研 | 单体拆分评估（问数引擎 vs 管理面）、多 Agent 编排预研（与参赛演进路线对齐） | 团队规模/需求复杂度显著增长时 |

## 四、风险与依赖
