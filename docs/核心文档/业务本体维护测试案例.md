# 业务本体维护测试案例

> 适用版本：v0.9.113（业务本体易用性优化 + 智能预填 + 全局开关）
> 测试对象：系统管理 → 规则治理 → 业务本体（实体与绑定 / 值域释义 / 关联路径 / 业务层级 + 版本历史 + 智能预填 + 本体注入开关）
> 对应实现：`src/components/admin/OntologyPanel.tsx`、`src/components/admin/OntologyAutoBuildModal.tsx`、`src/components/admin/ontologyUi.tsx`、`server/routes/ontology.ts`、`server/query/ontology.ts`、`server/query/ontologyAutoBuild.ts`、`server/query/ontologyConfig.ts`
> 自动化用例：`src/components/admin/OntologyPanel.test.tsx`、`server/routes/ontology.test.ts`、`server/query/ontology.test.ts`、`server/query/ontologyAutoBuild.test.ts`

本案例集同时用于**手工验收**与**自动化回归**。每条用例给出前置条件、操作步骤与可判定的预期结果；标注「自动化」的用例已在仓库内落地，可直接用命令回归。

## 1. 测试目标与范围

### 1.1 测试目标

1. 四类本体资产（实体与绑定、值域释义、关联路径、业务层级）可被管理员完整维护：新增、编辑、停用 / 启用、删除、检索。
2. 维护过程顺畅：不丢未保存改动、不因逐字输入反复请求、不因手输表列名频繁出错。
3. 治理语义正确：创建即 ACTIVE、写操作 version + 1 留快照、支持回滚、停用不删除数据。
4. 注入边界清晰：本体只影响问数圈表加权与提示词，不改变执行层 Schema 白名单与权限。
5. 权限正确：普通分析师只读，写接口一律 403。

### 1.2 不在本次范围

- 智能预填之外的自动推理（如 LLM 辅助抽取、跨库语义对齐、本体漂移自动修复，均未上线）。
- 血缘图「关联路径」边的渲染（v0.9.110 已覆盖，本轮回归只做冒烟）。
- 值域释义大规模导入脚本（单次上限 200 条，超出请分批）。

## 2. 环境与准备

### 2.1 账号

| 角色 | 用途 | 期望权限 |
| --- | --- | --- |
| ADMIN | 全部维护操作 | 读 + 写 |
| ANALYST | 只读校验 | 仅读，写接口 403 |

### 2.2 数据源与表结构

准备一个可用数据源（下文以 `ds_test` 代称），并确保 Schema 至少包含：

| 表名 | 列名 | 说明 |
| --- | --- | --- |
| `JGXX` | `JGMC`、`BB` | 机构信息：机构名称、报表期间 |
| `ZCXX` | `ZCBH`、`JGMC` | 资产信息：资产编号、归属机构 |
| `XMXX` | `XMBH`、`JGMC`、`XMZT` | 项目信息：项目编号、归属机构、项目状态 |

同时准备一张**不在 Schema 中**的表名（如 `NOT_IN_SCHEMA`）用于「未命中联想」用例。

### 2.3 进入入口

使用 ADMIN 登录 → 左侧「系统管理」→「规则治理」→ 顶部页签「业务本体」→ 选择数据源 `ds_test`。

### 2.4 数据清理（每轮回归前）

1. 在四个页签中逐条删除测试期间创建的资产（删除会保留快照，属预期）。
2. 或在测试库执行 `DELETE FROM ontology_bindings / ontology_value_notes / ontology_relations / ontology_hierarchies / ontology_entities / ontology_versions WHERE data_source_id = 'ds_test';`
3. 刷新页面，确认概览五个计数均为 0。

## 4. 详细用例

### 4.1 入口与权限

#### TC-ONT-001 分析师只读、写操作被拒（P0，自动化）

- **前置**：ANALYST 账号可登录；`ds_test` 已接入。
- **步骤**：
  1. 以 ANALYST 登录并进入业务本体面板；
  2. 依次查看四个页签；
  3. 使用接口工具以 ANALYST Token 调用任一写接口（如 `POST /api/ontology/entities`、`POST /api/ontology/value-notes/bulk`、`POST /api/ontology/hierarchies`、`GET /api/ontology/entities/1/versions`）。
- **预期**：
  - 面板可正常展示四类资产，无写操作入口或写操作被拒；
  - 写接口与版本接口均返回 `403`；
  - 读接口（列表 / 概览 / 最短路）返回 `200`。

#### TC-ONT-002 概览计数卡展示与跳转（P1，自动化）

- **前置**：`ds_test` 下已有至少 1 个实体、1 条绑定、1 条值域、1 条层级。
- **步骤**：进入面板，观察顶部五张计数卡；依次点击「业务实体」「值域释义」「关联路径」「业务层级」。
- **预期**：
  - 计数只统计 ACTIVE 资产，与各页签列表的 ACTIVE 条数一致；
  - 点击卡片直接切到对应页签，当前页签卡片有青色高亮边框；
  - 「表列绑定」卡片不可点击，悬停提示「在『实体与绑定』中按实体维护」。

### 4.2 实体与绑定

#### TC-ONT-003 新建实体并自动生效（P0，自动化）

- **前置**：`ds_test` 下无同名实体。
- **步骤**：点击「新建实体」→ 填写名称「机构」、类型「主体」、别名「机构名称、JGMC」、说明「机构主数据」→ 提交。
- **预期**：
  - 提示「实体『机构』已创建并生效」；
  - 列表出现该实体，状态「生效中」，版本 `v1`，绑定 0 条；
  - 概览「业务实体」+1；
  - 服务端写入 `ontology_versions`（action=CREATE）。

#### TC-ONT-004 名称重复被拒（P0，自动化）

- **前置**：已存在实体「机构」。
- **步骤**：再次创建同名实体。
- **预期**：接口返回 `409`，页面显示服务端错误文案，列表不新增。

#### TC-ONT-005 关键字检索（P1，自动化）

- **前置**：列表含「机构」与「客户」两个实体，「机构」绑定 `JGXX.JGMC`。
- **步骤**：在搜索框依次输入「机构」「JGMC」「客户」。
- **预期**：
  - 输入「机构」只显示「机构」；
  - 输入「JGMC」命中其绑定表列，仍只显示「机构」；
  - 输入「客户」只显示「客户」；
  - 计数提示「共 N 个 · 已绑定 X 个 · 当前显示 Y 个」实时变化。

#### TC-ONT-006 仅看未绑定（P1，自动化）

- **步骤**：清空搜索 → 勾选「仅看未绑定」。
- **预期**：只显示绑定数为 0 的实体；取消勾选恢复全部。

#### TC-ONT-007 绑定整组保存与脏标记（P0，自动化）

- **前置**：「机构」已有 1 条绑定 `JGXX.JGMC（标识）`。
- **步骤**：
  1. 点击「维护绑定」，观察徽标；
  2. 点击「添加绑定」，填入表 `ZCXX`、列 `JGMC`、角色「关联键」；
  3. 点击「保存绑定」。
- **预期**：
  - 展开时显示「与库内一致」，保存按钮显示「已保存」且禁用；
  - 任意编辑后徽标变为「有未保存改动」，按钮变为「保存绑定」且可点击；
  - 保存调用 `PUT /api/ontology/entities/:id/bindings`，成功后徽标回到「与库内一致」；
  - 「重置」可恢复为库内内容并清除脏标记。

#### TC-ONT-008 切换实体时未保存改动确认（P1，手工）

- **步骤**：展开「机构」并修改绑定（不保存）→ 点击「客户」的「维护绑定」→ 在确认框中分别选择取消与确定。
- **预期**：取消则保持原实体与草稿；确定则切到新实体，草稿丢弃、脏标记清除。收起当前实体时同样二次确认。

#### TC-ONT-009 表/列联想与未命中提示（P1，手工）

- **步骤**：
  1. 在绑定表名输入框聚焦，观察下拉建议；
  2. 输入 `NOT_IN_SCHEMA`；
  3. 表名填 `JGXX`，在列名输入框聚焦并输入 `NOPE`。
- **预期**：
  - 下拉出现当前数据源的表名 / 对应表的列名；
  - 未命中时输入框右侧出现黄色警示图标与「未在当前数据源 Schema 中找到该表 / 未在该表结构中找到该列」；
  - 仅提示、不阻断保存（登记库外表仍可保存）。

#### TC-ONT-010 Enter 新增行、Ctrl/Cmd+Enter 保存（P2，手工）

- **步骤**：在最后一行的列名输入框按 `Enter`；随后在绑定区域按 `Ctrl+Enter`（macOS `Cmd+Enter`）。
- **预期**：Enter 立即追加一条空绑定行；组合键触发整组保存。

#### TC-ONT-011 停用 / 启用实体（P0，自动化）

- **前置**：「机构」为 ACTIVE，绑定 1 条。
- **步骤**：点击行内「停用」图标按钮；再点击「启用」。
- **预期**：
  - 停用后状态徽标变「已停用」，行透明度降低，概览「业务实体」−1，绑定数据保留；
  - 启用后恢复「生效中」，概览 +1；
  - 两次操作均 `PUT` 全量字段 + `status`，版本 +1 并留快照。

#### TC-ONT-012 加载 / 空 / 无匹配三态（P2，手工）

- **步骤**：刷新页面观察加载态；删除全部实体观察空态；输入不存在的关键字观察无匹配态。
- **预期**：分别为「加载中…」「该数据源暂无业务实体…」「没有匹配的实体（共 N 个）+ 清除筛选」；点击「清除筛选」同时清空关键字与「仅看未绑定」。

### 4.3 值域释义

#### TC-ONT-013 单条新增与同键覆盖（P0，自动化）

- **步骤**：表 `JGXX`、列 `BB`、值 `1`、含义「本期」→ 提交；再次提交同键、含义改为「本期（修正）」。
- **预期**：首次新增成功；第二次更新同一条记录（按 `数据源+表+列+值` 唯一键），列表只有一条且含义为「本期（修正）」。

#### TC-ONT-014 批量粘贴多种分隔符解析（P1，自动化）

- **步骤**：在批量框输入：

  ```text
  1=本期
  2＝上期
  9	其他
  非法行
  ```

- **预期**：预览显示「将写入 3 条 · 1 行无法解析」；支持 `=`、全角 `＝`、Tab（Excel 两列）、中文冒号与单逗号。

#### TC-ONT-015 批量去重（后者覆盖）（P1，手工）

- **步骤**：输入 `1=本期` 与 `1=本期（改）` 两行。
- **预期**：预览为「将写入 1 条 · 重复 1 条按后者覆盖」；保存后列表只保留「本期（改）」。

#### TC-ONT-016 批量单请求写入与失败明细（P0，自动化）

- **前置**：表列已填写 `JGXX.BB`。
- **步骤**：提交 3 条（其中 1 条缺值编码）。
- **预期**：
  - 只发起 1 次 `POST /api/ontology/value-notes/bulk`；
  - 返回 `saved=2、failed=1、failures[0].error` 含「值编码」；
  - 页面提示「成功 2 条，失败 1 条（原因）」；成功条数 > 0 时清空输入并刷新列表。

#### TC-ONT-017 批量上限 200 条（P1，自动化）

- **步骤**：粘贴 201 条有效行。
- **预期**：前端提示「单次最多批量保存 200 条，请分批粘贴」且不发请求；直接调用接口返回 `400`。

#### TC-ONT-018 客户端检索 / 表列筛选（P1，手工）

- **步骤**：在搜索框输入值或含义；再填写「按表名筛选」「按列名筛选」。
- **预期**：均为客户端即时过滤，不触发新请求；清空后恢复全量。

#### TC-ONT-019 编辑含义与状态（P1，手工）

- **步骤**：点击「编辑」→ 修改含义 → 将状态下拉改为「已停用」→ 保存。

### 4.4 关联路径

#### TC-ONT-021 新建含多列关联（P0，自动化）

## 7. 风险与注意事项

1. **批量写入是逐条 upsert**：200 条为单次上限，超大字典请分批；失败明细只回传前 20 条，其余以计数呈现。
2. **停用 ≠ 删除**：停用只退出注入与计数，数据与绑定保留；删除会连带删除实体绑定并保留 DELETE 快照。
3. **表列未命中只提示**：允许登记库外表（为后续接入预留），但执行期不会命中；验收时以 Schema 内表为准。
4. **版本回滚只作用于治理元数据**：不改执行层 Schema，也不回滚已生成 SQL 与历史问数结果。
5. **并发编辑**：同一资产被两人同时保存时按后写覆盖（version + 1），需要时通过版本历史回滚。
6. **注入优先级**：铁律 > 语义指标 > 业务本体 > 业务口径 > 知识库；本体不覆盖铁律与指标口径。
7. **智能预填只是规则推断**：实体与绑定按「编号-名称列对 / 表主题」推断，关联路径按「跨表同名列 + 行数大小」推断 `N:1 LEFT`，都是**建议而非事实**——应用后务必复核关联路径、日期关联键与实体类型；文本型分类列的合法取值仍以 Schema 列说明为准（智能预填不重复登记）。默认 `overwrite=false`，不会覆盖人工维护内容。
