# 业务本体实施顺序（业务人员版）

> 适用版本：v0.9.118　适用对象：业务负责人、数据分析师、实施顾问
> 本文只回答三件事：**先登记什么、后登记什么、每步做到什么程度算完成**。
> 字段规则、注入预算、排障细节见《[业务本体功能与操作手册](./业务本体功能与操作手册.md)》。

---

## 一、先理解一件事

业务本体 = 给系统补一份「业务词典 + 取数地图」。它登记四类东西：

| 登记什么 | 解决的问题 | 一句话判断标准 |
|---|---|---|
| **业务实体 + 表列绑定** | 「机构」到底查哪张表哪个列 | 用户说的词，能对上物理表 |
| **值域释义** | `BB=1` 是什么、`SF` 怎么过滤 | 代码和含义不同形，才需要登记 |
| **关联路径** | 两张表按什么列 JOIN | 只能登记**验证过**的真实关联 |
| **业务层级** | 「集团 → 分公司 → 项目」怎么下钻 | 由粗到细，列名真实存在 |

关键前提：**本体是增强项，不是开关式改造**。登记错了最坏是提示不准，不会越权；随时可一键关闭回退。

## 二、实施顺序总表（建议 1 周内完成首轮）

| 顺序 | 做什么 | 为什么排这个位置 | 完成标志 | 耗时 |
|---|---|---|---|---|
| **0** | 选场景、圈表 | 没有目标场景就会堆砌无关资产，稀释注入预算 | 写下 3~5 个高频问题 + 涉及的表 | 0.5 天 |
| **1** | 智能预填（只预览） | 用机器把「从零登记」变成「审草案」 | 拿到草案与「未自动生成的项」清单 | 0.5 小时 |
| **2** | 核心实体 + 绑定（1~3 个） | 没有绑定，实体命中也不会加权任何表 | 每个实体有「1 标识 + 1 关联键」 | 0.5 天 |
| **3** | 高频值域 | 枚举错是最常见的口径错位来源 | 代码≠含义的列已覆盖 | 0.5 天 |
| **4** | 关键关联路径 | 多表 JOIN 臆造只能靠登记消除 | 高频两表之间有 1 条验证过的路径 | 0.5 天 |
| **5** | 1 个主层级 | 层级只影响分组顺序，属锦上添花 | 由粗到细 ≥2 级且列名真实存在 | 0.5 小时 |
| **6** | 验证 → 小步放量 | 一次全量上线无法判断收益与副作用 | trace 三数正常，A/B 无退化 | 持续 |

**排序原则**：先「能命中」（0→2），再「不报错」（3→4），最后「更好看」（5）。**实体与绑定是地基，不做这一步，后面三类资产都不会被命中。**

---

## 三、每一步的具体做法

### 第 0 步：选场景（最重要，别跳过）

1. 找业务方列 **3~5 个每月必问**的问题，例如「各机构客户数」「本期营收按条线」「按集团汇总项目数」；
2. 每个问题标出**正确答案依赖哪张表、哪个编码、哪条 JOIN**；
3. 只保留「模型现在经常答错」的问题作为首批目标。

产出：一张「问题 → 表 → 关键列」清单。这张纸决定后面所有登记范围。

### 第 1 步：智能预填（只审不写）

1. 进入 **系统管理 → 治理与审核 → 规则治理 → 业务本体**，选对数据源；
2. 点右上「智能预填」，等待草案生成；
3. **逐条审阅**，重点看三处：
   - 实体名是否业务常用词（「主营业务」是否该叫「业务条线」）；
   - 关联路径的方向与基数（默认「大表 → 小表、N:1、LEFT」）；
   - 层级顺序是否由粗到细；
4. **先不要点应用**。把「未自动生成的项」抄下来，作为第 2~5 步的补录清单。

> 预填是草案生成器，不是一键正确。自动推断的关系会标注「使用前请复核」。

### 第 2 步：核心实体与绑定（决定成败）

先只做 **1~3 个最核心的实体**（通常是机构、客户、项目），每个实体按下面配：

| 配什么 | 怎么配 | 注意 |
|---|---|---|
| 实体名称 | 用业务口语（机构、客户） | 不要用表名，≤50 字，数据源内唯一 |
| 别名 | 收全用户真实会说的词 + 列名（如 `JGMC`、组织） | ≤10 个，别放「表」「数据」这类超短歧义词 |
| 绑定·标识 | 名称列，角色选「标识」 | 权重最高（+8） |
| 绑定·关联键 | 编号列，角色选「关联键」 | 跨表 JOIN 靠它（+4），必配 |
| 绑定·属性 | 状态等筛选列 | 按需（+3），别把整张宽表列都绑上 |

**完成标准**：每个实体至少 1 条绑定，且「标识 + 关联键」齐全。绑多了没用——单表加权封顶 +15。

### 第 3 步：高频值域（只登记「代码≠含义」）

1. 从第 0 步清单里挑出被问最多的枚举列（如 `BB` 本期/同期、`SF` 是否）；
2. 子页签「值域释义」，先选定表名与列名，再批量粘贴：

   ```
   1=本期
   2=同期
   ```

3. 看实时预览的「将写入 / 重复 / 无法解析」，确认后「批量保存」。

**不要登记**：含义即文本的列（「取值如：主营业务、金融市场业务」）、指标计算口径、值与含义完全相同的项。

> 值域**没有版本、删除不可恢复**。批量改生产前先用测试数据源试，或先导出原值。

### 第 4 步：关键关联路径（只登记验证过的）

1. 「关联路径」→「登记路径」；
2. 填起点表/列、终点表/列（复合键就多列，两侧数量必须一致）；
3. 选 JOIN 类型（不确定用 LEFT）与基数（起点 → 终点）；
4. 用途写清业务语义，如「项目归属机构，按机构编号关联」；
5. 保存后用「路径预览」输入两张表名，点「检索最短路」自检。

**先只登记最高频的 1~2 条**。多跳路径系统会自动串联（最多 3 跳），不用重复登记 A→C。

### 第 5 步：一个主层级

1. 「业务层级」→「新建层级」，命名如「机构层级」；
2. 逐级填列名，用上下箭头排成**由粗到细**（`JTMC > FGSMC > XMMC`）；
3. 确认底部预览方向正确后「确认创建」。

至少 2 级、最多 10 级。层级只影响分组/下钻建议，不生成 SQL。

### 第 6 步：验证与放量

对第 0 步的每个目标问题各问一次，在结果卡片点「推导回放」，看「业务本体命中」：

| 指标 | 期望 | 为 0 说明什么 |
|---|---|---|
| 实体命中数 | ≥1 | 问题里没出现实体词，或别名没收全 |
| 加权表数 | ≥1 | 实体没绑定，或绑定表名与 Schema 不一致 |
| 注入 token | >0 且未顶满 1500 | 被预算裁掉、开关关闭，或资产过多 |

三条都正常后，再看 A/B：同一问题带 `disableOntology` 对比 SQL 是否更准。**验证通过才继续加资产**，每轮只加 1~2 个实体，观察一周。

> 同一问题在缓存期内会复用旧结果，登记后请换新问法或点「重新查询」。

---

## 四、三条红线

1. **值域无版本**：改动前先导出/测试，删除不可恢复；
2. **停用优先于删除**：暂时不用就停用，数据与绑定都保留；删除后界面无回收站（实体/关系/层级仅留快照，无恢复入口）；
3. **Schema 改名必回归**：当前版本没有漂移告警，表/列改名后绑定、值域、关系、层级会静默指向旧名，必须人工核对。

## 五、责任分工与首轮验收

| 角色 | 负责 | 交付物 |
|---|---|---|
| 业务负责人 | 第 0 步场景清单、实体命名与别名口径、值域含义确认 | 问题清单 + 口径确认 |
| 数据分析师 | 第 2~5 步登记、trace 验证 | 四类资产 + 验证记录 |
| 管理员（ADMIN） | 开关、权限、生产变更与回滚 | 变更记录 + 版本号 |

**首轮验收只做三件事**：目标问题 SQL 是否更准、结果是否与人工核对一致、开/关本体是否有可解释差异。三项都过，再扩量。

---

## 六、一页速查

```
① 选 3~5 个高频问题 → ② 智能预填只审不写 → ③ 1~3 个实体（标识+关联键）
→ ④ 高频值域（代码≠含义） → ⑤ 1~2 条验证过的 JOIN → ⑥ 1 个主层级
→ ⑦ 每问一次看 trace 三数 → ⑧ 小步放量，一周一轮
```
