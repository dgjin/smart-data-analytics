MODULE 02 · 流式体验

SSE 流式阶段：等待时屏幕上是什么

请求以 stream 方式提交，服务端通过 Server-Sent Events 实时推送阶段事件。

understanding

语义理解中

正在理解问题语义并匹配数据字段

introspecting

数据自省中

执行探查 SQL，确认字段真实取值（需数据源开启自省）

executed

SQL 已执行

返回真实行数；SQL 就绪后即先行回显，可提前预览

analyzing

洞察生成中

基于真实数据生成解读与图表配置

📍 SQL 先行回显

SQL 生成完成即推送到界面（sql_ready），无需等待执行与解读完成——审核 SQL 的同事可以提前介入，发现口径问题可提前终止。

🛟 降级兜底

AI 引擎或数据库暂时不可用时，返回带明确标识的示例数据，界面不白屏；审计状态记为 FALLBACK。这些失败样本还会自动进入对抗训练队列（模块三详解），系统越用越聪明。

等待的那段时间，屏幕不是空白转圈，而是实时告诉你系统进行到哪一步了。四个阶段：understanding 在理解语义；introspecting 是数据自省，只有数据源开了自省开关才会出现，它在真正出数前先探查一下字段里的真实取值；executed 表示 SQL 已经在数据库执行完，拿到真实行数了；analyzing 是最后的解读生成。这里有个很实用的细节：SQL 一生成完就会先行回显到界面上，不用等整条链路跑完。懂 SQL 的同学可以在这个窗口期先审一眼口径对不对，不对就提前停，省时间。另外记住降级兜底机制：万一大模型或者数据库临时不可用，系统会返回带明确标识的示例数据，保证界面不白屏，同时审计里记 FALLBACK，绝不会拿演示数据冒充真实结果。而且从 v0.9.44 开始，这些失败样本不会被浪费——它们会自动进入对抗训练审核队列，修好之后同类问题就自动会做了，这个机制模块三细讲。

🤔 触发场景

MODULE 02 · 进阶模式

三个进阶开关与模型自选

计划模式

先出计划，批准再执行

提问后先生成分析计划（编号步骤、涉及表，不执行），展示计划卡片供批准；批准后携带 planId 执行。计划 10 分钟有效、一次性消费，过期或问题不匹配返回 409。

深度分析

中间表清洗链

复杂问题自动多步清洗（去重 / 标准化 / 过滤 / 聚合），逐步物化为 ait_* 中间表（TTL 24 小时，每用户最多 10 张），最终 SQL 只引用中间表；清洗失败不阻断主链路。

数据自省

先探查再生成

数据源级开关（默认关）。开启后模型可先执行一条探查 SQL（DISTINCT 取值 ≤30 行回喂），解决「取值不确定」型歧义。仅首轮一次，防止递归。

MODULE 03 · 数据安全

数据安全：四道防线层层设防

防线一 · 只读执行

所有问数与样例 SQL 强制走 SELECT 白名单校验（AST 解析），字符串字面量在校验副本中置空防关键字干扰，杜绝注入与写操作。

防线二 · 行级权限

数据源 scope 可登记行过滤谓词（如 region LIKE '安徽省%'）；所有真实执行链路（问数 / 报表 / 重跑 / 下钻 / 降级复用）执行前由 AST 强制包裹为过滤派生表，注入失败一律 fail-closed 拒绝查询。

防线三 · 敏感信息过滤

Schema 上下文加载时剔除敏感列——AI 根本「看不见」这些字段，从源头防止敏感数据进入提示词与结果；数据源密码加密落库。

防线四 · 审计与限流

每次问数审计落账（SUCCESS / FALLBACK / CLARIFY / CACHE / DENIED）；API 访问日志含被拒请求；限流 + 每用户配额 + 并发槽互斥。

设计哲学：权限不是「建议」，是执行层强制——AI 生成的任何 SQL（含降级策略复用的 SQL）都逃不出这四道防线；宁可拒绝查询（fail-closed），绝不越权出数。

安全这一页请管理员务必记住，也请分析师放心。第一道防线只读执行：AI 生成的每条 SQL 都经过解析器白名单校验，只能 SELECT，写操作和注入根本进不了数据库——注意连 Fallback 降级复用的 SQL 也一样要过这道校验。第二道行级权限：可以按数据源配置行过滤，比如某个分析师只能看安徽省的数据，那他无论怎么问，SQL 都会被强制包上一层过滤条件，覆盖子查询、联合、连接各种写法，注入失败就整个拒绝，宁可不出数也不越权。第三道敏感信息：敏感列在 AI 读表结构那一步就被剔掉了，模型压根不知道有这个字段，提示词里不会出现，结果里自然也没有；数据源密码也是加密落库。第四道审计限流：每次提问都有审计状态，谁在什么时间问了什么、走没走缓存、有没有被拒，全部留痕。一句话总结：这个系统里，权限是墙不是帘子。
MODULE 03 · 知识库

知识库：把业务口径喂给 AI

📚 管什么

业务术语、指标口径、字段含义、分析指南类文档。例如「月末快照」「BB=1 核算版」「长龄项目」这类只有业务自己才懂的词。

⚙ 怎么生效

  • · 问数时按相关性检索（TOP4，单文档限 2 块）
  • · 向量分 × 词法分混合选块，口径/指南类保留专门槽位
  • · 注入提示词带 token 预算控制，不会撑爆上下文

📌 实践建议（管理员）

  • · 上线前先沉淀 10-20 条核心口径（版本字段、快照口径、专有缩写）
  • · 支持元数据 Excel 批量导入，宽表字段含义一次配齐
  • · 口径变更时同步更新知识库，AI 输出随之对齐
  • · 表 / 字段中文注释同样参与语义匹配，值得用心写

效果：知识库命中后，AI 用的是登记口径而非字面猜测——同一个「投资收益」，全系统同一个算法；业务维度取值变化时，系统还会自动提醒知识库可能过时（漂移检测，v0.9.7）。

🔗 外部知识源接入（v0.4.1）

知识库面板底部可接入企业已有 RAG 服务（Dify/RAGFlow/自建网关），POST 检索协议，Bearer 认证，与本地知识并行检索，独立 token 预算不挤占。

知识库是这个系统越用越准的第一秘诀。它管的是那些只存在业务同事脑子里的东西：术语、口径、字段含义、分析指南。举个例子，「月末快照」和「BB 等于 1」是什么意思，新来的分析师都要问老员工，AI 更不知道——但只要写进知识库，问数时系统会按相关性把这几条检索出来注入给模型，它就懂了。检索机制做了精细打磨：取最相关的前四块，单个文档最多贡献两块防止刷屏，向量相似度和关键词匹配混合打分，口径类指南类内容还有保留槽位。v0.9.7 还加了漂移检测：业务维度的取值发生变化时，系统会提醒你知识库可能过时了，该更新了。另外管理员还可以在知识库面板底部接入外部知识源——比如企业已有的 Dify、RAGFlow 等 RAG 服务，配好接口地址和认证就能用，问数时和本地知识库并行检索，独立 token 预算不挤占，单源失败也不阻断，知识来源更丰富。给管理员的实践建议：上线前先沉淀一二十条核心口径，宽表字段含义用 Excel 批量导入，口径变了记得同步更新。表和字段的中文注释也参与语义匹配，注释写得越用心，圈表和选列就越准。
MODULE 03 · SQL 样例库

SQL 样例库：AI 的「范文库 + 错题本」

每条样例是一对「问题 → SQL」；问数时自动挑选与当前问题最相似的 top-3 注入上下文（few-shot），让 AI 照着范文写。

来源一 · MANUAL

来源二 · FEEDBACK_UP

用户对结果点 👍 即自动沉淀该条问答为样例——最好的样例永远来自真实使用

来源三 · IMPORT

Excel 批量导入历史问答资产，存量取数经验一次性迁移进系统

🎯 生效机制

  • · 相似度排序取 top-3，只注入最相关的范文，不撑爆上下文
  • · 样例 SQL 同样过 SELECT 白名单，安全校验不豁免
  • · 样例按数据源维度管理，换源不串味
  • · JSON 备份导入导出（v0.9.33）：迁移 / 共享一键完成，冲突可跳过 / 覆盖，支持预检

📉 点踩怎么办

点 👎 的问答作为反例注入提示词，明确告诉模型「这类理解是错的」——AI 不仅学范文，也上错题本；失败样本还有对抗训练兜底（见后页）。

如果说知识库教 AI 懂业务，样例库就是教 AI 写 SQL。每条样例就是一个问题配上标准答案 SQL。攒样例有三条路：手工录入，把高频取数写成范文；点赞沉淀，这是最重要的一条——大家对结果满意就点个赞，这条问答立刻变成新样例，下次同事问类似问题直接命中；还有 Excel 批量导入，把过去多年的取数经验一次搬进来。生效的时候系统不是全量塞给模型，而是按相似度挑最像的三条做范文，上下文干净。样例 SQL 一样要过只读白名单，不能借样例之手干写操作。v0.9.33 之后指标库和样例库都支持 JSON 备份导入导出了，换环境、跨团队共享一键完成，同名冲突可以跳过或覆盖，还能先预检再正式导入。最后说点踩：点踩的问答会作为反例注入，明确提醒模型这种理解是错的。所以点赞点踩都是在训练你们自己的 AI 助手，成本为零，收益复利。

📐 语义指标层（管理员）

为什么值得做

  • · 「投资收益」「不良率」这类核心指标全系统一个算法
  • · 同义词登记后，口语化提问也能命中标准口径
  • · 口径变更只改一处，所有问数随之对齐
  • · 看板「语义指标直查」直出结果，指标 / 样例库支持 JSON 备份（v0.9.33）

⚡ 技能库：提问模板资产

技能 = 预置提问模板（名称 + 模板文本 + 适用数据源）。输入区 ＋ 按钮弹出技能面板，选中即填充，改两个词就能提问。

  • · 系统技能：内置通用分析模板，开箱即用
  • · 用户技能：个人技能可提交分享，管理员审核通过后全团队可用
  • · 技能与数据源绑定，换个源不会出现不适配的模板
这页讲两个提升命中率的基础设施。先看语义指标层。很多争议来自同名不同义：你说投资收益是这个算法，他说投资收益是那个算法。管理员把核心指标登记进去——指标名、同义词、标准口径 SQL 片段，每源最多两百条。之后任何人提问只要命中指标名或同义词，标准口径直接模板化注入，AI 照抄就行，不用自己理解。口径变了改一处，全系统对齐。指标还有个直查入口：看板页选「数据源加指标加分维度」，不写一句话也能直出结果，口径和问数共享同一套语义层定义。v0.9.33 起指标和样例库都支持 JSON 备份导入导出，跨环境迁移很方便。再看技能库。技能就是提问模板，解决「不知道怎么问」的问题：点输入框旁的加号弹出面板，选一个模板填充进来，改两个词就能跑。技能分系统内置和个人创建两类，个人技能可以提交分享，管理员审核通过后全团队复用。团队里总有人特别会提问，把他的问法沉淀成技能，就是最好的经验传承。
MODULE 03 · 铁律规则

铁律规则库：数据源级强制规则

v0.9.35 新增——按数据源定义所有问数必须遵守的强制规则，全量恒注入，优先级高于样例与知识库。

📏 什么是铁律

数据源级的红线规则，例如：「禁止跨法人统计」「只取最新一期数据」「表头及说明必须中文」。生效中的规则对每次智能问数与报表生成强制生效——模型必须遵守，用户无法绕过。

⚙ 生效机制（管理员）

系统管理 → 规则治理 → 铁律规则库：按数据源登记，支持启停；JSON 备份导入导出，冲突可跳过 / 覆盖、可预检。

🈶 中文强制兜底（v0.9.39 / v0.9.42）

「表头及说明必须中文」从提示词约束升级为双保险：即使模型没遵守，服务端也会在返回前把残留英文表名 / 列名自动替换为业务中文名；AI 自造的派生列按词根推断（如 recovery_ratio_pct → 回收比率（%）），无法识别的保持原值、不编造。

🧭 与其他治理手段的关系

优先级：铁律 > 语义指标 > 知识库 > few-shot 样例——红线永远是最高约束，冲突时铁律说了算。

接下来是治理体系里优先级最高的一层：铁律规则库。什么意思？有些规则不是「建议 AI 参考」，而是红线：比如「禁止跨法人统计」——法人口径是合规问题，绝不能混；「只取最新一期数据」——快照表取错期就会重复累计；「表头及说明必须中文」。v0.9.35 之后，管理员可以按数据源登记这些铁律，生效中的规则对每一次问数和报表生成都强制注入，优先级高于指标、知识库和样例，模型必须遵守，用户也绕不过去。其中中文这条铁律在 v0.9.39 和 v0.9.42 还做了服务端兜底：就算模型不听话输出了英文字段名，系统在返回结果前也会自动替换成数据源里维护的业务中文名；AI 自己造的派生列，比如 recovery_ratio_pct，会按统计和金融词根推断出「回收比率（%）」，实在识别不了的保持原值，绝不编造。所以现在界面上的表头、图表轴名、AI 解读，全链路都是中文。铁律也支持启停和 JSON 备份导入导出。记住优先级口诀：铁律大于指标大于知识库大于样例，红线永远是最高约束。

MODULE 04 · 安全合规

安全合规全景：账号、数据、审计三张网

账号与会话
  • · JWT 会话令牌，接口层统一鉴权
  • · 密码加密存储，永不明文回显
  • · 新账号首登强制改密
  • · 越权访问 403 + 路由重定向
数据防线（回顾 P18）
  • · SELECT 白名单（AST 解析）
  • · 行级权限强制注入，fail-closed
  • · 敏感列对 AI 不可见
  • · 数据源密码加密落库
审计与限流
  • · 问数审计五态：SUCCESS / FALLBACK / CLARIFY / CACHE / DENIED
  • · API 访问日志含被拒请求
  • · DLP 数据下载审计（AI 审核区）
  • · 限流 + 配额 + 并发槽 · traceId 可回放

合规要点：本地引擎方案下，提问、表结构、结果数据全程不出内网；全链路审计留痕满足内审与监管检查「谁在何时查了什么、看到了什么」的追溯要求。

安全讲了两页，这页收个总。三张网：账号层，JWT 会话加接口统一鉴权，密码加密存储永不明文回显，新账号强制改密，越权直接 403；数据层就是前面讲过的四道防线——只读白名单、行级权限、敏感列屏蔽、密码加密，这里列出来帮大家复习，注意降级策略复用的 SQL 同样要过这些校验；审计层，每次问数落审计账，五种状态：成功、降级、澄清、缓存、拒绝，被拒的请求也记录，数据下载有 DLP 审计，配上限流配额和并发槽，既能追责也能防滥用。合规角度总结一句话：用本地引擎部署时，从提问到表结构到结果数据全程不出内网；每个数字都能回答「谁、什么时候、问了什么、看到了什么」。这套体系拿去应对内审和监管检查，材料都是现成的。安全不是绊脚石，是这套系统能进生产环境的前提。
