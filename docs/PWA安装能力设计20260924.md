# Chrome 应用（PWA）安装能力设计

> 版本：v1.1（2026-09-24，补充 §6.1 生产部署判定）｜目标版本：v0.9.72
> 状态：**已批准并完成实施**（v0.9.72，2026-09-24）

---

## 1. 背景与目标

### 1.1 背景

当前应用为纯 Web 形态：浏览器标签页访问，无独立窗口、无桌面图标、无离线兜底。用户希望将本应用"安装为 Chrome 应用"——即通过 PWA（渐进式 Web 应用）技术，在 Chrome 中提供「安装应用」能力，安装后以独立窗口（无地址栏）运行，像桌面应用一样启动。

### 1.2 目标（P0）

1. Chrome（桌面）中满足可安装性条件：地址栏出现「安装」图标 + 应用内提供「安装应用」按钮；
2. 安装后以 standalone 独立窗口运行，从系统启动台/开始菜单启动；
3. 断网/离线时打开显示应用壳 + 明确的离线提示（不白屏、不报错）；
4. `/api/**` 数据一律**不缓存**（多用户数据与鉴权安全底线）；
5. 完全渐进增强：不支持的浏览器（Firefox/Safari 桌面）功能不受任何影响。

### 1.3 非目标（Non-goals，本次不做）

- 富安装界面（`screenshots` / 安装提示增强文案）；
- 内网 HTTPS 部署证书配置（本次场景为本机 `localhost`，天然满足安全上下文；内网分发需 HTTPS 已在 §7 风险中说明）；
- 离线数据能力（离线仅壳 + 提示，不做离线查询/写操作队列）；
- 移动端/Android 专门适配与验收；
- iOS/Safari 安装引导（Safari 桌面不支持 PWA 安装，非本需求范围）。

### 1.4 可安装性标准（依据）

Chrome 安装 PWA 的硬性条件（MDN，2025-02 版）：

| 条件 | 本项目满足方式 |
|---|---|
| Web App Manifest（必填 `name` / `icons` / `start_url` / `display`） | 新增 `public/manifest.webmanifest`（§4.1） |
| Service Worker（含 fetch 事件处理程序） | 新增 `public/sw.js`（§4.2） |
| 安全上下文（HTTPS 或 localhost/127.0.0.1） | 本机 `http://localhost:3000` 天然满足；内网 HTTP 裸 IP 不满足（见 §7） |

## 4. 详细设计

### 4.1 Web App Manifest（`public/manifest.webmanifest`）

```json
{
  "id": "/",
  "name": "智能问数分析系统",
  "short_name": "智能问数",
  "description": "多源数据集成 · 自然语言交互 · 自动可视化与决策简报",
  "lang": "zh-CN",
  "start_url": "/",
  "scope": "/",
  "display": "standalone",
  "background_color": "#0f172a",
  "theme_color": "#0f172a",
  "icons": [
    { "src": "/icons/icon-192.png", "sizes": "192x192", "type": "image/png" },
    { "src": "/icons/icon-512.png", "sizes": "512x512", "type": "image/png" },
    { "src": "/icons/maskable-192.png", "sizes": "192x192", "type": "image/png", "purpose": "maskable" },
    { "src": "/icons/maskable-512.png", "sizes": "512x512", "type": "image/png", "purpose": "maskable" }
  ]
}
```

要点：
- `display: standalone` → 安装后独立窗口（无地址栏）；
- `start_url` / `scope` / `id` 均为 `/`，与现有 SPA 路由一致（登录态由 localStorage 持久化，独立窗口打开即恢复）；
- `background_color` / `theme_color` 取 `slate-900 (#0f172a)`，与 Header 深色底一致（浅色主题下启动闪屏为深色，可接受；P1 再做动态化）；
- 图标 4 张：常规 ×2 + maskable ×2（maskable 保证 Android/不同圆形裁切下的安全区）。

### 4.2 Service Worker（`public/sw.js`，零依赖手写）

**缓存策略（三线分流）**：

| 请求类型 | 策略 | 说明 |
|---|---|---|
| `mode === 'navigate'`（页面/SPA 路由） | **网络优先** → 成功回填缓存 `/`；失败 → `caches.match('/')`；再无 → 返回内置离线页 | 在线永远拿到最新 `index.html`，从根上避免"页面不更新"问题 |
| 同源 GET 静态资源（`/assets/*`、`/icons/*` 等） | **缓存优先** → 未命中请求网络并回填 | Vite 产物为 hash 文件名，缓存天然安全；图标等由 `install` 预缓存 |
| `/api/**` 及其他非同源/非 GET 请求 | **直通（NetworkOnly）** | 绝不写入 CacheStorage；SSE（`text/event-stream`）不受任何影响 |

> **v0.9.98 实现修订（以代码为准）**：
> - 静态资源策略由「缓存优先」改为「**网络优先、离线回退缓存**」——在线永远最新，离线仍可回退缓存打开应用壳；修复点：dev 模式模块路径无 hash，缓存优先会把旧版本钉死，导致升级后「新功能对用户不可见」。
> - 缓存名升至 `nl2sql-app-v2`（旧版本缓存由 `activate` 清理）。
> - `register.ts` 在 dev 模式不再仅「不注册」，还会主动注销历史遗留的 SW 注册并清空 CacheStorage（异步静默，见 §4.3）；此前以生产模式访问过的浏览器经一次刷新（必要时两次）即可自愈。
>
> 详见《系统功能说明书》§3.15。

**生命周期**：

- `install`：预缓存核心壳（`/`、`/manifest.webmanifest`、4 张图标；采用逐个容错策略，单资源失败不阻塞安装）→ `skipWaiting()`；
- `activate`：清理非当前版本的旧缓存 → `clients.claim()`（首次安装即接管，无需二次刷新）；
- 更新机制：`sw.js` 由服务端 `Cache-Control: no-cache` 提供（§4.6）+ 页面每次加载调用 `registration.update()` 主动探测；新版本部署后用户**刷新一次即生效**（导航与静态资源双网络优先 + activate 清旧缓存三重保障，功能新鲜度不依赖版本号变更，版本常量仅用于缓存清理命名）。

**离线兜底**：若用户从未在线访问过（无缓存），导航请求失败时返回 SW 内置的极简离线 HTML（深色底 + "网络不可用，请检查网络后重试"），避免 Chrome 默认错误页。

### 4.3 注册模块（`src/pwa/register.ts`）

- `registerServiceWorker()`：
  - 仅 `import.meta.env.PROD && 'serviceWorker' in navigator` 时注册（**dev 模式不注册**，避免缓存干扰 HMR/调试；v0.9.98 起 dev 模式还会主动注销遗留 SW 注册并清空 CacheStorage 自愈，见 §4.2 修订注记）；
  - `window.load` 后 `register('/sw.js', { scope: '/' })`，随后调用一次 `registration.update()` 探测更新；
  - 全程 `catch` 静默（SW 注册失败不得影响应用本体）。
- `main.tsx` 增加一行调用（组合根位置）。

### 4.4 安装入口（应用内按钮 + 原生入口）

**Hook `src/pwa/usePwaInstall.ts`**：

| 状态 | 触发 | UI 表现 |
|---|---|---|
| 不支持 / 不可安装 | 无 `beforeinstallprompt`（Firefox/Safari/非安全上下文） | 不渲染按钮 |
| 可安装 | `beforeinstallprompt` 触发（`preventDefault()` 暂存事件） | 渲染「安装应用」按钮 |
| 安装中 | 点击 → `deferredPrompt.prompt()` → `await userChoice` | 按钮禁用态 |
| 已安装 | `appinstalled` 事件 或 `display-mode: standalone` 已成立 | 按钮永久隐藏 |

**组件 `src/components/InstallAppButton.tsx`**：放置于 Header 右侧操作区（主题切换按钮旁），样式对齐现有快捷按钮（`px-3 py-1.5 rounded-lg text-xs`，Lucide `MonitorDown` 图标，窄屏仅图标）；title 提示"如未弹出安装框，可点击地址栏右侧的安装图标"（覆盖 Chrome dismiss 冷却期场景）。

### 4.5 应用图标（AI 生成 + 派生）

1. **主图生成**：ImageGen 生成 1024×1024 主图，prompt 要点：深色圆角方形底（`#0f172a`）、中央数据可视化（柱状/趋势线）+ 对话气泡融合意象、靛蓝 `#6366f1` → 青色 `#22d3ee` 渐变、扁平现代风格、**无文字**、主体居中、四周留白；生成 1–2 张检视选优。
2. **派生（本机 Python/PIL）**：
   - `icon-512.png` / `icon-192.png`：主图缩放；
   - `maskable-512.png` / `maskable-192.png`：主体缩至 ~80% 安全区，四周填充 `#0f172a` 底色；
   - `apple-touch-icon-180.png`：顺带产出（成本 1 行）。
3. **落地**：`public/icons/*.png` → 构建自动拷贝至 `dist/icons/`。
4. **兜底**：若生成质量不满意，最多重试 2 次；仍不满意回退"自绘 SVG 矢量图标"方案（保底可用」。

## 5. 安全边界

1. **`/api/**` 零缓存**：SW 直通所有 API 请求（含 SSE），CacheStorage 不落任何业务数据，杜绝多用户数据串号与 token 外泄；
2. **SW 拦截面最小**：仅处理同源 GET 静态资源与导航请求；POST/PUT/DELETE/跨域一律直通；
3. 无新增权限申请（PWA 不涉及摄像头/通知等敏感权限）；
4. 安装行为完全由用户主动触发（按钮点击或地址栏图标），无强制引导；
5. `frame-ancestors 'none'` 等既有安全头保持不变。

### 6.1 生产环境部署判定（补充说明，2026-09-24）

> 结论先行：**应用功能在任何生产部署形态下都可用（渐进增强、零影响）；「安装为 Chrome 应用」能力仅取决于访问地址是否满足安全上下文**。

| 生产部署形态 | 应用功能 | PWA 安装能力 | 说明 |
|---|---|---|---|
| Docker + nginx `:80`（现有部署形态，团队以 `http://服务器IP` 访问） | 正常 | **不可用**（非安全上下文：安装按钮自动隐藏、地址栏无安装图标、无任何报错） | 现有 `deploy/nginx.multi-instance.conf` 为纯 HTTP |
| nginx 接入 HTTPS（`:443` + 证书），`http → https` 重定向 | 正常 | **完整可用**（安装 / 独立窗口 / 离线壳） | **仅 nginx 配置变更，应用代码零改动**；SW 注册在 https 下自动生效 |
| 经公司统一网关 / 零信任代理，浏览器侧为 https 域名 | 正常 | 完整可用 | 与后端实际形态无关，只看浏览器地址栏 |
| 前端部署在子路径（如 `https://host/app/`） | 正常 | 需适配 | 当前方案假设根路径（`scope/start_url = '/'`）；子路径部署需同步调整 Vite `base`、manifest `scope/start_url` 与 SW 注册 scope（本次不涉及） |

**生产接入 HTTPS 的两个注意点**：

1. **证书须被浏览器信任**：正式证书（Let's Encrypt / 企业 CA）直接可用；内网自签证书必须将根 CA 导入各客户端受信任根，否则 Chrome 拒绝在「证书错误被忽略」的页面上注册 Service Worker，安装能力同样不可用；
2. **origin 变更需重新安装**：PWA 安装与 SW 缓存均按 origin（协议 + 域名 + 端口）隔离；从 `http://ip:3000`（或 localhost）切换到 `https://域名` 后，需在新 origin 上重新安装一次，旧 origin 的安装不受影响。

**多实例 / 负载均衡无影响**：Service Worker 运行在浏览器端，与后端实例数无关；各实例提供同一构建产物（hash 文件名一致），nginx 轮询不产生任何差异。

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 生产环境为 HTTP（非 localhost） | Chrome 不提供安装能力（应用功能不受影响） | 仅需 nginx 接入 HTTPS（判定表见 §6.1），应用代码零改动；自签证书需导入受信任根，否则 SW 无法注册 |
| SW 缓存导致"页面不更新" | 用户停留在旧版本 | 导航网络优先 + `sw.js` no-cache + 页面加载 `update()` + activate 清旧缓存四重保障；README/使用指南附「应急注销 SW」说明（DevTools → Application → Service Workers → Unregister） |
| `beforeinstallprompt` 冷却期 | 用户 dismiss 后 Chrome 暂不再弹窗 | 按钮保留；文案引导"可通过地址栏安装图标安装" |
| 离线时打开 | 登录/查询失败体验差 | SW 壳缓存 + 全局离线横幅；首次即离线时返回内置离线页（不白屏） |
| AI 图标质量不达标 | 视觉不满意 | 重试 ≤2 次；保底回退自绘 SVG 方案 |
| 浅色主题下启动闪屏为深色 | 轻微观感差异 | 可接受（P1 可做动态 background_color）；不阻塞交付 |
| dev 模式无 SW | 开发者误以为功能缺失 | 注册模块显式注释"仅生产"；验收步骤明确要求跑 `npm run build && npm start` |

## 11. 附：关键实现草图（示意，非最终代码）

```js
// public/sw.js —— 核心结构示意
const CACHE = 'nl2sql-app-v1'; // 版本常量：仅用于缓存清理命名
const PRECACHE = ['/', '/manifest.webmanifest', '/icons/icon-192.png', '/icons/icon-512.png',
                  '/icons/maskable-192.png', '/icons/maskable-512.png'];

self.addEventListener('install', (e) => {
  e.waitUntil((async () => {
    const c = await caches.open(CACHE);
    // 容错预缓存：单资源失败不阻塞安装
    await Promise.allSettled(PRECACHE.map((u) => c.add(u)));
    await self.skipWaiting();
  })());
});

self.addEventListener('activate', (e) => {
  e.waitUntil((async () => {
    const keys = await caches.keys();
    await Promise.all(keys.filter((k) => k !== CACHE).map((k) => caches.delete(k)));
    await self.clients.claim();
  })());
});

self.addEventListener('fetch', (e) => {
  const { request } = e;
  const url = new URL(request.url);
  if (url.origin !== self.location.origin || request.method !== 'GET') return;   // 直通
  if (url.pathname.startsWith('/api/')) return;                                  // API 零缓存
  if (request.mode === 'navigate') {                                             // 导航：网络优先
    e.respondWith((async () => {
      try { const r = await fetch(request); (await caches.open(CACHE)).put('/', r.clone()); return r; }
      catch { return (await caches.match('/')) || offlineFallback(); }
    })());
    return;
  }
  e.respondWith((async () => (await caches.match(request)) ||                       // 静态：缓存优先
    (async () => { const r = await fetch(request); if (r.ok) (await caches.open(CACHE)).put(request, r.clone()); return r; })())());
});
```
