01 · OVERVIEW

项目是什么：一句话提问，数据自己开口

面向不良资产经营分析场景的自然语言数据分析系统，覆盖三类角色。

核心能力

自然语言问数

中文提问 → 语义理解 → 生成 SQL → 真实执行 → 图表 + AI 解读 + 建议追问；歧义先澄清、无关问题如实拒答，不编造数据。

业务场景

不良资产经营分析

机构投放排名、长龄业务、风险去化、逾期、投资收益等八大专业场景，内置专业技能模板与高管决策简报。

角色权限

三级管控

管理员全权配置、分析师问数与知识沉淀、只读用户看数；行级权限强制注入，问数直达生产库也放心。

业务价值：把「提需求 → 排队取数 → 等报表」的天级流程，压缩为「一句话提问 → 秒级出图出结论」。
先讲清楚这个项目是什么。它的核心能力是自然语言问数：业务同事在对话框里输入一句中文，比如「各机构本年投放金额排名」，系统会自动理解语义、找到对应的表和字段、生成 SQL 并在数据库里真实执行，最后把结果变成图表、关键指标卡片和一段通俗易懂的 AI 解读。这里要特别强调两点：第一，所有结果都来自数据库真实执行，不是 AI 编的；遇到歧义它会先反问澄清，遇到答不了的问题会如实说答不了，绝不糊弄。第二，它不是通用玩具，是专门为不良资产经营分析定制的——机构画像、长龄业务、风险去化、投资收益等八大场景都有现成的专业技能模板。权限上分三级：管理员、分析师、只读用户，并且支持行级权限控制。对业务最直接的价值，就是把过去提需求、排队取数、等报表的天级流程，压缩成一句话提问、秒级出结论。
01 · OVERVIEW

技术底座：本地优先、真库真数、轻量可控

AI 引擎本地 Ollama 双模型分工：大模型生成 SQL + 小模型快速解读，可选云端通义千问
数据底座MySQL 双宽表（业务 94 列 / 财务 204 列），兼容 PostgreSQL 与 Greenplum
知识增强口径知识库 + 语义指标 + SQL 样例库，教模型「懂业务口径」
应用架构React 前端 + Node 后端一体化，Docker 可部署，单机即可运行
本地优先

AI 模型跑在本地，数据不出内网，满足金融数据安全要求；云端引擎仅作可选补充。

轻量向量方案

知识检索用嵌入式向量 + 关键词混合，不引入独立向量数据库——百千级规模下零新增运维组件。

双模型分工

重思考用大模型保证准确，轻解读用小模型保证速度，问数整体提速一倍。

这一页讲技术底座，向各位保证三件事：本地优先、真库真数、轻量可控。AI 引擎跑在本地服务器上，数据不出内网，这对金融业务数据是硬要求；同时保留了云端通义千问作为可选补充。数据底座是两张真实业务宽表，业务宽表 94 列、财务宽表 204 列，合计 1266 万行、覆盖 20 个月末报告期快照，而且系统同时兼容 MySQL、PostgreSQL 和 Greenplum 三种数据库，未来对接数仓不需要重写。特别值得一提的是双模型分工的设计：生成 SQL 这种重思考的任务交给大模型保证准确率，生成解读这种轻任务交给小模型保证速度，整体问数速度提升了一倍。整个架构单机就能跑，Docker 一键部署，没有引入任何重型中间件——这是刻意的选型：在当前数据规模下，够用、可控、运维成本最低。

最后三个版本是收尾打磨，围绕一个设计哲学：系统可以有边界，但不能撒谎。第一个，金额单位自选：汇报时大家习惯不同，有人看亿元有人看万元，现在提问时可以随时切换，整条链路——图表、解读、导出——全部统一口径。第二个，解读失败降级优化：以前 AI 解读偶尔失败时会输出一句空洞的兜底文案，毫无信息量；现在改为规则引擎接管，基于真实查询结果的统计值自动生成有信息量的解读——总计多少、均值多少、最高最低是谁，全部真实可核。第三个是最新上线的拒答契约：如果有人问系统写一首诗、或者问数据源里根本没有的指标，系统会如实说明这个问题与当前数据无关或者缺少支撑数据，而不是编一份演示数据糊弄过去，并且每次拒答都会在审计日志留痕。这三个版本看似小，实际共同守住了数据分析系统最核心的资产——可信度。

04 · LESSONS

沉淀的六条经验：可复制到下一个项目

① 真库真数是底线

第一天就用真实数据验证，「看似正确」的口径错误逃不过与手工 SQL 的比对。

② 配置优先于代码

口径类问题在配置层修复，不动核心代码，零回归风险。

③ 全链路留痕

推导回放、审计八态、对话落库——每个结论可追溯、可复盘、可定责。

④ 降级不撒谎

失败给真实统计，答不了给真实理由，演示数据永远显式标记。

⑤ 文档即产品
