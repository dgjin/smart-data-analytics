## 一、先选一条初始化路径

| 路径 | 适用场景 | 数据源 | 预计耗时 | 关键差异 |
|---|---|---|---|---|
| A 体验验证 | 本机试用、演示、培训 | 内置演示数据集（926 行） | 30–60 分钟 | 不碰业务库；本体项需手工补 |
| B 正式上线（单机） | 单台服务器、单实例 | 自有 MySQL / PostgreSQL / Greenplum | 半天 | 需只读账号与范围确认 |
| C 生产部署（容器 / 多实例） | Docker、PM2、多实例 | 自有库 + Redis | 1 天 | 需安全基线、备份与监控 |

三条路径的**阶段 0/1/2 完全相同**，从阶段 3 起分叉。

## 三、阶段 0：环境准备

### 3.1 依赖清单

| 依赖 | 版本 / 说明 | 是否必需 |
|---|---|---|
| Node.js | ≥ 18（生产建议 22） | 必需 |
| MySQL | 8.x，系统元数据库 | 必需 |
| Ollama | 本地推理引擎 | 使用本地模型时必需 |
| Redis | 状态外置（限流/配额/缓存/多实例） | 可选 |
| Python 3 + ReportLab | 报告 / 问数结果 PDF 导出 | 可选 |

### 3.2 模型基线（红线）

```bash
ollama pull qwen3.8:27b-mlx      # 主推理模型；勿用 deepseek-r1 等推理模型（思考链分钟级会致问数超时）
ollama pull qwen3-embedding:8b   # embedding（圈表精排 / 知识检索）；nomic-embed-text 中文相似度塌缩已被评测否决
```

- 云端引擎（千问 / DeepSeek / Gemini）可按 `.env.example` 配密钥切换，但 embedding 需保证可用（DeepSeek 无公共向量端点时自动回退本地 Ollama）。
- **换 `EMBED_MODEL` 必须重嵌存量向量**：`npm run reembed:embeddings`（先 `--dry-run` 备份体检，再正式重嵌，完成后重启服务）。新旧向量混存会静默退化为词法检索。

### 3.3 配置文件

```bash
cp .env.example .env.local     # 按实际环境修改；模板已覆盖应用侧全部在用变量与运维脚本变量
```

- 必配：`MYSQL_*`；生产另需 `JWT_SECRET`、`DS_SECRET_KEY`、`SCRYPT_PEPPER`（生成方式见 [DEPLOYMENT 4.3](./DEPLOYMENT.md)）。
- 模板按「安全 / AI 引擎 / 服务 / 限流 / 缓存 / 连接池 / 数据资源库 / 记忆体 / 后台调度 / 追踪 / 评测」分段注释，逐项说明见 [DEPLOYMENT 第四章](./DEPLOYMENT.md)。
- 其中约 28 个键支持**系统管理 → 系统配置**在线修改并即时生效；`MYSQL_*` 只登记不热更，改后需重启。

### 3.4 连通性自检

```bash
node -v && mysqladmin ping -h 127.0.0.1 -u root -p     # Node / MySQL
curl -s http://localhost:11434/api/tags | head -c 300  # Ollama 已安装模型
redis-cli -u "$REDIS_URL" ping                         # 可选；密码用 REDISCLI_AUTH 传，避免留在命令历史
```

## 四、阶段 1：首次启动与自动建库

```bash
npm install
./start.sh            # 自动拉起 MySQL →（可选 Redis）→ Ollama → 应用，健康检查后打开浏览器
# 或 npm run dev      # 手动开发模式
```

首次启动自动完成三件事（均幂等，可重复执行）：

1. `initSchema()` 建表：**55 张**（含 `ontology_*` 6 张、`memory_*` 3 张等最新功能表）；
2. `seedInitialData()` 写种子：默认管理员、内置技能、预设报告模板、出厂看板、env 配置键位；
3. 加密存量明文密码（数据源凭据 AES-256-GCM）。

验证：`curl -s http://localhost:3000/api/health/ready` 返回 200，且 `checks.mysql.ok = true`。

> **手工建库/升级（可选）**：数据库账号无建库权限、离线交付或需要审计留档时，可先建库再执行 `deploy/sql/upgrade.sql`（累计式幂等，等价于上面第 1 步的建表与存量列/索引迁移），随后照常启动应用完成种子写入与凭据加密：
>
> ```bash
> mysql -h 127.0.0.1 -u root -p -e "CREATE DATABASE IF NOT EXISTS smart_analytics CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci"
> mysql -h 127.0.0.1 -u root -p smart_analytics < deploy/sql/upgrade.sql
> ```
>
> 脚本由 `npm run db:sql` 从 `schema.ts` / `migration.ts` 生成，`npm run db:sql:check` 校验与源码同步；可对同一库重复执行，`upl_*` / `ait_*` 等运行时表不在其中。

> 默认账号 `admin / admin123`。**阶段 5 第一件事就是改掉它**；服务端会持续告警未改默认口令。

## 五、阶段 2：首启初始化向导（v0.9.84+）

### 5.1 触发与重进

- 管理员**首次登录自动弹出**（L1 覆盖层）；点「稍后配置」转为顶部横幅（L2，默认静默 7 天，可设 1–365 天）。
- 完成后 L1/L2 永久消失；随时可在「系统管理 → 治理与审核 → 系统体检」卡片点「打开初始化向导」重进（支持回看与重跑，不影响系统使用）。
- 向导状态存单行表 `setup_wizard_state`，中途刷新页面恢复到当前步骤（断点续做）。

### 5.2 五步做什么

| 步骤 | 做什么 | 通过标准 |
|---|---|---|
| ① 环境自检 | 五项：MySQL / Redis / 对话模型 / Embedding / 内置演示数据（进入即自动执行） | 必需项通过；Redis 未配置按单实例模式，不阻塞 |
| ② 模型服务 | 真实探测 LLM 最小对话与 Embedding 调用 | 两者 `ok`；LLM 失败可点「跳过此步」继续（但问数不可用），Embedding 失败仅告警不挡步 |
| ③ 自动初始化 | 选择已连通数据源（或先一键加载演示数据集，再点「开始执行」） | 6 子任务全部 `success` 或 `skipped`（Embedding 缺失时 4/5 为 `skipped`） |
| ④ 待办确认 | 六项清单动态统计（见下表） | 清单加载即可继续；建议六项全部 `done` 后再完成向导 |
| ⑤ 完成引导 | 总结资产数字，给出下一步入口 | 点「完成」写入 `status='completed'` |

Step③ 流水线 6 子任务（`server/taskHandlers.ts`）：

| # | 子任务 | 产出 |
|---|---|---|
| 1 | Schema 元数据采集 | 表 / 列 / 注释 / 角色写入 `schema_json` |
| 2 | 画像与能力配置 | 领域画像、异常检测能力、指标阈值（默认未启用） |
| 3 | 知识骨架生成 | 知识条目 `knowledge_base_entries` + 铁律模板（`PENDING`） |
| 4 | 知识条目向量入库 | `knowledge_base` 切片与向量（Embedding 不可用则跳过） |
| 5 | Schema 元数据向量入库 | 每表一块的 Schema 向量（Embedding 不可用则跳过） |
| 6 | 样例库种子 | `sql_examples` 通用语法范式 few-shot |

### 5.3 Step④ 六项待办（v0.9.118 起）

| 项 | 统计口径 | 入口（系统管理内） |
|---|---|---|
| 铁律模板 | `iron_rules.status='PENDING'` 计数 | 规则治理 |
| 语义指标阈值 | 数据源 `anomaly_capabilities_json.domainThresholds.enabled` | 语义指标（阈值配置） |
| **业务本体** | `ontology_entities`（`ACTIVE`）+ `ontology_bindings` | 业务本体 |
| Embedding | 真实 ping 结果与维度 | 向导 Step② |
| 业务知识 | `knowledge_base_entries` / `knowledge_base` 切片 | 业务知识库 |
| SQL 样例 | `sql_examples` 计数（知识切片为空时转 `warn`） | SQL 样例库 |

> 清单项的「去处理」当前只会关闭向导并切到「系统管理」页签，需再点对应菜单；`admin:*` 深链尚未定位到具体子菜单（已知限制，不影响资产维护）。

### 5.4 演示数据集的边界

- 一键加载生成 3 张物理表共 **926 行**（销售 864 / 营销 30 / 库存 32），注册为 `ds_setup_demo`，问数链路真实执行，非 mock；重复加载幂等。
- 演示数据**不含业务本体资产**，因此 Step④ 的「业务本体」会保持 `todo` ——属预期，不是加载失败。需要体验本体能力时，到「业务本体」运行「智能预填」并人工复核。

## 六、阶段 3：接入自有数据源（正式路径）

1. **准备只读账号**：仅授予目标库 `SELECT`；不要用业务写账号，系统侧另有 SELECT-only 与表白名单防线。
2. **新增数据源**：支持 `mysql / postgresql / greenplum / csv / json / excel / api`；填写连接信息并测试连通。
3. **确认范围**：选定可查询表（scope）与敏感列过滤；范围越聚焦，圈表越准。
4. **自动配置**：连通后自动执行 Schema 分析与能力配置，并同步知识条目 / Schema 向量 / few-shot 种子；也可在向导 Step③ 对同一数据源重跑。
5. **补元数据**：表注释、列注释、主外键、枚举值含义是问数准确率的第一杠杆；逐类配置要点见 [数据源配置与问数质量保障指导手册](./数据源配置与问数质量保障指导手册.md)。

> 本轮新增数据源不会重新弹向导；到「系统体检」卡片可看到「可运行向量入库」类提示，或直接重走向导 Step③。

## 七、阶段 4：问数质量资产（六件事 + 两项运营）

| 资产 | 作用 | 首轮建议 | 入口 | 详见 |
|---|---|---|---|---|
| 铁律 | 硬约束（口径、禁用列、必须过滤条件） | 先确认自动生成的 `PENDING` 模板，再补 3–5 条高频口径 | 系统管理 → 规则治理 | 实操手册 |
| 指标阈值 | 领域指标异常检测 | 至少启用 1 个核心指标（如长龄化率） | 系统管理 → 语义指标 | 实操手册 |
| 业务本体 | 业务词 → 表/列/值域映射 | 3–5 个实体、8–15 条绑定，先「智能预填」再复核 | 系统管理 → 业务本体 | [主手册](./核心文档/业务本体功能与操作手册.md) / [业务人员版](./核心文档/业务本体实施顺序（业务人员版）.md) |
| 知识条目 | 业务口径、数据字典 | 每张核心表 1 条口径说明 | 系统管理 → 业务知识库 | 实操手册 |
| SQL 样例 | few-shot 冷启动 | 每类高频问题 1–2 条；线上点踩可回流候选 | 系统管理 → SQL 样例库 | 实操手册 |
| 指标库 | 权威指标口径与直查 | 先登记 3–5 个对外口径指标 | 系统管理 → 语义指标 | 实操手册 |
| 评测集 | 回归与门禁 | 20–50 条真实问题，覆盖单表/多表/时间/同义词 | `npm run eval` | [评测集标注规范](./评测集标注规范.md) |
| 满意度 | 质量反馈闭环 | 上线后按周看星级与点踩 | 系统管理 → 访问与评价 | 实操手册 |

业务本体三条红线（来自业务人员版）：只登记「业务词 ↔ 表列/值域」映射，不在本体里写 SQL；单源实体 ≤ 8、关系 ≤ 12、值域 ≤ 40、层级 ≤ 5；无把握先留空，宁缺勿错（错误绑定比没有更伤准确率）。注入预算 `ONTOLOGY_TOKEN_BUDGET=1500`，无数据时零注入。

## 八、阶段 5：账号、权限与安全基线

| 角色 | 智能问数 | 报表/看板 | 数据源管理 | 系统管理 |
|---|:---:|:---:|:---:|:---:|
| ADMIN | ✅ | ✅ | ✅ | ✅ |
| ANALYST | ✅ | ✅ | ❌ | ❌ |
| VIEWER | ❌ | ✅ | ❌ | ❌ |

1. 立即修改 `admin` 默认密码，按人建号（不要共用管理员）。
2. 生产必备：`JWT_SECRET`（缺失 fail-fast 拒启）、`DS_SECRET_KEY`（数据源凭据加密，更换后需重录）、`SCRYPT_PEPPER`、`METRICS_TOKEN`、HTTPS 反代。
3. 可选安全能力：
   - 企业 SSO：`OIDC_ISSUER` + `OIDC_CLIENT_ID`（+ `OIDC_CLIENT_SECRET`）同时配置后登录页出现入口；首次登录按 `OIDC_DEFAULT_ROLE`（默认 VIEWER）JIT 建号，随机密码占位不可本地登录。
   - 数据防泄漏 DLP：默认开启，敏感字段掩码；ADMIN 默认豁免（`DLP_EXEMPT_ADMIN=0` 取消）；非 ADMIN 导出行数超 `DLP_EXPORT_APPROVE_ROWS`（5000）转审批，ADMIN 通过后 24 小时内可再导出一次，导出即消费；单次硬上限 `DLP_EXPORT_MAX_ROWS`（10 万）。
4. Redis 认证（v0.9.118）：`REDIS_URL` 密码含 `/ + =` 必须 percent-encode，推荐 `openssl rand -hex 24` 生成 hex 密码；运维命令用 `REDISCLI_AUTH` 传密码，不要 `-a` 明文。

## 十、阶段 7：Go-Live 验收清单

| # | 检查项 | 方法 | 通过标准 |
|---|---|---|---|
| 1 | 服务就绪 | `curl -s -o /dev/null -w '%{http_code}' http://<host>:3000/api/health/ready` | `200` |
| 2 | 表结构完整 | `SELECT COUNT(*) FROM information_schema.tables WHERE table_schema=DATABASE();` | `55` |
| 3 | 向导状态 | `SELECT status, current_step FROM setup_wizard_state;` | `completed`（或明确跳过且已知原因） |
| 4 | 数据源连通 | `SELECT id,name,status FROM data_sources;` | 目标源 `connected` |
| 5 | Schema 向量 | `SELECT COUNT(*) FROM knowledge_base WHERE data_source_id='<dsId>' AND doc_id LIKE 'autosch_%';` | `> 0` |
| 6 | 知识切片 | `SELECT COUNT(*) FROM knowledge_base;` | `> 0` |
| 7 | 业务本体 | `SELECT COUNT(*) FROM ontology_entities WHERE status='ACTIVE';` + `SELECT COUNT(*) FROM ontology_bindings;` | 实体 ≥ 1、绑定 ≥ 1（体验路径允许 0，需登记豁免说明） |
| 8 | 铁律已确认 | `SELECT COUNT(*) FROM iron_rules WHERE status='PENDING';` | `0` |
| 9 | 样例库 | `SELECT COUNT(*) FROM sql_examples;` | `> 0` |
| 10 | 端到端问数 | 用 3 个真实业务问题提问 | 返回真实数据 + 图表，解读不含臆造数字 |
| 11 | RAG 命中 | 查 `query_trace` 最近一条问数的步骤记录（`step_type` / `output_summary`） | 存在圈表/知识检索步骤且输出非空 |
| 12 | 导出与脱敏 | 用 ANALYST 导出超过 5000 行的 CSV | 触发下载审批；ADMIN 通过后 24h 内可导出一次 |

> 第 5 项 `autosch_` 是自动 Schema 文档的固定前缀（`server/knowledge/autoKnowledgeSync.ts`）；自动知识条目前缀为 `autokb_`。

## 十一、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 首登没弹向导 | 状态已 `completed` / 在静默期 / 非 ADMIN | 「系统体检」卡片手动打开；查 `setup_wizard_state.skipped_until` |
| Step③ 子任务 4/5 显示 `skipped` | Embedding 探测失败 | 修复 Ollama 模型或云端向量配置，回到 Step③ 重跑该子任务；其余子任务不受影响 |
| 演示加载后本体仍为待办 | 演示数据不含本体资产 | 预期行为；到业务本体运行「智能预填」并复核 |
| 换了 embedding 后检索变差 | 新旧向量混存 | `npm run reembed:embeddings` 重嵌并重启 |
| 登录页没有 SSO 按钮 | 只配了 `OIDC_ISSUER` 或 `OIDC_CLIENT_ID` 其中之一 | 补齐两项；核对 `OIDC_REDIRECT_URI` 与 IdP 白名单 |
| Redis 报 `NOAUTH` / 连接串解析失败 | 未带密码，或密码含 `/ + =` 未转义 | 用 percent-encode 或 hex 密码；`REDISCLI_AUTH` 传密码 |
| 导出被拦下要求审批 | DLP 超阈值（默认 5000 行） | ADMIN 在「下载审批」面板通过；授权 24h 内有效且仅一次 |
| 想重新走一遍向导 | 需要重置状态 | 先备份，再执行：`UPDATE setup_wizard_state SET status='pending', current_step=0, step_results=NULL, pipeline_task_id=NULL, skipped_until=NULL, completed_at=NULL WHERE id=1;`（不影响已建资产与数据源） |
| 生产启动即退出 | 未配 `JWT_SECRET` | 设置后重启（fail-fast 属预期） |
