# 数据源接入自动化配置设计（异常扫描模块通用化）

> 日期：2026-09-27　状态：**待批准**　目标版本：v0.9.73  
> 关联：[报表异常扫描优化设计20260927.md](./报表异常扫描优化设计20260927.md)（本设计为其前置依赖）

## 一、背景与问题

当前异常扫描模块的领域能力（四红线口径校验、业务阈值、领域归因）**硬编码绑定数据资源库**（`ds_1786620486498`），新增数据源时无法自动获得这些能力，需手工配置，违背「接入即问数」的产品理念。

**核心矛盾**：数据资源库的四红线/阈值/知识库是**人工沉淀的领域资产**，无法纯自动推导；但新增数据源时系统应**自动完成可自动化的部分**（Schema 分析、通用阈值推导、知识库骨架生成），并**引导管理员完成必须人工确认的部分**（口径规则登记、阈值调整）。

## 二、设计目标

1. **自动化**：新增数据源时自动完成 Schema 分析、通用异常检测能力接入、知识库骨架生成；
2. **可引导**：对必须人工确认的领域规则（口径/阈值），提供明确的配置引导与模板；
3. **渐进增强**：数据源从「基础异常检测」→「领域感知异常检测」随管理员配置逐步升级；
4. **零硬编码**：异常扫描引擎不再绑定特定数据源 ID，全部能力按数据源配置驱动。

## 四、详细设计

### 4.1 Schema 深度分析增强（`server/datasource/schemaAnalyzer.ts`）

在现有 `extractDbSchema` 基础上增加分析维度：

```typescript
interface SchemaAnalysis {
  // 已有
  tables: AssembledTable[];
  
  // 新增分析结果
  analysis: {
    /** 时序表识别：含日期分区列的表 */
    timeSeriesTables: {
      tableName: string;
      dateColumn: string;        // 识别到的日期列名
      dateColumnType: 'date' | 'datetime' | 'string';
      partitionPattern: 'monthly' | 'daily' | 'unknown';  // 从列名/注释推断
    }[];
    
    /** 快照表识别：表名/注释含快照语义 */
    snapshotTables: {
      tableName: string;
      snapshotColumn: string;    // 快照日期列
      evidence: string;          // 识别依据（表名含"snapshot"/注释含"月末"等）
    }[];
    
    /** 版本字段识别：枚举值少且含版本语义 */
    versionFields: {
      tableName: string;
      columnName: string;
      distinctValues: string[];  // 采样得到的枚举值（如 ['0','1','2']）
      suggestedFilter: string;   // 建议过滤条件（如 "BB = '1'"）
    }[];
    
    /** 主键/去重字段识别 */
    uniqueFields: {
      tableName: string;
      columnName: string;
      fieldType: 'primary_key' | 'business_key';  // 主键 vs 业务编号
    }[];
    
    /** 金额字段识别（用于阈值推导） */
    amountFields: {
      tableName: string;
      columnName: string;
      suggestedUnit: '元' | '万元' | '亿元';  // 从注释/样本值推断
    }[];
  };
}
```

**识别规则**（启发式，可配置）：

| 识别目标 | 规则 |
|----------|------|
| 时序表 | 含 `*_rq`/`*_date`/`*_month`/`report_date` 等日期列，或注释含「月末/日报/快照」 |
| 快照表 | 表名含 `snapshot`/`_snap`/「快照」，或注释含「月末快照/时点快照」 |
| 版本字段 | 列名含 `bb`/`version`/`版本`，且采样 distinct 值 ≤5 个 |
| 主键字段 | 列名含 `id`/`bh`/`编号`，或 `isPrimaryKey=true` |
| 金额字段 | 列名含 `amount`/`je`/`金额`/`余额`，类型为 number |

### 4.2 通用异常检测能力自动接入

根据 Schema 分析结果，自动生成数据源级能力配置（存 `data_sources.anomaly_capabilities_json`）：

```typescript
interface AnomalyCapabilities {
  /** 时序重算能力（有时序表时启用） */
  timeSeriesRecalc: {
    enabled: boolean;
    dateColumn: string;           // 用于改写 SQL 的日期列
    maxPeriods: number;           // 默认 12（近 12 期）
  };
  
  /** 分类维度检测能力 */
  categoricalDetection: {
    enabled: boolean;
    rankChangeThreshold: number;  // 排名突变阈值，默认 3
    shareShiftThreshold: number;  // 占比偏移阈值（pp），默认 10
  };
  
  /** 口径校验能力（有快照表/版本字段时启用） */
  caliberCheck: {
    enabled: boolean;
    rules: {
      snapshotLock: boolean;      // 检查 MAX 快照锁定
      versionFilter: boolean;     // 检查版本过滤
      distinctCount: boolean;     // 检查 COUNT DISTINCT
    };
  };
  
  /** 领域阈值（默认空，需管理员配置） */
  domainThresholds: {
    enabled: boolean;
    thresholds: DomainThreshold[];  // 初始为空数组
  };
}
```

**自动启用逻辑**：
- 有时序表 → `timeSeriesRecalc.enabled = true`
- 有分类维度（category 类型列）→ `categoricalDetection.enabled = true`
- 有快照表或版本字段 → `caliberCheck.enabled = true`（对应规则开启）
- `domainThresholds.enabled = false`（必须人工配置）

### 4.3 知识库骨架自动生成

根据 Schema 分析结果，自动生成知识库条目（存 `knowledge_entries`，`status='ACTIVE'`，`category='自动生成'`）：

| 触发条件 | 生成条目 | 内容要点 |
|----------|----------|----------|
| 总是 | 「数据源概览」 | 表数量、核心表清单、行数规模 |
| 有时序表 | 「时间维度查询注意事项」 | 日期列名、分区模式、建议用 MAX 锁定最新期 |
| 有快照表 | 「快照口径说明」 | 快照表特性（静态/不跨期累加）、正确查询方式 |
| 有版本字段 | 「版本过滤说明」 | 版本字段含义、建议过滤条件 |
| 有金额字段 | 「金额单位说明」 | 识别到的金额字段、建议单位 |

**示例**（快照表识别后生成）：

```markdown
## 快照表口径说明

本数据源包含月末快照表 `fct_jc_main_biz_stat`（报告日期列：`BBRQ`）。

**快照表特性**：
- 每月末生成静态快照，反映该时点状态
- 不跨月累加：查询「最新」数据需用 `MAX(BBRQ)` 锁定
- 错误示例：`WHERE BBRQ >= '2026-01-01'`（会包含多个月末快照，重复累计）

**正确查询方式**：
```sql
SELECT * FROM fct_jc_main_biz_stat
WHERE BBRQ = (SELECT MAX(BBRQ) FROM fct_jc_main_biz_stat)
```
```

### 4.4 领域规则模板预填（铁律）

根据 Schema 分析结果，自动预填铁律模板（存 `iron_rules`，`status='PENDING'` 待确认）：

| 触发条件 | 铁律模板 | 内容 |
|----------|----------|------|
| 有快照表 | 「最新快照锁定」 | 查询 `{tableName}` 时必须用 `MAX({dateColumn})` 子查询锁定最新快照期 |
| 有版本字段 | 「版本过滤」 | 查询 `{tableName}` 时必须添加 `WHERE {versionColumn} = '{suggestedValue}'` |
| 有主键字段 | 「去重计数」 | 统计 `{tableName}` 的记录数时必须用 `COUNT(DISTINCT {uniqueColumn})` |
| 有时序表 | 「时间维度一致性」 | 涉及时间对比时，确保使用同一时间粒度（月/日） |

**管理员确认流程**：
1. 数据源保存成功后，前端展示「自动化配置报告」弹层；
2. 「待确认」区列出预填的铁律模板（含识别依据）；
3. 管理员可「一键确认全部」/「编辑后确认」/「忽略」；
4. 确认后铁律状态改为 `ACTIVE`，立即生效。

### 4.5 领域阈值配置引导

在「自动化配置报告」的「建议」区，引导管理员配置领域阈值：

```
💡 建议配置领域阈值以获得更精准的异常检测：

检测到以下金额字段，可配置阈值规则：
- fct_jc_main_biz_stat.YQJE（逾期金额）：建议配置分级阈值
  [配置阈值] → 跳转「系统管理 → 规则治理 → 语义指标」
```

**阈值配置方式**（复用现有语义指标层）：
- 管理员在「语义指标」面板为指标配置 `thresholds_json`（新增字段）；
- 异常扫描时，命中阈值直接定级并携带业务归因。

### 4.6 异常扫描引擎改造（通用化）

`server/report/anomalyScan.ts` 不再硬编码数据资源库规则，改为：

1. **加载数据源能力配置**：`SELECT anomaly_capabilities_json FROM data_sources WHERE id = ?`
2. **按能力执行检测**：
   - `caliberCheck.enabled` → 执行口径校验（规则从 `iron_rules` 表加载 ACTIVE 规则）
   - `timeSeriesRecalc.enabled` → 执行时序重算
   - `categoricalDetection.enabled` → 执行分类维度检测
   - `domainThresholds.enabled` → 执行领域阈值检测
3. **知识库注入**：LLM 归因时检索该数据源的知识库条目（含自动生成的骨架）

### 4.7 数据资源库迁移

将数据资源库的硬编码规则迁移为配置：

1. **四红线** → 迁移为 `iron_rules` 表的 4 条 ACTIVE 规则（`data_source_id='ds_1786620486498'`）；
2. **领域阈值** → 迁移为语义指标的 `thresholds_json` 配置；
3. **知识库** → 已有 5 条知识条目保留，标记为「人工维护」（区别于自动生成）；
4. 迁移脚本：`scripts/migrate-data-resource-rules.ts`（幂等，已存在则跳过）。

## 六、验收标准

1. **自动化配置**：新增 MySQL 数据源（含快照表+版本字段）→ 自动识别并生成知识库骨架 + 预填铁律模板；
2. **能力接入**：有时序表的数据源 → 异常扫描自动启用时序重算能力；
3. **铁律确认**：管理员确认预填铁律后 → 异常扫描执行口径校验；
4. **知识库生效**：自动生成的「快照口径说明」知识条目 → 问数时检索注入；
5. **数据资源库迁移**：迁移脚本执行后 → 四红线规则在 `iron_rules` 表中可查且 ACTIVE；
6. **通用化**：异常扫描引擎不再硬编码 `ds_1786620486498`；
7. 门禁全绿；文档同步完成；提交推送双远程。

## 七、风险与缓解

| 风险 | 缓解 |
|------|------|
| Schema 启发式识别误判（如把普通日期列识别为快照分区列） | 识别结果仅作为「建议」，铁律模板需管理员确认才生效；提供「重新分析」按钮 |
| 自动生成知识库质量不高 | 标记为「自动生成」类别，管理员可编辑/删除；LLM 检索时优先级低于人工维护条目 |
| 数据资源库迁移后规则重复 | 迁移脚本幂等（按 `data_source_id + title` 唯一约束跳过已存在规则） |
| 新增数据源无领域阈值 → 异常检测精度低 | 明确引导管理员配置阈值；通用统计检测仍可用 |
| 铁律模板确认增加管理员操作成本 | 提供「一键确认全部」；识别准确率高时几乎无需编辑 |

## 八、与异常扫描优化设计的关系

本设计是 [报表异常扫描优化设计20260927.md](./报表异常扫描优化设计20260927.md) 的**前置依赖**：
- 异常扫描引擎的「口径校验」「领域阈值」能力依赖本设计的数据源级配置；
- 实施顺序：先完成本设计（自动化配置），再实施异常扫描优化（通用化引擎）；
- 数据资源库作为「已配置完成」的示例数据源，验证通用化引擎的正确性。
