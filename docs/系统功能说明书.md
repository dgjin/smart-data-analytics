## 1. 系统概述

智能问数分析系统是一个面向企业的**自然语言数据分析平台**（NL2SQL）。用户用中文提问，系统自动理解语义、匹配数据表结构、生成并执行 SQL，再将真实查询结果转化为图表、KPI 与洞察解读，最终可一键产出高管决策简报。

核心能力：

- **多源数据集成**：接入 MySQL / PostgreSQL / Greenplum / CSV / Excel / JSON / API 等数据源
- **自然语言交互**：中文提问自动转 SQL（NL2SQL），支持歧义澄清
- **自动可视化**：根据查询结果智能推荐图表并输出归因诊断
- **决策简报**：一键自动生成面向高管的分析报告（可导出 PDF）
- **企业级安全**：角色权限、输入防护、限流、审计、敏感列过滤

## 3. 功能模块详解

### 3.1 智能问答与查询（NL2SQL）

系统核心功能，位于左侧导航「智能问答与查询」。

**使用流程**

1. 在顶部选择当前数据源（Header 数据源切换器）。
2. 在输入框用中文提问，例如「各类型客户的数量是多少？」。
3. 提交后系统流式返回处理阶段，最终给出 SQL、数据表、图表与解读。

**关键能力**

- **SSE 流式进度**：请求以 `stream:true` 提交，服务端通过 Server-Sent Events 推送阶段事件：
  - `understanding` 正在理解问题语义并匹配数据字段
  - `introspecting` 数据自省中，确认真实取值
  - `executed` SQL 已执行，返回行数
  - `analyzing` 正在基于真实数据生成洞察
- **歧义澄清**：当问题存在多种理解时，系统不直接执行 SQL，而是返回澄清问题与候选理解，由用户确认后重新提交。
- **语义缓存**：相同/等价问题（归一化后）在 10 分钟内命中缓存，秒级返回，审计状态记为 `CACHE`。
- **few-shot 样例注入**：系统从 SQL 样例库挑选与当前问题最相似的「问题-SQL」对，以 user/assistant 消息对形式注入上下文，提升生成准确率。
- **数据自省**（可选）：开启后，模型可先执行一条探查 SQL 确认真实取值，再据此生成最终 SQL。详见 3.6。
- **推导过程记录与可视化**：每次问数全程埋点（traceId），步骤含圈表、知识库命中、自省、SQL 生成/重试、执行、阶段二解读（各带 SQL、行数、耗时）；查询中展示横向步骤器，完成后可在消息内展开「推导过程」垂直时间线回放；`GET /api/query/trace/:traceId` 仅本人或 ADMIN 可查。
- **三级数据溯源**（P0-3）：消息卡片「查看生成的 SQL」弹窗升级为「指标口径卡 → 表关联图 → SQL/原始数据」三级链路（SQLPreviewModal，各级可折叠）——**L1 指标口径卡**：加载该数据源语义指标（`GET /api/metrics`）并按 SQL 文本/列中文表头匹配命中项，展示权威口径表达式、来源表、固定过滤、审批状态徽标（待审批/已生效/已驳回/已停用）与版本号，并可展开单指标版本历史（`GET /api/metrics/:id/versions`，含版本/动作/操作人/时间）；**L2 表关联图**：前端正则解析 SQL 血缘（`src/utils/sqlLineage.ts`：剥离注释与字符串字面量后提取主表 + JOIN 链 + ON/USING 条件），渲染表卡片与 JOIN 类型徽标；**L3 SQL 与原始数据**：完整 SQL（保留 AI 解释/优化与重跑能力）+ 查询返回的原始数据行预览（前 15 行，中文表头）。头部标注数据来源（真实/演示）。
- **计划模式**（可选开关，持久化）：开启后提问先由 LLM 生成分析计划（编号步骤/涉及表，不执行），展示计划卡片供批准；批准后携带 planId 提交执行，计划 10 分钟有效、一次性消费，过期/篡改/问题不匹配返回 409。
- **深度分析（中间表清洗链）**（自动触发 + 可选开关强制）：复杂问题先经复杂度评估，多步骤清洗（去重/标准化/过滤/聚合）逐步在源库 SELECT 并物化为应用库物理中间表 `ait_*`（注册表登记，TTL 24 小时，每用户最多 10 张，写入前剔除敏感列），最终 SQL 仅引用中间表时改在应用库执行；清洗链失败不阻断主链路。仅 mysql/postgresql/greenplum 数据源启用。
- **反馈与自学习**：对结果点赞（UP）会自动将该问答沉淀进 SQL 样例库（auto_train），点踩（DOWN）记录负反馈。
- **模型自选**：输入框旁提供模型下拉（目录来自 `GET /api/system/models`，Ollama 实时列已安装模型），选择随提问生效并持久化到浏览器；不同模型的结果缓存互相隔离。
- **结果全屏查看**（v0.9.38）：结果区顶部工具条（「分析结果 · 共 N 行」+ 全屏按钮）点击进入 fixed 全屏叠层，完整呈现 KPI/AI 归因洞察/图表/明细表四部分——图表高度 320px→560px、明细分页 10 行/页→50 行/页，吸顶栏显示提问原文；图表定制工具栏（类型/主题/同环比/固化到看板）在全屏内照常可用；Esc 或「退出全屏」按钮关闭，叠层期间锁定背景滚动。普通态与全屏态复用同一份结果 JSX（renderResultBody(full)），两态展示内容严格一致，仅尺寸与分页密度不同。
- **表头与说明强制中文**（v0.9.39）：铁律「统计分析呈现的表头及说明必须使用中文」由「提示词约束」升级为「提示词 + 服务端兜底」双保险——LLM 未遵守时，系统在返回结果前将表格表头（columnNames）、图表轴名/标题、推导过程与 AI 解读/洞察/KPI/建议追问中残留的英文表名/列名自动替换为数据源 Schema 中维护的业务中文名（标识符边界匹配 + 长名优先，不误伤包含关系）；表头组装层同时拦截「LLM 英文占位值盖掉 Schema 中文底」（override 值不含中文时不得覆盖已有中文表头）。实现上 buildIdentifierNameMap / replaceIdentifiersWithChinese 自报表链路（v0.5.1）下沉至 liveQueryUtils 供问数/报表双链路复用，阶段二解读 prompt 新增英文标识符禁令；无法映射的自定义别名保持原值（如实兜底，不编造中文名）；v0.9.42 起派生英文列名（LLM 自造别名、Schema 无映射，如 recovery_ratio_pct）经 inferChineseHeader 按内置统计/金融词根表推断中文表头兜底（蛇形/驼峰拆词、全词根命中才转换，如 recovery_ratio_pct → 回收比率（%），任一词根未识别保持原值不编造），阶段一 prompt 同步强制派生列必须给中文业务名。
- **降级兜底**：当 LLM/数据库不可用时，返回带明确标识的示例数据，保证界面不白屏。
- **专家角色库化管理**（v0.9.40 库化 / v0.9.43 内容升级）：问数专家视角（角色标签 / 触发关键词 / rolePrompt）由代码常量升级为数据库可维护——管理员在「系统管理 → 专家角色」维护，保存即时生效（60 秒缓存 + 写操作即时失效）；路由按优先级（sortOrder 升序）对提问做关键词包含匹配，无命中回落 default 兜底角色，库查询异常自动回退内置常量路由（降级不撒谎）；default 兜底角色强制关键词为空、始终生效、优先级最大（仅名称与提示词可改），内置角色禁止删除。v0.9.43 将内置 5 角色提示词由一句话身份设定升级为完整「角色定位 + 四大分析维度框架 + 输出要求 + 术语规范」结构（对齐业务方 role.md，输出要求与阶段二 JSON 契约对齐），关键词按行业术语扩充（risk 20 个 / customer 16 个 / finance 17 个 / npl 13 个）；rolePrompt 上限由 500 提至 2000 字（表列同步扩容 VARCHAR(2000)）；内置内容版本化（content_version 列 + BUILTIN_PERSONA_CONTENT_VERSION），版本升级时启动后一次性刷新内置角色的标签/关键词/提示词，管理员的再编辑与状态/优先级设置不被覆盖。
- **金额单位口径全链路一致**（v0.4.5 单位自选 / v0.9.41 解读口径修复）：问数输入区可选 亿元/百万元/万元/元，单位进缓存键防口径互串；阶段一用户消息首位注入【金额单位约定】（SQL 按除数换算 + 别名带单位后缀），v0.9.41 起声明「界面选定等同用户明确要求，优先于金额原值保护」解除与 system 规则的指令冲突；阶段二解读 system 与 user 双注入口径事实（数值已按该单位换算、禁止任何换算或进位改写、KPI 引导带该单位），可视化报表链路 buildReportStage2System 同步注入。

### 3.2 可视化决策报表

一键自动生成面向高管的分析简报，位于「可视化决策报表」。

- 自动生成执行摘要、关键指标、图表与结论建议；数据库型数据源走真实数据双阶段（查询计划 → 真实执行 → 真实数据摘要撰写）。
- **业务口径注入**（P2-14 / v0.9.19）：阶段一 SQL 生成与问数同一知识口径——报表主题+额外要求命中登记指标时注入语义层权威口径，并经知识库 RAG 检索业务知识片段（口径红线/枚举写法/计算规则）一并注入（同一检索函数与 token 预算，相关性阈值过滤无关片段）；检索失败或为空降级不注入，不阻断报表生成。
- **生成效率**（v0.9.20，对照智能问数效率提升方案）：多条查询计划**并行**过安全执行层（墙钟≈最慢一条而非逐条相加；连接池按场景分级配额排队兜底，chain 默认 5/export 默认 2 并发上限自动排队），汇总保持计划原顺序（executedSqls 与图表索引严格对齐，下钻依赖）；阶段二报表撰写接入 `LLM_ANALYSIS_ENGINE`/`LLM_ANALYSIS_MODEL` 快速模型路由（与问数阶段二同一机制，未配置时保持主模型可一键回退）。
- **报告计划模式**（可选开关，持久化）：开启后先由 LLM 生成报表查询计划（每图标题/目的/SQL，不执行），批准后携带 reportPlanId 生成；计划 10 分钟有效、一次性消费，过期/越权/数据源或模板不匹配返回 409。
- **下载 PPT**：服务端 pptxgenjs 组装 PPTX（封面/高管摘要/KPI 页/每图一页/结论页），图表由前端 SVG 转 base64 PNG 提交（`POST /api/report/export`，独立 20MB body 限额）。
- **导出 PDF**（v0.5.3 起改用 ReportLab）：服务端 Python ReportLab 原生排版（矢量文本、非截图），A4 竖版/横版可选，中文内置 CID 字体无乱码，内容完整无错位遮挡；图表由前端 ECharts 转 base64 PNG 提交（`POST /api/report/export-pdf`）；另支持打印友好模式（window.print）。
- **下载 Excel**（P0-2）：服务端 exceljs 组装 XLSX 三工作表（高管摘要（含洞察与建议）→ 核心 KPI → 图表与解读（嵌入 PNG，无图走文字兜底）），`POST /api/report/export-excel`（复用 normalizeExportData 归一化 + 独立 20MB body 限额 + 服务端注入导出水印）；适合报表数据的二次加工。
- **下载 Word**（P0-2）：服务端 docx 组装 DOCX（标题 + 执行摘要 + KPI 表格 + 图表 PNG 嵌入 + 结论建议），`POST /api/report/export-word`（同归一化与水印链路）；图文混排、面向正式报送与二次编辑，中文字体声明式使用无需服务端字体文件。
- **图表同/环比对比**：柱/折线/面积图工具栏与报表全局开关支持同比（YoY）/环比（MoM）基线对比与差异百分比标记；仅时间序列维度（年/月/日/季度等按序排列）可用，机构名等分类维度自动禁用，避免跨维度错配对比。
- **图表点击下钻**（P2-2）：live 链路的柱状/折线/面积图支持点击某个维度值下钻明细——后端基于该图表的原聚合 SQL（AST 提取 FROM/JOIN/WHERE，去聚合改 `SELECT *`，追加 `维度列 = 点击值`，LIMIT 50）真实执行并返回最多 50 行明细（`POST /api/query/drill`），行级权限仍强制注入；仅 ADMIN/ANALYST 可用。
- 支持对图表添加评论与批注（ChartCommentSection）。
- **历史报表服务端持久化**（v0.9.23）：生成的历史报表保存到后端 MySQL `saved_reports` 表（report_id 唯一约束 / user_id / username / data_source_id / template_type / data_provenance / report_data 完整 JSON / created_at / updated_at），替代原浏览器 localStorage（zustand persist）存储——跨设备、清理浏览器缓存后报表不丢失。REST API 挂载 /api/saved-reports：GET 列表（所有登录用户可见，可按数据源过滤；决策报表为团队共享简报）/ POST 创建（ADMIN/ANALYST，report_id 冲突 409 幂等）/ PUT 整体替换（重新生成场景，ADMIN/ANALYST 且仅本人或 ADMIN）/ PUT /:id/comments 仅更新批注（所有登录用户可协同批注）/ DELETE 删除（仅本人或 ADMIN，越权统一 404 防探测）。前端 store 为服务端数据的内存镜像：乐观更新 + 失败回滚（创建场景例外——生成成本高，保存失败保留本地并明确提示「刷新后将丢失」）；更新遇 404 自动降级 POST 补建。存量迁移：首次进入报表页自动将 localStorage 旧报表逐条 POST 迁移（内置演示报表除外，409 幂等吸收重复迁移），完成后 persist v5 不再写入 savedReports。内置演示报表（report-demo-1）改为纯前端展示（不落库），删除仅本地隐藏（persist 标记）。批注增删/解决状态变更自动同步服务端（fire-and-forget）。
- **历史报表维护**（v0.9.22）：历史列表支持「修改条件重新生成」与「删除」。生成时保存完整条件快照（genParams：报表主题/自定义要求/金额单位，数据源沿用报表平铺字段）；重新生成编辑器以快照预填（旧版报表回退平铺 customPrompt 与当前默认模板/单位），修改后复用异步生成端点重跑并就**就地替换**原报表（保留报表 id 与已有批注，createdAt 更新）；仅真实数据源（live）报表且 ADMIN/ANALYST 可重新生成，演示报表禁用并提示。删除需确认，删除后当前查看索引自动钳制。数据变化自动重生成（v0.4.8）同步改用条件快照取参，修复此前错用当前模板选择的口径漂移；重新生成编辑器打开/执行期间自动重生成暂停（互斥防覆盖）。

### 3.3 决策数据看板

固化指标图表与看板展示（CustomDashboard），适合日常巡检与大屏投放，所有角色可见。

- **图表固化与自主更新**：问数/灵活查询/指标直查的图表可固化至看板；带 sourceSql 的固化图表参与数据变化自动重放刷新（v0.4.8）。
- **语义指标直查**（P2-14，ADMIN/ANALYST）：选「数据源 + 已生效语义指标 + 可切分维度」即直出结果，口径与问数/报表共享同一语义层定义；结果可一键固化至看板。
- **金额单位口径**（v0.9.21）：直查金额类指标（指标名/口径说明/表达式命中金额关键词，且非 COUNT 类计数）默认跟随 Header 全局金额单位换算，面板内可模块级覆盖（优先于全局）；换算在 SQL 层完成（`ROUND(聚合表达式/除数, 2)`），结果区与固化卡片标题均标注单位；COUNT 类计数与「元」原值口径不换算。
- **看板图表服务端持久化**（v0.9.24）：固化图表从浏览器 localStorage（zustand persist）迁至 MySQL `dashboard_widgets` 表（widget_id 唯一约束 / user_id / username / widget_data 完整 JSON / sort_order / created_at / updated_at）——跨设备、清理缓存不丢失，团队共享同一看板。REST API 挂载 /api/dashboard-widgets：GET 列表（所有登录用户可见，按 sort_order 升序）/ POST 固化（ADMIN/ANALYST，冲突 409 幂等）/ PUT /order 批量排序（ADMIN/ANALYST）/ PUT /:id 整体替换（ADMIN/ANALYST，标题/布局调整与 v0.4.8 自动重放快照回写）/ DELETE（本人或 ADMIN，出厂内置仅 ADMIN，越权 404 防探测）。出厂 5 个默认图表（widget-1..5，月末快照静态数据）改为服务启动时表空 seed（user_id=0/system），行为与用户固化图表完全统一（可排序/调布局/由 ADMIN 删除）。前端 store 为服务端数据的内存镜像：initDashboardWidgets 会话一次迁移 localStorage 遗留（排除出厂 id）后拉取服务端列表；乐观更新 + 失败回滚；v0.4.8 自动重放快照更新失败（VIEWER 无写权限 403 或网络异常）仅本地生效不回滚，避免看板数字闪回；拖拽缩放 mousemove 高频调用仅本地预览（localOnly），mouseup 一次性同步。persist 升 v6 移除 dashboardWidgets 键。

**数据源类型**：MySQL、PostgreSQL、Greenplum、CSV、Excel、JSON、API。

**文件数据源真实落库**（v0.9.34，仅 ADMIN）：数据源管理页「导入本地 CSV / Excel / JSON」上传文件（本体 ≤7MB），服务端解析真实数据落应用库物理表（`upl_*`），登记为数据源后问数/报表/指标/灵活查询全部走真实执行（不再出示演示数据）。表头安全化（中文等非法表头 → f1..fN，原表头保留为字段含义注入 prompt 与结果表头中文化）；命中敏感词的列整列剔除并在导入提示中列明；行 ≤20000 / 列 ≤100 超限截断如实标注；数值占比 ≥60% 的列推断为 DOUBLE 参与指标聚合。文件数据为静态快照（源文件变更需重新导入），删除数据源时级联删除物理表。

**数据自省开关**：在数据源卡片上以紫色扫描图标切换（`allowIntrospection`），默认关闭。开启后该数据源的问数允许执行探查 SQL。

**语义指标层**（P1-1 / 治理增强 P0-4）：管理员按数据源登记结构化业务指标（名称/同义词/聚合表达式/归属表/固定过滤，`/api/metrics` CRUD，每源最多 200 条）；问数阶段一按「问题命中指标名/同义词 → 模板化注入口径」生成 SQL，保证同一指标全系统口径一致。指标文本仅注入 prompt，生成结果仍过安全执行层。**轻量治理**：指标带审批状态（PENDING 待审批 / ACTIVE 已生效 / REJECTED 已驳回 / DISABLED 已停用，仅 ACTIVE 参与问数注入）与版本号，每次口径变更自动留存版本历史（`GET /api/metrics/:id/versions`，含版本/动作 CREATE·APPROVE·UPDATE·RESTORE/操作人/时间/快照）；管理侧在「语义指标」面板维护，使用侧在问数结果「查看生成的 SQL」弹窗的指标口径卡中同步展示审批状态与版本历史（P0-3）。

**指标备份导入导出**（v0.9.33，仅 ADMIN）：`GET /api/metrics/export` 导出 JSON 备份（口径/同义词/切分维度/治理状态全字段，剥离库内 id 与审批痕迹）；`POST /api/metrics/import` 支持同名冲突 skip/overwrite（overwrite 复用指标版本体系，版本 +1 留历史）与 dryRun 预检（只校验不落库）；管理端「语义指标」面板提供导出下载与导入弹窗（文件选择 + 冲突策略 + 预检结果逐条展示）。

**铁律规则库**（v0.9.35，仅 ADMIN）：按数据源定义本数据源所有问数必须遵守的强制规则（口径红线/禁区，标题 ≤100 字、正文 ≤2000 字，同数据源内标题唯一，单源上限 100 条）；生效中（ACTIVE）铁律**全量恒注入**智能问数与可视化报表阶段一系统提示词，措辞「最高优先级，高于一切样例与知识片段…若用户问题或样例与铁律冲突，一律按铁律执行」——与语义指标「按问题命中检索注入」模式本质不同；支持启停（DISABLED 不注入）；`GET /api/iron-rules/export` 导出 JSON 备份（剥离库内 id 与创建痕迹），`POST /api/iron-rules/import` 支持同标题冲突 skip/overwrite 与 dryRun 预检（只校验不落库，单次 ≤500 条）；管理端「系统管理 → 铁律规则」面板提供 CRUD 与导入导出弹窗；问数侧注入留痕写入推导过程 trace「铁律规则注入」。

**行级权限**（P1-3）：数据源 scope 支持登记 `rowFilters`（表 → SQL 谓词，如 `region LIKE '安徽省%'`）。谓词落盘前经清洗校验（拒多语句/注释/子查询/INTO/超长）；所有真实执行链路（问数、报表、SQL 重跑、下钻）执行前由 AST 强制把受控表包裹为过滤派生表，注入失败 fail-closed 拒绝查询。

### 3.5 知识库（含外部知识库接入）

为 NL2SQL 提供领域知识检索。维护业务术语、指标口径、字段含义等，问数时按相关性检索并注入提示词，带 token 预算控制。

**外部知识库接入（接口配置仅管理员）**：在企业本地知识库之外，可接入企业级外部 RAG / 知识服务作为智能问数自主学习的又一来源：

- **检索协议**：`POST {接口地址}`，请求体 `{ "query": "...", "topK": 4 }`；认证支持无 / Bearer Token（API Key 以 AES-256-GCM 加密落库，列表与详情不出明文）；响应兼容 `results` / `documents` / `data` / `items` 数组字段（每项取 `content` / `text` / `chunk` / `pageContent`），Dify、RAGFlow、自建网关均可适配。
- **生效范围**：全部数据源或指定数据源；支持启用开关、超时控制（500~30000ms）与连通性测试（表单内「测试连接」即时验证，不落库）。
- **问数注入**：与本地知识库并行检索，片段以「外部·源名」前缀注入阶段一 prompt；独立 token 预算（1200），不挤占本地知识注入槽位；单源失败降级为空不阻断问数。
- **入口**：知识库面板底部「外部知识源接入」卡片（仅 ADMIN 可见），提供接入/编辑/删除/测试；管理接口 `/api/knowledge-external` 全部仅 ADMIN。

### 3.6 SQL 样例库（Training Data）

管理「问题-SQL」训练样例，是 few-shot 注入与自学习的数据基础。

- **来源类型**：`MANUAL`（手工登记）、`FEEDBACK_UP`（点赞自动沉淀）、`IMPORT`（批量导入）。
- **登记/编辑/剔除**：支持对单条样例增删改。
- **批量导入冷启动**：粘贴多条 SQL 脚本，系统调用 LLM 逐条反推一句中文问题，可编辑预览后批量入库（问题留空则跳过）。
- **备份导入导出**（v0.9.33，仅 ADMIN）：`GET /api/sql-examples/export` 导出 JSON 备份（含问题/SQL/来源标记）；`POST /api/sql-examples/import` 支持同问题冲突 skip/overwrite/append 三策略（导入新增统一记 IMPORT 来源）与 dryRun 预检；面板提供导出下载与导入弹窗。
- 样例仅允许 `SELECT` 语句，长度受限（问题 ≤500 字、SQL ≤2000 字）。

### 3.7 数据自省（Data Introspection）

数据源级能力（默认关闭）。开启后，问数第一阶段模型可输出第三种契约：

```json
{ "needIntrospection": true, "intermediateSql": "SELECT DISTINCT ... LIMIT 30", "note": "..." }
```

系统真实执行该探查 SQL，把最多 30 行结果回喂模型，再生成最终 SQL，用于解决「取值不确定」导致的歧义。仅在首次尝试的首个候选上允许一轮，防止递归。

### 3.13 可观测性：Prometheus + Grafana 监控（v0.9.15 新增）

系统内置 Prometheus 指标暴露与配套监控栈，用于问数链路的趋势观测与告警（与 `query_audit_log` 审计明细双轨互补：Prometheus 管趋势/告警，审计表管个案追溯）。

- **指标端点**：`GET /metrics`（基础设施端点，不走 JWT，不参与 OpenAPI 校验；可选环境变量 `METRICS_TOKEN` 开启 Bearer/query token 保护）。
- **业务指标**（单点旁路埋点，fail-open 不影响业务链路）：
  - `nl2sql_requests_total{status,endpoint}` / `nl2sql_duration_seconds{status}`——埋于 `writeAudit`，覆盖 SUCCESS/CACHE/FALLBACK/REFUSED/CLARIFY/ERROR/DENIED_* 全终态；
  - `nl2sql_cache_hits_total{layer}`——L1 归一化精确 / L2 语义命中（L2 内部取载荷不计 L1，避免双计）；
  - `llm_call_duration_seconds{channel,engine,model,ok}` / `llm_tokens_total{channel,model,type}`——埋于 `recordLlmUsage`，model label 天然区分快速/主模型；
  - `sql_execute_duration_seconds{result}`——`executeSafeSql` 包装计时；
  - `http_request_duration_seconds{method,route,status}`——仅 `/api/*`（规避 Vite 静态资源高基数），route 取路由模式而非实际路径；
  - 另有 prom-client 默认 Node 运行时指标（事件循环 lag、堆内存、GC）。
- **基数红线**：question/userId/dataSourceId 不进 label。
- **监控栈**：`docker-compose.monitoring.yml` 一键起 Prometheus（:9090，保留 30d/2GB）+ Grafana（:3100）+ node/redis/mysql exporter；仪表盘即代码（`deploy/grafana/dashboards/` provisioning 自动加载）。项目名内嵌（`name: nl2sql-monitoring`，规避中文目录名解析为空）；mysql-exporter 凭据经 `.my.cnf` 挂载注入（v0.16+ 已移除 DATA_SOURCE_NAME 环境变量支持，默认读 `~/.config/nl2sql-monitoring/my.cnf`，`MYSQL_EXPORTER_CNF` 可覆盖，密码不落库）；redis-exporter 用独立变量 `REDIS_EXPORTER_ADDR`（容器内不可复用应用侧 localhost 地址）；Alertmanager 的 `ALERT_WEBHOOK_URL` 经 `deploy/alertmanager-entrypoint.sh` 启动时渲染模板注入（AM 无原生 env 展开能力）。
- **告警（P1）**：`deploy/prometheus-alerts.yml` 9 条规则分三组——可用性（应用/MySQL/Redis 宕机）、业务（成功率 <85%、P95 >180s、缓存命中率 <15% 带流量门槛防夜间误报、FALLBACK 率 >15% 对照 7.9% 基线）、资源（进程内存 >1.5GiB、磁盘 >85%）；Alertmanager（:9093）经 Webhook 通知（`ALERT_WEBHOOK_URL` 环境变量，未配置走黑洞仅 UI 可见），含抑制规则（应用宕机时抑制连锁业务告警防风暴）。
- **仪表盘（4 张）**：总览（北极星 4 stat + 状态分布/LLM 分模型时延/缓存分层/SQL vs LLM 瓶颈对比）、问数业务明细（全终态趋势/时延分位/澄清拒答占比/DENIED 拦截）、LLM 性能（分模型 P50/P95/调用占比/token 吞吐/失败调用）、基础设施（采集目标在线状态/Node 内存与事件循环 lag/MySQL 连接 QPS 慢查询/Redis 内存键数命中率/CPU 磁盘）。
- **对账校验（P2）**：`npm run metrics:reconcile [-- --window=120]`——Prometheus `increase(nl2sql_requests_total)` 与 `query_audit_log` 按状态逐行对账（同一 writeAudit 路径应两侧一致），窗口自动钳制到应用进程启动后（计数器重启清零语义），容差 max(2, 5%)；退出码 0 一致 / 1 不符 / 2 基础设施不可达，用于月度口径审计与埋点回归排查。
- **监控栈自监控（P2）**：4 条规则——Prometheus 活跃序列 >40 万（基数失控预警）、告警规则求值失败、抓取耗时 >10s、Alertmanager 宕机（prometheus.yml 增 alertmanager 抓取 job 支撑）。
- **多实例抓取拓扑（P2）**：`docker-compose.multi-instance.yml` 的 app1/app2 已映射宿主端口 3001/3002，prometheus.yml 注释区给出多目标 job 模板；进程内计数器按 instance label 区分，仪表盘 sum() 聚合口径不变。

### 3.14 异常巡检中心（P0-1 新增）

侧边栏「异常巡检」入口，数据源级巡检计划管理 + 异常预警结果展示（PatrolCenter）。把「你问它答」的问数升级为「它主动盯」的主动洞察最小闭环：按周期自动扫描数据源最新真实数据报表，发现指标异常波动主动预警。

- **巡检计划**：绑定数据源 + 巡检间隔（1 小时 ~ 7 天，UI 提供 每小时/每 6 小时/每 12 小时/每天/每周 档位），计划名可空（默认「数据源名 巡检」）；创建/修改/启停/删除限 ADMIN/ANALYST 且仅创建人或 ADMIN 可维护（越权统一 404 防探测）；计划含 last_run_at / next_run_at / last_run_status / last_anomaly_count 快照，卡片直接呈现「上次巡检/下次巡检/最近异常数」。
- **巡检引擎**（`server/anomalyPatrol.ts`）：内置调度器随服务启动（与 v0.9.2 异步任务队列同类内置 worker，不引入外部 cron；tick 级防重入由闭包守卫），按 next_run_at 到期原子领取（UPDATE 条件推进排期，多实例不重复执行）；单次巡检扫描该数据源最新一份 live 决策报表（saved_reports），复用报表异常检测引擎（Z-Score 偏离 / 阈值越界）逐指标检测，异常明细（指标名/当前值/偏离幅度/严重程度 high·medium·low）落 `patrol_runs` 运行历史；无 live 报表时如实记 NO_DATA 不误报。
- **API**（`/api/patrols`，全部登录鉴权）：GET / 列表（可按数据源过滤）；POST / 新建（ADMIN/ANALYST）；PUT /:patrolId 更新（名称/间隔/启停）；DELETE /:patrolId 删除（连同运行历史）；POST /:patrolId/run 立即执行（限流 + 不改既有排期）；GET /:patrolId/runs 运行历史。全部写操作写审计（endpoint=patrol）。
- **前端**（PatrolCenter）：计划卡片（状态徽标 巡检中/已暂停、周期、上次/下次巡检、最近状态徽标 发现异常/正常/无可扫描报表/执行失败 + 异常数）、新建表单、立即巡检/暂停/启用/运行历史/删除操作；运行历史弹窗逐条展示结论与异常明细（严重度着色）；所有登录用户可查看巡检结果，计划维护限 ADMIN/ANALYST。

## 4. 智能问数处理链路

一次提问在服务端的完整处理顺序：

1. **输入防护（L1）**：`queryGuard` 500 字截断 + 注入检测。
2. **鉴权与角色**：仅 `ADMIN`/`ANALYST` 可问数。
3. **限流**：`rateLimiter` + 每用户查询配额 + 并发槽位（进行中查询互斥）。
4. **Schema 上下文加载**：落库 schema → scope 白名单 → 敏感列过滤 → 5 分钟缓存。
5. **语义缓存**：命中则直接返回（`CACHE`）。
6. **生命周期钩子**：`emitBeforeQuery`。
7. **圈表**：关键词粗排 + embedding 精排（`selectRelevantTablesAsync`），embedding 不可用时降级纯关键词。
8. **上下文并行构建**：few-shot 样例（团队库 top-3 + 个人对话沉淀）、本地知识库 RAG、**外部知识库检索**、语义指标命中、**铁律规则全量注入**、点踩反例七者并发执行（各自失败降级不阻断）；知识类注入带 token 预算截断，推导过程 trace 中记录「外部知识库 N 字（成功 M 源）」。
9. **复杂度评估与清洗链**：LLM 判定 simple/multi-step；多步或「深度分析」开关开启时执行中间表清洗链（物化 `ait_*` 至应用库），失败不阻断。
10. **阶段一 SQL 生成**：可能触发歧义澄清或数据自省；携带已批准计划（planId）时按计划执行并跳过澄清。
11. **安全执行**：`executeSafeSql` 仅放行只读查询；SQL 仅引用已注册 `ait_*` 时改在应用库执行（白名单校验）。
12. **阶段二分析**：基于真实数据生成解读与图表配置。
13. **审计落账（L6）**：记录状态 `SUCCESS`/`FALLBACK`/`CLARIFY`/`CACHE`/`DENIED_*`。
14. **生命周期钩子**：`emitAfterQuery`。

全链路各步骤同步写入 `query_trace`（推导过程回放数据源）。

## 5. AI 引擎

- LLM 通道统一收敛在 `server/llmClient.ts`，支持三引擎：**Ollama**（本地）、**通义千问百炼**（OpenAI 兼容协议）、**Gemini API**。
- 引擎选择优先级：**用户自选（请求级，AsyncLocalStorage 传递）> `AI_ENGINE` 显式指定 > 密钥存在性自动 > Ollama**。
- 用户自选：问数输入框旁的模型下拉，目录由 `GET /api/system/models` 给出；非法引擎/模型名返回 400；选择写入请求体 `model: {engine, model}` 并纳入结果缓存键。
- 当前主引擎：`Ollama qwen3.8:27b-mlx`（本地 MLX 优化版，`AI_ENGINE=ollama`，地址由 `OLLAMA_URL` 配置，默认 `http://localhost:11434`）；阶段路由全本地——简单单表 SQL 生成与数据解读分流本地 `qwen3:8b`（`LLM_SQL_*`/`LLM_ANALYSIS_*`），复杂/多表 SQL 强制主模型保口径（v0.8.1 分档机制）；embedding 用本地 nomic-embed-text；云端 Qwen 配置保留可切回（`AI_ENGINE=qwen` + `LLM_*_ENGINE=qwen`）。注意：`deepseek-r1` 系列为推理模型，思考链分钟级，禁止用于任何阶段（会突破问数超时上限）。
- 通义千问：默认模型 `qwen3.8-max`（`QWEN_MODEL` 可改）；普通按量 Key 用默认端点，Coding Plan Key（`sk-sp-` 开头）必须配专属端点 `https://coding.dashscope.aliyuncs.com/v1`，且官方限定仅可在编程工具中使用。
- Embedding 用于圈表精排（Ollama 需本地 embedding 模型，千问用 `text-embedding-v4`），不可用时自动降级纯关键词粗排。
- 引擎信息通过 `GET /api/system/engine` 暴露给前端（不泄露内网地址），侧边栏底部有引擎运行状态指示灯。

## 6. 安全与合规

- **密钥管理**：生产环境（`NODE_ENV=production`）缺失 `JWT_SECRET` 时拒绝启动（fail-fast），防止伪造 token。
- **安全响应头**：`X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy`；生产启用 HSTS 与 CSP。
- **输入防护**：问题截断、注入检测、历史消毒。
- **只读执行**：样例与问数 SQL 强制 `SELECT` 白名单；字符串字面量在校验副本中置空防关键字干扰，但最终执行 SQL 保留原文字面量值。
- **行级权限（P1-3）**：scope.rowFilters 经 AST 强制注入为过滤派生表，覆盖子查询/UNION/JOIN，谓词非法或注入失败一律拒绝查询（fail-closed）。
- **敏感列过滤**：Schema 上下文加载时剔除敏感字段。
- **可观测性**：`requestLogger` 记录 requestId 与 API 访问日志（鉴权前，被拒请求同样留痕）；`auditLog` 记录问数审计。
- **默认回环**：服务默认绑定 `127.0.0.1`，需显式设置 `HOST=0.0.0.0` 才对外暴露。
