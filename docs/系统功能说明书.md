## 1. 系统概述

智能问数分析系统是一个面向企业的**自然语言数据分析平台**（NL2SQL）。用户用中文提问，系统自动理解语义、匹配数据表结构、生成并执行 SQL，再将真实查询结果转化为图表、KPI 与洞察解读，最终可一键产出高管决策简报。

核心能力：

- **多源数据集成**：接入 MySQL / PostgreSQL / Greenplum / CSV / API / JSON 等数据源
- **自然语言交互**：中文提问自动转 SQL（NL2SQL），支持歧义澄清
- **自动可视化**：根据查询结果智能推荐图表并输出归因诊断
- **决策简报**：一键自动生成面向高管的分析报告（可导出 PDF）
- **企业级安全**：角色权限、输入防护、限流、审计、敏感列过滤

## 3. 功能模块详解

### 3.1 智能问答与查询（NL2SQL）

系统核心功能，位于左侧导航「智能问答与查询」。

**使用流程**

1. 在顶部选择当前数据源（Header 数据源切换器）。
2. 在输入框用中文提问，例如「各类型客户的数量是多少？」。
3. 提交后系统流式返回处理阶段，最终给出 SQL、数据表、图表与解读。

**关键能力**

- **SSE 流式进度**：请求以 `stream:true` 提交，服务端通过 Server-Sent Events 推送阶段事件：
  - `understanding` 正在理解问题语义并匹配数据字段
  - `introspecting` 数据自省中，确认真实取值
  - `executed` SQL 已执行，返回行数
  - `analyzing` 正在基于真实数据生成洞察
- **歧义澄清**：当问题存在多种理解时，系统不直接执行 SQL，而是返回澄清问题与候选理解，由用户确认后重新提交。
- **语义缓存**：相同/等价问题（归一化后）在 10 分钟内命中缓存，秒级返回，审计状态记为 `CACHE`。
- **few-shot 样例注入**：系统从 SQL 样例库挑选与当前问题最相似的「问题-SQL」对，以 user/assistant 消息对形式注入上下文，提升生成准确率。
- **数据自省**（可选）：开启后，模型可先执行一条探查 SQL 确认真实取值，再据此生成最终 SQL。详见 3.6。
- **推导过程记录与可视化**：每次问数全程埋点（traceId），步骤含圈表、知识库命中、自省、SQL 生成/重试、执行、阶段二解读（各带 SQL、行数、耗时）；查询中展示横向步骤器，完成后可在消息内展开「推导过程」垂直时间线回放；`GET /api/query/trace/:traceId` 仅本人或 ADMIN 可查。
- **计划模式**（可选开关，持久化）：开启后提问先由 LLM 生成分析计划（编号步骤/涉及表，不执行），展示计划卡片供批准；批准后携带 planId 提交执行，计划 10 分钟有效、一次性消费，过期/篡改/问题不匹配返回 409。
- **深度分析（中间表清洗链）**（自动触发 + 可选开关强制）：复杂问题先经复杂度评估，多步骤清洗（去重/标准化/过滤/聚合）逐步在源库 SELECT 并物化为应用库物理中间表 `ait_*`（注册表登记，TTL 24 小时，每用户最多 10 张，写入前剔除敏感列），最终 SQL 仅引用中间表时改在应用库执行；清洗链失败不阻断主链路。仅 mysql/postgresql/greenplum 数据源启用。
- **反馈与自学习**：对结果点赞（UP）会自动将该问答沉淀进 SQL 样例库（auto_train），点踩（DOWN）记录负反馈。
- **模型自选**：输入框旁提供模型下拉（目录来自 `GET /api/system/models`，Ollama 实时列已安装模型），选择随提问生效并持久化到浏览器；不同模型的结果缓存互相隔离。
- **降级兜底**：当 LLM/数据库不可用时，返回带明确标识的示例数据，保证界面不白屏。

### 3.2 可视化决策报表

一键自动生成面向高管的分析简报，位于「可视化决策报表」。

- 自动生成执行摘要、关键指标、图表与结论建议；数据库型数据源走真实数据双阶段（查询计划 → 真实执行 → 真实数据摘要撰写）。
- **报告计划模式**（可选开关，持久化）：开启后先由 LLM 生成报表查询计划（每图标题/目的/SQL，不执行），批准后携带 reportPlanId 生成；计划 10 分钟有效、一次性消费，过期/越权/数据源或模板不匹配返回 409。
- **下载 PPT**：服务端 pptxgenjs 组装 PPTX（封面/高管摘要/KPI 页/每图一页/结论页），图表由前端 SVG 转 base64 PNG 提交（`POST /api/report/export`，独立 20MB body 限额）。
- **导出 PDF**：基于 html2pdf.js 高清导出（可选横纵向/明暗主题）；另支持打印友好模式（window.print）。
- **图表点击下钻**（P2-2）：live 链路的柱状/折线/面积图支持点击某个维度值下钻明细——后端基于该图表的原聚合 SQL（AST 提取 FROM/JOIN/WHERE，去聚合改 `SELECT *`，追加 `维度列 = 点击值`，LIMIT 50）真实执行并返回最多 50 行明细（`POST /api/query/drill`），行级权限仍强制注入；仅 ADMIN/ANALYST 可用。
- 支持对图表添加评论与批注（ChartCommentSection）。

### 3.3 决策数据看板

固化指标图表与看板展示（CustomDashboard），适合日常巡检与大屏投放，所有角色可见。

### 3.4 数据源与 Schema（管理员）

位于「数据源与 Schema」，包含多个子页签：

| 子页签 | 功能 |
|--------|------|
| 数据源管理 | 新增/编辑/删除数据源，测试连接，启停智能问数 |
| Schema 查看器 | 查看表结构、字段、类型、行数 |
| 数据血缘 | 展示数据流向与依赖关系（DataLineageView） |
| 知识库 | 维护业务术语、口径、指标定义，供问数时检索 |
| SQL 样例库 | 维护「问题-SQL」训练样例（Training Data） |

**数据源类型**：MySQL、PostgreSQL、Greenplum、CSV、API、JSON。

**数据自省开关**：在数据源卡片上以紫色扫描图标切换（`allowIntrospection`），默认关闭。开启后该数据源的问数允许执行探查 SQL。

**语义指标层**（P1-1）：管理员按数据源登记结构化业务指标（名称/同义词/聚合表达式/归属表/固定过滤，`/api/metrics` CRUD，每源最多 200 条）；问数阶段一按「问题命中指标名/同义词 → 模板化注入口径」生成 SQL，保证同一指标全系统口径一致。指标文本仅注入 prompt，生成结果仍过安全执行层。

**行级权限**（P1-3）：数据源 scope 支持登记 `rowFilters`（表 → SQL 谓词，如 `region LIKE '安徽省%'`）。谓词落盘前经清洗校验（拒多语句/注释/子查询/INTO/超长）；所有真实执行链路（问数、报表、SQL 重跑、下钻）执行前由 AST 强制把受控表包裹为过滤派生表，注入失败 fail-closed 拒绝查询。

### 3.5 知识库

为 NL2SQL 提供领域知识检索。维护业务术语、指标口径、字段含义等，问数时按相关性检索并注入提示词，带 token 预算控制。

### 3.6 SQL 样例库（Training Data）

管理「问题-SQL」训练样例，是 few-shot 注入与自学习的数据基础。

- **来源类型**：`MANUAL`（手工登记）、`FEEDBACK_UP`（点赞自动沉淀）、`IMPORT`（批量导入）。
- **登记/编辑/剔除**：支持对单条样例增删改。
- **批量导入冷启动**：粘贴多条 SQL 脚本，系统调用 LLM 逐条反推一句中文问题，可编辑预览后批量入库（问题留空则跳过）。
- 样例仅允许 `SELECT` 语句，长度受限（问题 ≤500 字、SQL ≤2000 字）。

### 3.7 数据自省（Data Introspection）

数据源级能力（默认关闭）。开启后，问数第一阶段模型可输出第三种契约：

```json
{ "needIntrospection": true, "intermediateSql": "SELECT DISTINCT ... LIMIT 30", "note": "..." }
```

系统真实执行该探查 SQL，把最多 30 行结果回喂模型，再生成最终 SQL，用于解决「取值不确定」导致的歧义。仅在首次尝试的首个候选上允许一轮，防止递归。

### 3.8 技能库（Skills）

为问数面板提供可复用的提示模板（prompt template）。

- **作用域**：`SYSTEM`（系统库，管理员维护）、`USER`（个人库，登录用户自建）。
- **分享流**：个人技能可发起分享（PENDING_SHARE），由管理员审核（approve/reject）后进入系统库。
- 技能支持占位符（placeholders），在问数面板中一键套用。

### 3.9 系统管理（管理员）

用户账号与角色权限配置（AdminPanel）：新增用户、调整角色、停用账号、重置密码等。

## 4. 智能问数处理链路

一次提问在服务端的完整处理顺序：

1. **输入防护（L1）**：`queryGuard` 500 字截断 + 注入检测。
2. **鉴权与角色**：仅 `ADMIN`/`ANALYST` 可问数。
3. **限流**：`rateLimiter` + 每用户查询配额 + 并发槽位（进行中查询互斥）。
4. **Schema 上下文加载**：落库 schema → scope 白名单 → 敏感列过滤 → 5 分钟缓存。
5. **语义缓存**：命中则直接返回（`CACHE`）。
6. **生命周期钩子**：`emitBeforeQuery`。
7. **圈表**：关键词粗排 + embedding 精排（`selectRelevantTablesAsync`），embedding 不可用时降级纯关键词。
8. **few-shot 注入**：从样例库挑选 top-3 相似样例。
9. **复杂度评估与清洗链**：LLM 判定 simple/multi-step；多步或「深度分析」开关开启时执行中间表清洗链（物化 `ait_*` 至应用库），失败不阻断。
10. **阶段一 SQL 生成**：可能触发歧义澄清或数据自省；携带已批准计划（planId）时按计划执行并跳过澄清。
11. **安全执行**：`executeSafeSql` 仅放行只读查询；SQL 仅引用已注册 `ait_*` 时改在应用库执行（白名单校验）。
12. **阶段二分析**：基于真实数据生成解读与图表配置。
13. **审计落账（L6）**：记录状态 `SUCCESS`/`FALLBACK`/`CLARIFY`/`CACHE`/`DENIED_*`。
14. **生命周期钩子**：`emitAfterQuery`。

全链路各步骤同步写入 `query_trace`（推导过程回放数据源）。

## 5. AI 引擎

- LLM 通道统一收敛在 `server/llmClient.ts`，支持三引擎：**Ollama**（本地）、**通义千问百炼**（OpenAI 兼容协议）、**Gemini API**。
- 引擎选择优先级：**用户自选（请求级，AsyncLocalStorage 传递）> `AI_ENGINE` 显式指定 > 密钥存在性自动 > Ollama**。
- 用户自选：问数输入框旁的模型下拉，目录由 `GET /api/system/models` 给出；非法引擎/模型名返回 400；选择写入请求体 `model: {engine, model}` 并纳入结果缓存键。
- 当前主引擎：`Ollama deepseek-r1:32b`（本地，`AI_ENGINE=ollama`，地址由 `OLLAMA_URL` 配置，默认 `http://localhost:11434`）；可切换云端 `Qwen qwen3.8-max`（百炼通用按量端点，带深度思考，耗时较长）。
- 通义千问：默认模型 `qwen3.8-max`（`QWEN_MODEL` 可改）；普通按量 Key 用默认端点，Coding Plan Key（`sk-sp-` 开头）必须配专属端点 `https://coding.dashscope.aliyuncs.com/v1`，且官方限定仅可在编程工具中使用。
- Embedding 用于圈表精排（Ollama 需本地 embedding 模型，千问用 `text-embedding-v4`），不可用时自动降级纯关键词粗排。
- 引擎信息通过 `GET /api/system/engine` 暴露给前端（不泄露内网地址），侧边栏底部有引擎运行状态指示灯。

## 6. 安全与合规

- **密钥管理**：生产环境（`NODE_ENV=production`）缺失 `JWT_SECRET` 时拒绝启动（fail-fast），防止伪造 token。
- **安全响应头**：`X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy`；生产启用 HSTS 与 CSP。
- **输入防护**：问题截断、注入检测、历史消毒。
- **只读执行**：样例与问数 SQL 强制 `SELECT` 白名单；字符串字面量在校验副本中置空防关键字干扰，但最终执行 SQL 保留原文字面量值。
- **行级权限（P1-3）**：scope.rowFilters 经 AST 强制注入为过滤派生表，覆盖子查询/UNION/JOIN，谓词非法或注入失败一律拒绝查询（fail-closed）。
- **敏感列过滤**：Schema 上下文加载时剔除敏感字段。
- **可观测性**：`requestLogger` 记录 requestId 与 API 访问日志（鉴权前，被拒请求同样留痕）；`auditLog` 记录问数审计。
- **默认回环**：服务默认绑定 `127.0.0.1`，需显式设置 `HOST=0.0.0.0` 才对外暴露。

## 7. 技术栈

| 层 | 技术 |
|----|------|
| 前端 | React 19 + Vite + TypeScript + Tailwind CSS 4 + Zustand + Recharts + motion |
| 后端 | Express 4 + Node.js（tsx 开发 / esbuild 打包） |

npm start            # 运行打包产物
npm test             # 运行 Vitest
