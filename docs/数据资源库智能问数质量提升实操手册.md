## 2. 四条口径红线（每条都有真实事故教训）

宽表问数的错误 90% 集中在这四类。以下每条规定都是**被真实事故验证过**的，也是后续所有资产建设的共同约束。

### R1 快照期锁定（最高优先级）

两张宽表都是**月末快照**：`fct_jc_main_biz_stat.BBRQ`、`fct_jc_financial_stat.SJRQ` 取值为月末日期，同一日期是当月全量快照。

- **禁止**：跨快照期直接 `SUM` 金额（会把 N 个月的存量余额累加 N 倍）
- **必须**：问「最新/当前/累计」一律锁定 `BBRQ = (SELECT MAX(BBRQ FROM 同表)`
- **真实事故**：8 个指标定义缺少 BBRQ 锁定，「各机构本年投放金额排名」算出 39204 亿（20 期快照累加），正确值 2318.28 亿，虚增 16 倍

### R2 版本防重

`BB` 字段：1=核算版，2=分成版（同一业务在分成版下有多行）。

- **必须**：金额汇总与笔数统计默认带 `AND BB = '1'`
- **例外**：仅当用户明确问「分成口径」时才用 BB='2'，且须在解读中说明

### R3 去重计数

客户数、项目数、业务数等计数问题，宽表一行≠一个实体。

- **必须**：`COUNT(DISTINCT XMBH)`（项目数）等，禁止 `COUNT(*)`
- **真实事故**：快速模型多表 JOIN 时漏写 `DISTINCT`，客户数 259 被虚增为 278，且同源多候选表决无法纠正此类系统性偏差（v0.8.1 已据此把复杂/多表问题强制路由主模型）

### R4 期间列与金额单位

- 投放金额三兄弟不可混用：`LJTFJE` 累计投放 / `BNTFJE` 本年投放 / `BYTFJE` 本月投放；投资收益同理（`TZSYDN` 当年 / `TZSYLJ` 累计）
- 趋势类问题（逐月走势）正确做法是**逐期取当月列**（如 `BYTFJE`）GROUP BY BBRQ，而不是对累计列跨期求和
- 金额单位遵循问数页选定单位（亿元/百万元/万元/元），换算在 SQL 层完成（除以 1e8/1e6/1e4 并 ROUND 两位）

## 3. 五大提升杠杆（按投入产出比排序）

### L1 SQL 样例库：从 0 到 20（两周内 ROI 最高的动作）—— ✅ 首批 13 条已导入（2026-08-23）

**原理**：样例库以 few-shot 方式注入阶段一 prompt，模型直接模仿标准写法，是把口径红线「翻译成模型行为」的最短路径。

**两条录入通道**：

1. **日常沉淀（自动）**：问数结果右下角「点赞」——`verdict=UP 且真实执行过且 SQL 非空`的问答对会**自动幂等沉淀**进样例库（同问题同 SQL 跳过）。分析师日常使用即建设。
2. **首批补录（手工）**：管理员在「SQL 样例库」管理页录入，或调 `POST /api/sql-examples/bulk`。附录 A 的 8 条标准样例 + 5 条扩展样例已于 2026-08-23 通过 bulk 接口导入（id 21-33，source=IMPORT）；其中 7 条已经 `/api/query/execute-sql` 真实执行核对通过，其余 6 条因触发每小时 20 次问数限流延后核对（列名均已对照生产 schema 核验）。

**验收**：样例库 ≥20 条，且每条人工执行核对过结果。

### L2 指标库：从 0 建 8 个核心指标 —— ✅ 已建成 11 条（2026-08-23）

**原理**：指标定义以「权威口径」强度注入 prompt，优先级高于知识库自然语言描述——历史事故证明指标 filter 写错会直接压过知识库的正确规则，所以**指标定义必须自带 R1/R2 锁定**。

**操作**：管理员进入「指标库」页新建，按附录 B 模板填写（名称 / 业务口径描述 / 聚合表达式 / filter / 关联表）。执行记录：盘点发现存量已有 8 条（39204 亿事故后的修复版，均已带快照期锁定），本次净增 3 条（项目数 / 成本余额 / 当年资产处置收益）、合并去重 1 条（本年投资收益补可切分维度），现共 11 条；3 条关键指标（累计投放金额 / 本年投放金额 / 项目数）已试算与 SQL 直查逐一比对一致。

现有 13 篇都是「正面规则」。补一类**正反对照**条目效果最好（✅ 首篇《宽表快照期常见错误与正确写法（易错反例）》已于 2026-08-23 入库，docId `kb_1787471930478_330958`，4 个检索块），例如：

## 附录 A：首批 8 条标准 SQL 样例（真实列名，可直接执行）

> 归属数据源：`ds_1786620486498`。✅ 已于 2026-08-23 通过 `POST /api/sql-examples/bulk` 全量导入（样例 id 21-33，source=IMPORT；导入版在 MAX 子查询内统一补了 `BB = '1'`，与本附录下方 SQL 一致）。

**A1 最新一期累计投放总额（R1+R2）**
```sql
SELECT SUM(LJTFJE) AS 累计投放金额
FROM fct_jc_main_biz_stat
WHERE BB = '1'
  AND BBRQ = (SELECT MAX(BBRQ) FROM fct_jc_main_biz_stat WHERE BB = '1');
```

**A2 各机构本年投放金额排名（R1+R2）**
```sql
SELECT JGMC AS 机构名称, SUM(BNTFJE) AS 本年投放金额
FROM fct_jc_main_biz_stat
WHERE BB = '1'
  AND BBRQ = (SELECT MAX(BBRQ) FROM fct_jc_main_biz_stat WHERE BB = '1')
GROUP BY JGMC
ORDER BY 本年投放金额 DESC;
```

**A3 逐月投放趋势（R4：逐期取当月列，非累计列跨期求和）**
```sql
SELECT BBRQ AS 报表期, SUM(BYTFJE) AS 当月投放金额
FROM fct_jc_main_biz_stat
WHERE BB = '1'
GROUP BY BBRQ
ORDER BY BBRQ;
```

**A4 最新一期项目总数（R3 去重计数）**
```sql
SELECT COUNT(DISTINCT XMBH) AS 项目数
FROM fct_jc_main_biz_stat
WHERE BB = '1'
  AND BBRQ = (SELECT MAX(BBRQ) FROM fct_jc_main_biz_stat WHERE BB = '1');
```

**A5 最新一期逾期金额（R1+R2）**
```sql
SELECT SUM(YQJE) AS 逾期金额
FROM fct_jc_main_biz_stat
WHERE BB = '1'
  AND BBRQ = (SELECT MAX(BBRQ) FROM fct_jc_main_biz_stat WHERE BB = '1');
```

**A6 当年投资收益（财务宽表，R1 锁 SJRQ + R2）**
```sql
SELECT SUM(DNTZSY) AS 当年投资收益
FROM fct_jc_financial_stat
WHERE BB = '1'
  AND SJRQ = (SELECT MAX(SJRQ) FROM fct_jc_financial_stat WHERE BB = '1');
```

**A7 业务二级类别投放分布（R1+R2+维度分组）**
```sql
SELECT YWEJLB AS 业务二级类别, SUM(BNTFJE) AS 本年投放金额
FROM fct_jc_main_biz_stat
WHERE BB = '1'
  AND BBRQ = (SELECT MAX(BBRQ) FROM fct_jc_main_biz_stat WHERE BB = '1')
GROUP BY YWEJLB
ORDER BY 本年投放金额 DESC;
```

**A8 两期对比：最新期 vs 上期的本年投放（R1 两期分别锁定）**
```sql
SELECT
  SUM(CASE WHEN BBRQ = (SELECT MAX(BBRQ) FROM fct_jc_main_biz_stat WHERE BB = '1')
           THEN BNTFJE ELSE 0 END) AS 最新期本年投放,
  SUM(CASE WHEN BBRQ = (SELECT MAX(BBRQ) FROM fct_jc_main_biz_stat WHERE BB = '1'
                         AND BBRQ < (SELECT MAX(BBRQ) FROM fct_jc_main_biz_stat WHERE BB = '1'))
           THEN BNTFJE ELSE 0 END) AS 上期本年投放
FROM fct_jc_main_biz_stat
WHERE BB = '1';
```

## 附录 B：指标定义模板（filter 必须自带锁定，铁律）

以「累计投放金额」为例，其余 7 个同构替换聚合列：

| 字段 | 内容 |
|------|------|
| 名称 | 累计投放金额 |
| 业务口径 | 历史累计授信金额，取最新月末快照、核算版口径 |
| 聚合表达式 | `SUM(LJTFJE)` |
| filter（关键） | `BB = '1' AND BBRQ = (SELECT MAX(BBRQ) FROM fct_jc_main_biz_stat)` |
| 关联表 | `fct_jc_main_biz_stat` |

其余指标聚合列对照：本年投放金额 `SUM(BNTFJE)`、业务笔数 `COUNT(DISTINCT YWBH)`（按业务编号去重，优于 `COUNT(*)`，与线上存量指标一致）、项目数 `COUNT(DISTINCT XMBH)`、逾期金额 `SUM(YQJE)`（配 `SFYQ='是'`，与线上一致）、成本余额 `SUM(CBEY)`、当年投资收益 `SUM(DNTZSY)`（财务表锁 SJRQ）、当年资产处置收益 `SUM(DNZCCZSY)`（财务表锁 SJRQ）。

## 附录 C：知识库易错反例条目范文（一段一块，400 字内）

> 标题：宽表快照期常见错误与正确写法
>
> 【反例1】`SUM(LJTFJE)` 不带 BBRQ 条件 —— 会把全部月末快照累加，结果虚增 N 倍（真实事故：39204 亿 vs 正确 2318.28 亿）。
> 【正例1】`WHERE BB='1' AND BBRQ=(SELECT MAX(BBRQ) FROM fct_jc_main_biz_stat)`。
> 【反例2】问「项目数」用 `COUNT(*)` —— 宽表一行业务≠一个项目，同项目多行会重复计数。
> 【正例2】`COUNT(DISTINCT XMBH)`；客户数同理 `COUNT(DISTINCT 客户列)`（真实事故：259 虚增为 278）。
> 【反例3】问趋势对 `LJTFJE` 跨期 SUM —— 累计列跨期求和无意义。
> 【正例3】趋势用当月列：`SELECT BBRQ, SUM(BYTFJE) ... GROUP BY BBRQ`。
> 【反例4】忘记 `BB='1'` —— 分成版同业务多行导致金额翻倍。
> 【正例4】金额与笔数统计默认 `AND BB='1'`，仅在明确问分成口径时用 BB='2' 并说明。
