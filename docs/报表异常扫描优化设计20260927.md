# 可视化决策报表「自动异常数据高亮扫描诊断」优化设计（数据资源库领域感知版）

> 日期：2026-09-27　状态：**待批准**　目标版本：v0.9.73

## 一、背景与现状缺陷

「自动异常数据高亮扫描诊断」当前由纯前端规则引擎 [anomalyDetector.ts](file:///Users/dgjin/dgjinapp/智能问数据分析系统/src/utils/anomalyDetector.ts) 实现，结合「数据资源库」（`ds_1786620486498`）的月末快照业务特性，存在四类系统性缺陷：

| # | 缺陷 | 根因 | 影响 |
|---|------|------|------|
| D1 | **KPI 异常大面积漏检** | KPI 检测完全依赖 LLM 阶段二给出的 `change` 百分比；月末快照口径下 LLM 常因缺历史对比数据而留空 `change` | 投放/逾期等核心 KPI 的环比异常静默漏过 |
| D2 | **分类维度误报** | Z-Score 离群检测对「机构排名」「业务分类占比」等分类维度天然不适用（头部机构天然偏离均值） | 正常排名被标为异常，误导决策 |
| D3 | **reasoning 文案与领域脱节** | 通用模板（"营销投流冲量""供应链断货"）不适用于不良资产经营场景 | 异常解读无业务指导性 |
| D4 | **口径错误与数值异常混淆** | 报表 SQL 若违反四红线（漏 BB='1'、未锁 MAX 快照、COUNT 未去重、财务指标走错表），产生的是「口径错误数据」而非「业务异常」，当前引擎无区分能力 | 口径错误被当作业务异常高亮，或反之 |

**可利用的领域资产**（数据资源库已沉淀）：
- 四红线口径规则（R1 最新快照锁定 / R2 BB='1' 核算版 / R3 COUNT DISTINCT / R4 财务指标走财务表）
- 明确业务阈值：长龄化率 >30% 关注 / >40% 严重；逾期金额分级（<100万一般 / 100-500万较大 / ≥500万重大）；月末快照独立性（不跨月累加）
- live 报表已携带 `executedSqls`（每图原聚合 SQL）+ `dataSourceId`，服务端按原 SQL 重放取数链路已经下钻功能验证可行

## 二、优化目标

1. **检出率**：KPI 环比/同比异常不再依赖 LLM 给 `change`，由服务端按原 SQL 重放历史快照真实计算；
2. **准确性**：分类维度改用「排名突变 + 占比偏移」检测，消除 Z-Score 误报；
3. **领域感知**：叠加四红线口径校验与数据资源库业务阈值，异常结论带业务归因；
4. **一致性**：报表页「重新扫描异常」与「异常巡检」复用同一服务端引擎，结果一致。

## 四、详细设计

### 4.1 服务端扫描引擎（`server/report/anomalyScan.ts`）

**输入**：`reportId`（从 `saved_reports` 加载完整 SavedReport JSON + `executedSqls` + `dataSourceId`）。

**Step 1 口径校验（四红线 AST 静态检查）**

对每条 `executedSqls[i]` 用 `node-sql-parser` 解析，检查：

| 红线 | 检查规则 | 违规标记 |
|------|----------|----------|
| R1 | WHERE 含 `BBRQ = (SELECT MAX(BBRQ)...)` 或 `SJRQ = (SELECT MAX(SJRQ)...)` | `missing_snapshot_lock` |
| R2 | WHERE 含 `BB = '1'` | `missing_bb_filter` |
| R3 | 含 `COUNT(XMBH)` 或 `COUNT(*)` 且涉及项目数语义 | `count_not_distinct` |
| R4 | SELECT 含投资收益语义字段但 FROM 为业务表 | `wrong_table_for_finance` |

- 违规图表/指标 → 生成 `AnomalyItem`（`type: 'threshold'`、`location: 'chart'`、`severity: 'medium'`、`reasoning` 明确说明口径问题与正确做法），**不再参与 Step 2-4 数值异常判定**；
- 前端单独分区展示「口径存疑」，引导用户重新生成报表或联系管理员修正口径。

**Step 2 时序重算（真实环比/同比）**

对口径合规的每条 SQL：
1. **改写**：AST 移除 `BBRQ = (SELECT MAX(...))` 快照锁定，改为 `BBRQ >= DATE_SUB((SELECT MAX(BBRQ)...), INTERVAL 12 MONTH)`，取近 12 个月快照序列；
2. **执行**：走 `executeSafeSql`（复用现有安全层：白名单/行级权限/超时/行数上限）；
3. **计算**：按月聚合 → 环比（MoM）、同比（YoY，若有 12 个月前数据）、3 个月移动平均；
4. **判定**：|MoM| ≥ 20% 或 |YoY| ≥ 30% 或连续 3 期同向变动 → 标记趋势异常。

**Step 3 维度适配检测**

| xAxisKey 类型 | 检测方法 | 说明 |
|---------------|----------|------|
| 时间维度（BBRQ/SJRQ/月份） | Z-Score（保留）+ 环比突变 | 时序数据适用统计离群 |
| 分类维度（JGMC/YWFL/KM_YJFL 等） | **排名突变**（本期排名 vs 上期排名变化 ≥3 位）+ **占比偏移**（占比变化 ≥10pp） | 消除头部机构天然离群的误报 |

**Step 4 领域阈值叠加（数据资源库）**

内置阈值表（可被数据源级配置覆盖）：

| 指标语义 | 阈值规则 | 严重度 |
|----------|----------|--------|
| 长龄化率（SFCL 占比） | >30% | medium |
| 长龄化率 | >40% | high |
| 逾期金额（YQJE 单机构） | ≥500万 | high |
| 逾期金额 | 100-500万 | medium |
| 逾期率（YQJE/LJTFJE） | >10% | high |
| 成本回收率 | <50% | medium |
| 本年投放环比 | 降幅 >30% | high |

命中阈值 → 直接定级，`reasoning` 携带业务归因（如「长龄化率 42% 已超 40% 严重线，需启动专项处置」）。

**Step 5 LLM 归因解读（可选）**

- 仅对 `severity=high` 的异常触发；
- Prompt 携带：异常上下文（指标/维度/实际值/期望值/偏离）+ 数据资源库知识库相关条目（长龄/逾期/口径）；
- 输出领域化 `reasoning` 与 `actionItem`；
- LLM 不可用 → 降级为规则模板文案（保证功能可用）。

### 4.2 API 端点

```
POST /api/report/scan-anomalies
Body: { reportId: string }
Auth: 登录用户（复用 authMiddleware）
Response: { success: true, anomalies: AnomalyItem[], scanTime: string, engine: 'server-v2' }
```

- 服务端从 `saved_reports` 加载报表（校验 `dataSourceId` 权限）；
- 扫描结果**不落库**（每次重扫实时计算，避免旧结果与新数据不一致）；
- 超时 30s（时序重算最多 12 条 SQL，并行执行）。

### 4.3 阈值配置（内置默认 + 可覆盖）

- **内置默认**：4.1 Step 4 表格硬编码在 `anomalyScan.ts`；
- **数据源级覆盖**：`data_sources` 表新增 `anomaly_thresholds_json` 列（TEXT，JSON），管理员在「数据源与 Schema」面板按需覆盖；
- 覆盖优先级：数据源配置 > 内置默认；
- 未配置的数据源（非数据资源库）→ 仅启用通用统计检测（Step 2/3），跳过领域阈值（Step 4）。

## 六、验收标准

1. **口径校验**：构造违反四红线的报表 SQL（如漏 BB='1'）→ 扫描结果标记「口径存疑」且不参与数值异常判定；
2. **时序重算**：对数据资源库生成报表 → KPI 环比异常由服务端真实计算（不依赖 LLM `change`）；
3. **分类维度**：机构排名图表 → 不再因头部机构天然高值误报，仅排名突变/占比偏移才标记；
4. **领域阈值**：长龄化率 >40% 的报表 → 直接判定 high 并携带「启动专项处置」归因；
5. **巡检一致**：同一报表，报表页重扫与巡检执行结果一致；
6. **降级**：LLM 不可用时 high 异常仍有规则模板 reasoning；
7. 门禁全绿；文档同步完成；提交推送双远程。

## 七、风险与缓解

| 风险 | 缓解 |
|------|------|
| 时序重算增加 DB 负载（每报表最多 12 条额外查询） | 并行执行 + 连接池分级（chain 场景）+ 30s 超时 + 结果不落库（实时计算） |
| 四红线 AST 静态检查误判（复杂 SQL 解析不全） | 误判仅标记「口径存疑」不阻断；提供「忽略口径校验」开关；测试覆盖常见违规模式 |
| 非数据资源库数据源无领域阈值 | 通用统计检测仍生效；领域阈值仅对配置了 `anomaly_thresholds_json` 或匹配内置语义的数据源启用 |
| LLM 归因解读增加延迟 | 仅 high 异常触发 + 异步执行（先返回规则结果，LLM 完成后流式补充） |
| 历史报表无 `executedSqls`（演示数据/旧版） | 前端检测缺失时隐藏服务端扫描入口，回退本地扫描并提示 |
