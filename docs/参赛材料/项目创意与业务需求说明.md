## 一、项目背景与痛点

### 1.1 业务背景

在不良资产经营管理领域，投后管理与经营分析高度依赖数据驱动：业务人员需要围绕**核心业务数据**（业务宽表、财务宽表等，单表可达数百列、千万级行）进行高频查询与分析。典型场景包括：

- **经营巡检**：定期查看各机构业务规模排名、长龄业务占比、逾期金额趋势
- **风险排查**：按业务分类/机构/行业维度筛选风险项目，追踪关键指标变动
- **决策支撑**：向管理层汇报经营概况、投资收益分析、多期对比
- **合规审计**：核对数据口径、版本一致性、快照期正确性

### 1.2 核心痛点

| 痛点 | 现状 | 影响 |
|------|------|------|
| **SQL 门槛高** | 业务人员不懂 SQL，每次取数需提 IT 工单 | 平均等待 1-3 天，决策时效性丧失 |
| **口径不一致** | 同一指标不同人写出不同 SQL（如「长龄业务」过滤条件各异） | 数据结论互相矛盾，管理层无法采信 |
| **宽表复杂度高** | 数百列宽表、多版本快照结构，人工容易遗漏关键过滤条件 | 真实事故：跨期累加致金额虚增近 17 倍 |
| **分析链路断裂** | 取数→做图→写解读→出报告，环节多、工具散 | 一次完整分析需 2-4 小时，重复劳动严重 |
| **数据安全顾虑** | 云端 AI 服务存在数据出域风险 | 金融行业合规红线，不能使用外部 AI |

### 1.3 为什么是 AI 智能体 + NL2SQL

传统 BI 工具（拖拽式报表）能解决固定报表需求，但无法应对**临时性、探索性、口语化**的分析提问。让业务人员用自然语言直接对话数据，是解决上述痛点的最优路径。但业界通用方案普遍存在三大缺陷：

1. **幻觉不可控**：AI 编造列名/表名/数值，金融领域零容忍
2. **口径无治理**：同一问题每次生成不同 SQL，结果不可复现
3. **安全不达标**：缺乏行级权限、审计追溯、敏感字段保护

本项目针对这三大缺陷，构建了一套**企业级可信数据分析智能体（Data Agent）**——不是一个"生成 SQL 的工具"，而是一个具备自主决策能力、受口径治理约束、可自我学习的金融数据智能体。

## 二、赛道适配说明

### 2.1 为什么属于智能创新赛道

本项目横跨「数据决策、知识问答、自动化报告」三类场景，核心创新是 **AI Agent 驱动的可信数据决策机制**，无法被现有五大赛道任一单一定义完整覆盖：

- **区别于智能办公**：办公赛道聚焦流程审批、文书处理等日常办公提效；本项目解决的是经营数据**决策可信性**问题（口径一致、零幻觉、可审计），属于经营决策基础设施
- **区别于智能研究**：研究赛道聚焦行业研究、文献分析等内容生成；本项目不生成研究观点，而是让 AI 安全、准确地直连企业核心经营数据
- **区别于智能尽调/风控/营销**：项目虽服务风险排查等场景，但本质是**跨业务条线的数据智能底座**，任一单一条线场景均无法涵盖

### 2.2 与赛道四大方向的深度融合

| 赛道方向 | 本项目落点 | 融合方式 |
|----------|-----------|----------|
| **方向 1：AI+资管新业态** | 不良资产投后经营分析 | AI 辅助资产包经营巡检、长龄资产监测、投放回收分析，为投后管理决策提供秒级数据支撑 |
| **方向 3：AI Agent 自动化** | 数据分析智能体 | 智能体自主完成「理解→决策→取数→制图→解读→报告」全链路；定期经营报告自动生成 |
| **方向 4：RAG 企业应用** | 企业口径知识问答 | 知识库/指标库/样例库三库 RAG 检索增强，员工随时问询业务口径与经营数据 |

三大方向有机融合于同一智能体架构：**RAG 提供知识、Agent 提供决策与执行、资管场景提供落地土壤**——并非浅层拼接。

### 2.3 技术与数据合规说明

- 本项目**不训练大模型基础能力**，AI 推理基于开源大模型的标准部署，推理接口兼容 OpenAI 标准协议，**可无缝切换至公司统一 AI 平台**
- 现场演示环节全部使用**脱敏样例数据集**，不含任何真实客户信息

## 三、项目创意

### 3.1 一句话定位

**一个懂业务口径的金融数据分析智能体：业务人员用中文直接对话数据库，智能体自主完成理解决策、安全取数、图表可视化与报告解读，全程安全可控、口径可治理、结果可溯源。**

### 3.2 创意总览：智能体工作闭环

```
                     ┌─── 数据分析智能体（Data Agent）工作闭环 ───┐
                     │                                          │
     ① 感知 ────────────► ② 决策 ────────────► ③ 执行            │
   Schema 圈表         四契约自主决策          安全执行层           │
   知识 RAG 检索        生成/澄清/自省/拒答     SELECT-only        │
   指标口径命中         复杂度分档路由          行级权限强制注入      │
     ▲                                                │          │
     │                                                ▼          │
     ⑤ 学习 ◄──────────── ④ 反思 ◄──────────── ⑥ 表达            │
   点赞沉淀样例           自纠错重试              自动图表            │
   点踩注入反例           多候选择优表决           真实数据解读        │
   个人问答记忆           评测门禁回归            一键报告生成        │
                     └──────────────────────────────────────────┘
```

### 3.3 五大创意亮点

#### 创意 1：智能体自主决策（四契约输出）—— 「宁可拒答，不可胡答」

业界数据问答系统的最大信任杀手是 AI 编造数据。本项目智能体在**决策环节**首创四契约输出机制——它知道何时该答、何时该问、何时该查、何时该拒绝：

| 契约 | 触发条件 | 智能体行为 |
|------|----------|-----------|
| **正常生成** | 问题明确、字段可映射 | 输出 SQL + 图表配置 + 推理过程 |
| **歧义澄清** | 关键概念有多种理解 | 主动返回 2-4 个候选理解供用户选择 |
| **数据自省** | 过滤值格式不确定 | 先自主执行轻量探查 SQL 确认真实取值，再生成最终查询 |
| **诚实拒答** | 问题超出数据覆盖范围 | 明确告知无法处理，附数据源覆盖范围说明 |

**价值**：具备「知道何时不该回答」的自主决策能力，从机制上杜绝「AI 编数字」——这是金融领域 AI 应用的第一信任基石，也是本项目区别于普通问答工具的智能体本质。

#### 创意 2：口径治理四层防线 —— 从「千人千 SQL」到「全系统一致」

| 层级 | 机制 | 作用 |
|------|------|------|
| L1 知识库 | 业务术语/口径文档 RAG 检索注入 | 智能体理解业务语义 |
| L2 指标库 | 管理员登记指标权威口径（表达式+过滤条件） | 命中即模板化注入，口径锁定 |
| L3 样例库 | 验证正确的「问题-SQL」对作为参考样例 | 同类问题口径自动对齐 |
| L4 业务红线 | 快照期锁定/版本防重/去重计数/表路由 | 硬编码业务规则防口径漂移 |

**真实效果**：某次重大口径偏差事故（金额虚增近 17 倍）发生后，通过 L2 指标库补锁 + L3 样例修正 + L4 红线约束，同类错误归零。

#### 创意 3：数据飞轮 —— 智能体的经验记忆沉淀

```
用户提问 → 智能体生成 SQL → 用户反馈
                            ↓
              ┌───── 点赞 → 自动沉淀为团队样例
              ├───── 点踩 → 以「反面教材」注入后续决策
              └───── 历史成功问答 → 个人经验记忆沉淀
```

每次用户交互都在为智能体积累领域经验，准确率随使用时间单调递增——**系统越用越聪明**。

#### 创意 4：全本地 AI 引擎 —— 金融数据零出域

- 主推理模型：本地部署大语言模型（消费级硬件即可运行）
- 快速模型路由：简单查询自动分流至轻量模型（提速约 50%）
- 向量检索：本地 Embedding 模型，无需外部 API
- **零云端依赖**：所有 AI 推理在企业内网完成，数据不出域
- **平台兼容**：推理接口兼容 OpenAI 标准协议，可平滑切换至公司统一 AI 平台

#### 创意 5：双阶段真实数据回喂 —— 解读永远有真实数据背书

决策阶段只生成 SQL 不生成数据；SQL 执行后，解读阶段基于真实查询结果生成分析。LLM 失败时自动降级为规则化解读（基于真实列统计），**保证每一句解读都有真实数据支撑**。

## 四、业务需求分析

### 4.1 目标用户

| 角色 | 核心诉求 | 使用频率 |
|------|----------|----------|
| 业务分析师 | 快速取数、灵活分析、生成报告 | 每日 |
| 业务部门负责人 | 经营概况、风险预警、决策依据 | 每周 |
| 高管/管理层 | 决策简报、KPI 看板 | 每月/每季 |
| 数据管理员 | 口径治理、权限管理、质量监控 | 持续 |

### 4.2 核心业务场景

**场景 1：日常经营巡检（高频）**

> 分析师提问：「各机构本年业务规模排名前十的是哪些？」
> 智能体秒级返回：SQL + 机构排名表格 + 柱状图 + 数据解读

**场景 2：风险排查（中频）**

> 业务负责人提问：「逾期金额合计是多少？各业务分类的逾期情况如何？」
> 智能体返回：逾期总额 + 分类明细 + 占比饼图 + 归因分析

**场景 3：管理层决策简报（低频但高价值）**

> 高管提问：「整体业务经营情况如何？」
> 智能体识别问题笼统 → 主动澄清分析维度 → 用户确认 → 生成完整分析报告（摘要 + KPI + 图表 + 洞察），一键导出 PDF/PPT

**场景 4：口径核对与审计（合规场景）**

> 审计人员提问：「累计业务规模是多少？」
> 智能体返回带快照期锁定 + 版本过滤的 SQL，结果与源系统精确一致

## 八、参赛价值主张

本项目不是概念验证或 Demo，而是一个**已在真实业务数据上验证过的准生产级数据分析智能体**。它回答了金融 AI 应用的核心命题：

> **如何让 AI 在金融数据领域做到「可信、可控、可治理」？**

- **可信**：四契约自主决策 + 双阶段真实数据回喂，杜绝数据幻觉
- **可控**：全本地引擎 + 行级权限 + 审计追溯，数据零出域
- **可治理**：指标库 + 知识库 + 样例库 + 评测门禁，口径全系统一致

这三点正是金融行业 AI 落地的最大门槛，也是本项目的核心参赛价值：**把 AI 从"能聊数据"提升到"敢用于决策"**。
