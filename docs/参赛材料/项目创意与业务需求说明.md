## 一、项目背景与痛点

### 1.1 业务背景

在金融企业日常经营管理中，业务人员需要围绕**核心业务数据**（业务宽表、财务宽表等，单表可达数百列、千万级行）进行大量数据查询与分析。典型场景包括：

- **经营巡检**：定期查看各机构业务规模排名、长龄业务占比、逾期金额趋势
- **风险排查**：按业务分类/机构/行业维度筛选风险项目，追踪关键指标变动
- **决策支撑**：向管理层汇报经营概况、投资收益分析、多期对比
- **合规审计**：核对数据口径、版本一致性、快照期正确性

### 1.2 核心痛点

| 痛点 | 现状 | 影响 |
|------|------|------|
| **SQL 门槛高** | 业务人员不懂 SQL，每次取数需提 IT 工单 | 平均等待 1-3 天，决策时效性丧失 |
| **口径不一致** | 同一指标不同人写出不同 SQL（如「长龄业务」过滤条件各异） | 数据结论互相矛盾，管理层无法采信 |
| **宽表复杂度高** | 数百列宽表、多版本快照结构，人工容易遗漏关键过滤条件 | 真实事故：跨期累加致金额虚增近 17 倍 |
| **分析链路断裂** | 取数→做图→写解读→出报告，环节多、工具散 | 一次完整分析需 2-4 小时，重复劳动严重 |
| **数据安全顾虑** | 云端 AI 服务存在数据出域风险 | 金融行业合规红线，不能使用外部 AI |

### 1.3 为什么是 AI + NL2SQL

传统 BI 工具（拖拽式报表）能解决固定报表需求，但无法应对**临时性、探索性、口语化**的分析提问。NL2SQL 技术让业务人员用自然语言直接对话数据，是解决上述痛点的最优路径。但业界 NL2SQL 方案普遍存在三大缺陷：

1. **幻觉不可控**：AI 编造列名/表名/数值，金融领域零容忍
2. **口径无治理**：同一问题每次生成不同 SQL，结果不可复现
3. **安全不达标**：缺乏行级权限、审计追溯、敏感字段保护

本项目针对这三大缺陷，构建了一套**企业级可信 NL2SQL 系统**。

## 二、项目创意

### 2.1 一句话定位

**让金融业务人员用中文直接对话数据库，AI 生成可信 SQL 并自动完成可视化与决策简报，全程安全可控、口径可治理、结果可溯源。**

### 2.2 五大创意亮点

#### 创意 1：四契约输出 —— 「宁可拒答，不可胡答」

业界 NL2SQL 系统的最大信任杀手是 AI 编造数据。本项目首创四契约输出机制：

| 契约 | 触发条件 | 行为 |
|------|----------|------|
| **正常生成** | 问题明确、字段可映射 | 输出 SQL + 图表配置 + 推理过程 |
| **歧义澄清** | 关键概念有多种理解 | 返回 2-4 个候选理解供用户选择 |
| **数据自省** | 过滤值格式不确定 | 先执行轻量探查 SQL 确认真实取值 |
| **诚实拒答** | 问题超出数据覆盖范围 | 明确告知无法处理，附数据源覆盖范围说明 |

**价值**：从机制上杜绝「AI 编数字」，这是金融领域 AI 应用的第一信任基石。

#### 创意 2：口径治理四层防线 —— 从「千人千 SQL」到「全系统一致」

| 层级 | 机制 | 作用 |
|------|------|------|
| L1 知识库 | 业务术语/口径文档 RAG 检索注入 | LLM 理解业务语义 |
| L2 指标库 | 管理员登记指标权威口径（表达式+过滤条件） | 命中即模板化注入，口径锁定 |
| L3 样例库 | 验证正确的「问题-SQL」对作为 few-shot 参考 | 同类问题口径自动对齐 |
| L4 业务红线 | 快照期锁定/版本防重/去重计数/表路由 | 硬编码业务规则防口径漂移 |

**真实效果**：某次重大口径偏差事故（金额虚增近 17 倍）发生后，通过 L2 指标库补锁 + L3 样例修正 + L4 红线约束，同类错误归零。

#### 创意 3：自学习闭环 —— 越用越准的数据飞轮

```
用户提问 → AI 生成 SQL → 用户反馈
                            ↓
              ┌───── 点赞 → 自动沉淀为团队样例（auto_train）
              ├───── 点踩 → 以「反面教材」注入后续 prompt
              └───── 历史成功问答 → 个人 few-shot 沉淀
```

每次用户交互都在为系统积累领域知识，准确率随使用时间单调递增。

#### 创意 4：全本地 AI 引擎 —— 金融数据零出域

- 主推理模型：Ollama 本地部署大语言模型（消费级硬件即可运行）
- 快速模型路由：简单查询自动分流至轻量模型（提速约 50%）
- Embedding 圈表：本地向量模型，无需外部 API
- **零云端依赖**：所有 AI 推理在企业内网完成，数据不出域

#### 创意 5：双阶段真实数据回喂 —— 解读永远有真实数据背书

阶段一只生成 SQL 不生成数据；SQL 执行后，阶段二基于真实查询结果生成解读。LLM 失败时自动降级为规则化解读（基于真实列统计），**保证每一句解读都有真实数据支撑**。

## 三、业务需求分析

### 3.1 目标用户

| 角色 | 核心诉求 | 使用频率 |
|------|----------|----------|
| 业务分析师 | 快速取数、灵活分析、生成报告 | 每日 |
| 业务部门负责人 | 经营概况、风险预警、决策依据 | 每周 |
| 高管/管理层 | 决策简报、KPI 看板 | 每月/每季 |
| 数据管理员 | 口径治理、权限管理、质量监控 | 持续 |

### 3.2 核心业务场景

**场景 1：日常经营巡检（高频）**

> 分析师提问：「各机构本年业务规模排名前十的是哪些？」
> 系统秒级返回：SQL + 机构排名表格 + 柱状图 + 数据解读

**场景 2：风险排查（中频）**

> 业务负责人提问：「逾期金额合计是多少？各业务分类的逾期情况如何？」
> 系统返回：逾期总额 + 分类明细 + 占比饼图 + 归因分析

**场景 3：管理层决策简报（低频但高价值）**

> 高管提问：「整体业务经营情况如何？」
> 系统触发澄清 → 用户确认分析维度 → 生成完整分析报告（摘要 + KPI + 图表 + 洞察），一键导出 PDF/PPT

**场景 4：口径核对与审计（合规场景）**

> 审计人员提问：「累计业务规模是多少？」
> 系统返回带快照期锁定 + 版本过滤的 SQL，结果与源系统精确一致

- ✅ 系统从 v0.1 迭代至 v0.8.5，累计 27 个版本

- ✅ 重大口径偏差事故根治方案已落地并验证

### 4.2 技术创新点

1. **四契约输出机制**（拒答/澄清/自省/生成）—— 业界首创的诚实性设计
2. **行级权限 AST 强制注入** —— 与 Snowflake 行访问策略等价的 fail-closed 方案
3. **口径治理四层防线** —— 知识库→指标库→样例库→红线约束的纵深防御
4. **自学习数据飞轮** —— 点赞沉淀 + 点踩反例 + 个人 few-shot 三通道闭环
5. **复杂度分档路由** —— 简单问题走快速模型、复杂问题强制主模型，兼顾速度与准确率

## 五、参赛价值主张

本项目不是概念验证或 Demo，而是一个**已在真实业务数据上验证过的准生产级系统**。它回答了金融 AI 应用的核心命题：

> **如何让 AI 在金融数据领域做到「可信、可控、可治理」？**

- **可信**：四契约输出 + 双阶段真实数据回喂，杜绝数据幻觉
- **可控**：全本地引擎 + 行级权限 + 审计追溯，数据零出域
- **可治理**：指标库 + 知识库 + 样例库 + 评测门禁，口径全系统一致

这三点正是金融行业 AI 落地的最大门槛，也是本项目的核心参赛价值。
